# 《礼与道》接入原版儒家

2026-10-12 当前架构；源码静态就绪，新的原版信仰实机验收尚未完成。

新增学派是原版儒家中的礼仪和思想路线。36 个 `lyd_rite_*` 的 parent faith 为 `confucian_faith`；经学 `jingxue`、道学 `daoxue` 和原版开局主礼仪保留。孔门经礼只是本模组的入门礼仪。模组不把原版 faith 定义、主礼仪、宗主或历史信条状态替换成另一套共同体。

玩家须已信奉原版儒家才能“入儒门，习经礼”。执行前核对当前与目标礼仪属于同一 faith；成功后仅本人采用孔门经礼，再开放问学和修习。择学同样只列同 faith 的目标礼仪，成功后设置一年冷却。不迁移 NPC、伯爵领或其他礼仪，也不移动、复制或改写原版经学与道学。

入门成功时，或由玩家选择“研读诸家信条”时，本人学习 36 张新增信条。原版实际支持的 `set_tenet_status` 仅用于尚无 core/permitted/known/prohibited 状态的新 LYD 信条，登记为允许；`add_known_tenet` 仅增加本人的知识。既有状态（包括玩家以后明确禁用的新信条）不被重复登记覆盖，所有原版信条状态保持不动。没有整份 faith history 的覆盖或替换。

研读不是自动选取。玩家仍需在原版个人信念窗口中选择个人信条，沿用原生槽位、费用、DLC 和资格条件。信条定义包含原生角色、伯爵领、个人选择者修正；采用礼仪的三核心信条与个人额外选择是不同来源。实际列表可见性、选取、效果传播、叠加、换派清理和重载必须在新运行中验证，源码与 AST 通过不能替代这些结果。

## 宗主与共同体边界

I3b 的 `only_owned_rites` 检查继续保留。原版儒家包含经学和道学，它们不属于本模组的授权名单，因此不能通过本模组一次表决改写整个原版儒家的宗主制度，也不强改原版主礼仪。已有只含模组礼仪的独立共同体继续遵守原有代表、学者、玩家同意及完整名单章程；这不授予接管原版礼仪的权力。

## 0.1.0 试玩存档

release 0.1.0、旧 tag 和旧实机记录保持历史原样。`lyd_common_faith` 仅保留历史兼容定义及名称，不再用于正常入门或新角色的自动归属。不能假定新类型文件会自动迁移旧存档的 faith/rite 对象；实际兼容仍待新版本存载验证，不能把加载成功称为迁移完成。

没有自动迁移全体 NPC、整 faith 或整 rite 的步骤。旧存档中的现任宗主、派领袖、挑战者、赞助者及 C2/C3/I3b 待办须先按原流程处理；不能静默删除职位、争统、名单或历史回执来通过迁移。

旧试玩玩家回归的目标是**仅本人**回到原版 `confucian_faith` 当时实际的主礼仪，不能硬编码道学。先保存旧档和身份/职务/待办记录；完成上述职责处理后，由本人通过原版允许的改信入口主动选择原版儒家，并实际读回 faith 和 rite。如原版界面不提供该合法入口，则停在未迁移状态：当前版本尚无专用已验迁移决议，不能用调试命令代替。专用后继决议须复查角色及全部职务/待办，再执行一次本人 setter、核对实际目标，并保持其他人和旧回执。

旧档返回原版后，原保存的 LYD 礼仪可能仍属旧 faith；同 faith 守卫会拒绝把本人再次送回旧共同体。完整的新架构体验优先使用新存档；不能承诺旧档全部学派直接续用。独立共同体的现有礼仪也不会被新正常入门收回。

## 生成与验收

只改 `tools/content_data.py`、`tools/gen_runtime.py` 等权威输入，再运行 `gen_content.py` 和 `gen_runtime.py`。`lyd_faiths.txt` 是兼容 stub，`lyd_faith_history.txt` 是无活动历史的占位；保留原正式 allowlist，当前生成仍为 71 个 runtime 文件，不手改带 GENERATED 标记的输出。

本次新 `test_vanilla_faith_integration.py` 检查真实生成 AST、正常入口与研读 helper 的接线、36 个有限 ID、原状态保留、同 faith 拒绝和实际静态校验器正负例。它不运行 CK3，不授予个人选取、旧存档迁移或宗主业务成功信用。
