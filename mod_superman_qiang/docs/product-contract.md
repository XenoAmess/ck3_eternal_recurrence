# 《超人强》1.0.0 产品规则

用户于 2026-10-04 确定中文名《超人强》，工坊标题《超人强：越超人越强》，并授权开发、测试验收与发布。产品键 `superman-qiang`，源码目录 `mod_superman_qiang`，脚本命名空间 `sxad`。这是原创独立产品，不沿用其他产品或上游的 Workshop item ID。

## 一次行为如何结算

1. 接入 CK3 1.20.0.3 原版 `had_sex_with_effect` 的真实执行。保留原版妊娠、压力、记忆、秘密及其他效果，不把提示预览计作真实执行。
2. 双方必须是不同的、存活的、年满 18 岁的角色。玩家和 AI 均适用，不按性别、婚姻或同一天次数另设限制。
3. 读取双方本次行为前的性经验。未初始化变量的角色视为 0；相同经验不吸取。
4. 经验较多的一方从经验较少的一方吸取六项能力中的随机一项：外交、军事、管理、谋略、学识、勇武。每个角色分别保存六项有符号“净转移点数”账本；成功时同一项能力的接收者账本严格 +1、来源者账本严格 -1，其他五项账本不变。转移单位是原始属性修正点，不得分别随机两项或凭空赠点。
5. 无论是否成功转移，双方经验各增加 1。不存在可转移属性时仍累计经验；先比较后计数，双方轮流作为事件发起人不改变规则。
6. 同一天确实发生多次行为就分别结算，不设置未获要求的冷却或收益递减。

原版 `had_sex_with_unknown_effect` 没有可定位的另一角色。满足年龄及存活条件的已知角色增加 1 经验，不吸取属性。角色死亡、出生、婚姻、怀孕和定期心跳不代替性行为计数。

## 能力边界

六项账本各限定在 **-1,000,000 至 +1,000,000** 原始属性修正点。未设置的账本按 0 读取。每次转移后，用该角色账本重建对应的缩放 character modifier；正账本投影为正属性修正，负账本投影为负属性修正，0 清除该项修正。缩放在赋予 modifier 时计算一次，不能仅修改变量后沿用旧投影。

来源者当前有效技能必须大于 0；有效技能为 0 的项没有可扣点数，不进入本次候选。接收者有效技能为 0 时仍可以接收。只有本次来源者 -1 和接收者 +1 都不会越过各自单项账本边界时，该技能才是候选；越界项跳过，剩余候选之间等权抽取。所有候选均被排除时，不转移属性，双方经验仍各 +1。

原生六项基础属性数组保持原样。原版百分比修正、整数取整及最终技能边界继续作用于总技能，故吸取 1 个原始修正点后，面板变化可能为 0、1、2 或其他由原版计算决定的数值；不承诺双方有效技能严格 +1/-1，也不以显示总和作为原始转移守恒的唯一证据。

当前方案已经获得原版静态定义及调用先例的源级支持，**新账本方案的实机验收仍 pending**。R0006 的旧破坏性试扣探测为 RED，A0002 增加刷新后的静态结果只属于历史候选；两轮证据保留，不能作为账本方案的通过证据。来源及历史说明见 [技能边界参考](skill-boundaries-reference.md)。

## 计数与查看

- 权威数据为角色变量 `sxad_sex_experience`，随存档保存。查看不能新增经验、修改属性或触发吸取抽选；不对原生事件窗口自身使用的引擎随机状态作额外承诺。
- 通用查看入口覆盖尚未记录的角色，显示 0。特质说明读取特质持有人，不能绑定 `GetPlayer`。
- 不通过定期遍历全世界来给零经验角色添加特质。显示特质不承载唯一计数，不采用 100 点特质经验条作为上限。
- 计数上限依据引擎有符号 64 位、十万倍固定点的理论范围为 92,233,720,368,547。应在上限停止递增，不能溢出、绕回或变为负数。这个理论范围不是极值实机结论；发布时分别报告正常计数、百万级及边界夹具实际覆盖。
- 启用之前的经历不反推。0 代表本模组尚未记录次数，不代表处子身份。经验不遗传，不跨战役保存。

## 兼容与玩家入口

以 CK3 1.20.0.3 原版为来源，描述文件声明 `1.20.*`；后续补丁兼容仍需验证。无其他模组或 DLC 硬依赖。成年 AI 与玩家相同规则是用户“每个人记录”需求的一部分。

覆盖范围限于两项原版 scripted effect 的独立生成投影，不复制整份 `00_romance_effects.txt`，不使用 `replace_path` 覆盖目录。安装了同样改写这两项效果的模组时，须合并接入点；不宣称通用兼容全部恋爱模组。

可加入现有存档，从启用时开始记录；移除后的未知自定义变量/特质处理需要实测并如实说明。多人、Ironman、成就及非目标游戏版本不在首发已验证范围。
