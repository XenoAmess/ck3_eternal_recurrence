# 《超人强》1.1.0 产品规则

用户于 2026-10-04 确定中文名《超人强》，工坊标题《超人强：越超人越强》，并授权开发、测试验收与发布。产品键 `superman-qiang`，源码目录 `mod_superman_qiang`，脚本命名空间 `sxad`。这是原创独立产品，不沿用其他产品或上游的 Workshop item ID。

## 一次行为如何结算

1. 接入 CK3 1.20.0.3 原版 `had_sex_with_effect` 的真实执行。保留原版妊娠、压力、记忆、秘密及其他效果，不把提示预览计作真实执行。
2. 双方必须是不同的、存活的、年满 18 岁的角色。玩家和 AI 均适用，不按性别、婚姻或同一天次数另设限制。
3. 读取双方本次行为前的性经验。未初始化变量的角色视为 0；相同经验不吸取。
4. 经验较多的一方从经验较少的一方吸取七项属性中的随机一项：外交、军事、管理、谋略、学识、勇武、健康。所有本次合格项等权。六项能力的转移单位为 1 原始属性修正点；健康的转移单位为 0.00075 原始健康修正点。双方同一项的有符号净转移账本分别增加、减少同量，其他六项不变，不得分别随机两项或凭空赠点。
5. 无论是否成功转移，双方经验各增加 1。不存在可转移属性时仍累计经验；先比较后计数，双方轮流作为事件发起人不改变规则。
6. 同一天确实发生多次行为就分别结算，不设置未获要求的冷却或收益递减。

原版 `had_sex_with_unknown_effect` 没有可定位的另一角色。满足年龄及存活条件的已知角色增加 1 经验，不吸取属性。角色死亡、出生、婚姻、怀孕和定期心跳不代替性行为计数。

## 属性边界

六项账本各限定在 **-1,000,000 至 +1,000,000** 原始属性修正点。未设置的账本按 0 读取。每次转移后，用该角色账本重建对应的缩放 character modifier；正账本投影为正属性修正，负账本投影为负属性修正，0 清除该项修正。缩放在赋予 modifier 时计算一次，不能仅修改变量后沿用旧投影。

来源者当前有效技能必须大于 0；有效技能为 0 的项没有可扣点数，不进入本次候选。接收者有效技能为 0 时仍可以接收。只有本次来源者 -1 和接收者 +1 都不会越过各自单项账本边界时，该技能才是候选；越界项跳过，剩余候选之间等权抽取。所有候选均被排除时，不转移属性，双方经验仍各 +1。

健康使用独立的 `sxad_health_balance` 小数账本，未设置按 0 读取，范围同样为 ±1,000,000 原始健康修正点。来源者当前有效健康须至少为 3.00075，且双方账本本次 ±0.00075 均不越界，健康才加入等权候选。以正负 `health` modifier 和非负 scale 重建投影，不改写基础健康。每次只可能吸取一项，不能同时吸取健康和能力。

0.00075 是平衡基准，不是寿命上限的严格换算。当前原版从 25 岁起每年以初始 7.5% 概率扣除 0.125 健康，初始参数折算的月期望损失为 0.00078125，本模组选取稍小的 0.00075。年龄会改变概率，疾病、健康修正和随机死亡也影响寿命，因此无法保证实际寿命最多改变一个月。健康惩罚抵消等原版机制继续生效；承诺的是原始账本 ±0.00075 守恒，有效健康不承诺严格对称。参数来源与实机状态见 [健康设计](health-design-1.1.0.md)。

原生六项基础属性数组保持原样。原版百分比修正、整数取整、勇武惩罚抵消及最终技能边界继续作用于总技能，故吸取 1 个原始修正点后，面板变化可能为 0、1、2 或其他由原版计算决定的数值；不承诺双方有效技能严格 +1/-1，也不以显示总和作为原始转移守恒的唯一证据。R0007 的实际诺曼文化含 `tradition_chanson_de_geste`，提供 5 点勇武惩罚抵消；因此流失 1 点修正后勇武仍可保持原值，后续累积惩罚超过抵消额度才影响总值。

1.0.0 的六技能账本方案已在本机 CK3 1.20.0.3 完成真实机制与保存验证，包括正负百分比、零显示接收、正负百万边界、向反方向离开边界、scale 更新时机和重复重建。当时的正常查看与新进程存档重载亦已通过；范围和原始证据见 [首发验收汇总](acceptance-1.0.0-20261004.md)。R0006 的旧破坏性试扣探测为 RED，A0002 增加刷新后的静态结果只属于历史候选，R0007 的两项错误断言及其 UI 故障也保留，不能改写为后续候选通过。来源及历史说明见 [技能边界参考](skill-boundaries-reference.md)。

1.0.0 的六项能力与旧查看界面验收记录仅证明当时版本。1.1.0 的健康机制在 [R0019](live-R0019-health-1.1.0.md) 通过20条实机案例，[R0020](live-R0020-health-reload-1.1.0.md) 新进程保存重载通过，[R0021](live-R0021-normal-ui-1.1.0.md) 已验证通知读数、特质持有人记录及查看只读。R0021 审阅同时发现额外原生确认窗；移除后，[R0022](live-R0022-compact-ui-1.1.0.md) 已通过普通存档自己与NPC一次菜单点击直接出气泡及只读复验。正式发布仍待完成。新增范围及未覆盖项见 [1.1.0 增量验收汇总](acceptance-1.1.0-20261004.md)，不能由首发证据外推。

## 计数与查看

- 权威数据为角色变量 `sxad_sex_experience`，随存档保存。右键选择“查看性经验”后直接出现原生气泡，无需额外确认；它显示目标次数、六项能力的当前值和累计净变化，以及五位小数的健康当前值与净变化。六项能力分两排，健康单独一排，括号内明确为本模组累计净修正；这些读数直接显示在通知正文，不依赖悬停。查看不能新增经验、修改属性或触发吸取抽选。
- 通用查看入口覆盖尚未记录的角色，显示 0。特质说明读取特质持有人，不能绑定 `GetPlayer`。
- 不通过定期遍历全世界来给零经验角色添加特质。显示特质不承载唯一计数，不采用 100 点特质经验条作为上限。
- 计数上限为 92,233,720,368,547，达到上限后停止递增。该安全整数范围依据引擎有符号 64 位、十万倍固定点确定，并由 R0009 实际保存验证上限减一增长到上限、已达上限保持；fixed5 原始值为 `9223372036854700000`。R0010 新进程重新加载后仍保持该值。百万经验的正常查看与持有人 hover 另外实测，不能把极值保存证据扩大为极值 UI 排版或其他引擎版本验收。
- 启用之前的经历不反推。0 代表本模组尚未记录次数，不代表处子身份。经验不遗传，不跨战役保存。

## 兼容与玩家入口

以 CK3 1.20.0.3 原版为来源，描述文件声明 `1.20.*`；后续补丁兼容仍需验证。无其他模组或 DLC 硬依赖。成年 AI 与玩家相同规则是用户“每个人记录”需求的一部分。

覆盖范围限于两项原版 scripted effect 的独立生成投影，不复制整份 `00_romance_effects.txt`，不使用 `replace_path` 覆盖目录。安装了同样改写这两项效果的模组时，须合并接入点；不宣称通用兼容全部恋爱模组。

可加入现有存档，从启用时开始记录；移除后的未知自定义变量/特质处理需要实测并如实说明。多人、Ironman、成就及非目标游戏版本不在首发已验证范围。
