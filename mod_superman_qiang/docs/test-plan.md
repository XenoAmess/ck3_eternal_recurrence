# 《超人强》测试与验收方案

制定日期：2026-10-04。版本目标：1.0.0；游戏目标：CK3 1.20.0.3（Crozier），Steam build 25652598。方案先于正式验收落库。运行结果独立记录，不能把本方案勾选为通过。规则见 [产品合同](product-contract.md)。

首发实际结果：本机 L1–L3、正式标签构建、真实订阅缓存、公开媒体及完整更新说明已验证，见 [最终发布报告](release-1.0.0-20261004/README.md)。仓库提交推送回执单独记录，冻结的旧候选和历史 pending 不覆盖。

当前转移实现合同为六项有符号账本及缩放 character modifier：每项账本范围 -1,000,000 至 +1,000,000，双方同一项原始修正点严格 +1/-1，原生基础数组保持。原版百分比、取整和总技能边界继续作用于面板，不承诺有效技能严格 +1/-1。候选 L0 与本机 L1–L3 的实际结果见 [首发验收汇总](acceptance-1.0.0-20261004.md)，正式 tag 构建及 P 发布门独立关闭。[R0006 RED](live-R0006.md) 与 [A0002 缓存修复静态结果](build-validation-2026-10-04-R0006-cache-fix.md) 保留为旧候选历史，不计入新方案通过。

## 环境与证据

正式验收仅使用简体中文；其他实际支持语言只验证编码、header、key、转义、占位符及解析。先从目标安装 `launcher/settings-layout.json` 枚举语言，再与原版目录核对，记录来源 SHA-256。

每轮使用独立的完整机器/产品/R 序号、外置 attempt、production staging、独立 `-userdir` 和外置测试模组。冻结源 commit、生成器输入 SHA、staging manifest、CK3 build/EXE SHA、解释器、命令、日志、保存文件与截图。禁止改写失败轮次或把旧版本游戏结果外推成新版本通过。

启动前先登记任务总线、核对本机 MCP/operator 与 CK3 进程、取得 `ck3-screen:acquired` 独占和当次新鲜 Steam 离线画面。MCP 查询和后置状态为主要真值，脚本断言日志/存档为补充；OCR、截图文字推测、输入 ACK、工具 schema 通过不能代替机制通过。UI 操作按仓库坐标映射及英文键盘布局合同执行。

每一步先判断 `open_kaishek` 是否覆盖其确定性子集。有覆盖则先离线预验，记录工具 commit/profile、fixture SHA、命令、结果及未覆盖项；没有则记录具体 `not-applicable` 原因。离线预验不代替 CK3 实机。

## L2：真实引擎机制矩阵

| ID | 输入/动作 | 预期与断言 |
| --- | --- | --- |
| L2-01 | 双方未初始化 | 0 对 0，双方变 1，不转移技能；无未定义变量错误。 |
| L2-02 | 经验 10 对 3 | 同一可转移技能的接收者账本 +1、来源者账本 -1，其他五项账本保持；双方经验 11/4；该项双方账本增量之和为 0。无百分比及其他边界的受控场景再核对有效技能相应变化。 |
| L2-03 | 发起角色顺序反转 | 赢家仍由先前经验决定，低经验发起不会改变吸取方向。 |
| L2-04 | 经验相同且非零 | 不转移，双方各 +1。 |
| L2-05 | 六分支和随机性 | 每分支的生产 transfer helper 都实测；实际随机 dispatcher 可覆盖多个结果、每次只转移一项，无分支偏置静态错误。不以有限样本宣称随机分布已统计证明。 |
| L2-06 | 基础技能 0，有正修正 | 来源者有效技能 >0 时可贡献一个原始修正点，即使基础值为 0；双方账本同项 +1/-1，原生基础数组前后完全相同，不能出现旧试扣漏点。接收者有效值为 0 的独立场景仍能接收。 |
| L2-07 | 负百分比、取整及总值边界 | 覆盖 -25% 等负百分比、正百分比与面板钳制：原始账本和投影仍准确守恒，显示变化为 0 或 2 时不误判失败或重做转移。来源者基础有点但有效值为 0 的项不成为候选；接收者有效值为 0 可以接收。基础数组始终保持。 |
| L2-08 | 所有技能不能转移 | 无属性改变，但双方经验 +1。 |
| L2-09 | 未满 18、死亡、自身 | 无经验、技能或显示特质改变。包含 16/17 岁，避免把 is_adult 的游戏阈值当 18。 |
| L2-10 | AI/AI 与玩家/AI | 相同规则，AI 计数和方向准确。 |
| L2-11 | 匿名事件 | 仅已知、合格角色 +1，技能均不变；不构造不存在对象。 |
| L2-12 | 同日重复两次 | 真调用两次双方各 +2，转移次数符合两次结算；无去重误杀。 |
| L2-13 | tooltip/no_sex_memory | 提示预览不累计；真实 no_sex_memory 调用照常累计一次；原版记忆禁用不阻止计数。 |
| L2-14 | 大计数 | 99→100→101，百万级和安全极值夹具；记录实际可读精度，上限不溢出。百万级保存重载必测，极值理论和实测单列。 |
| L2-15 | 原版功能保全 | 真 effect 的原版压力/记忆及合格情境下原版副作用仍按其规则执行；不将怀孕概率结果误作必定发生。 |
| L2-16 | 六项账本方向边界 | 接收者 +999,999→+1,000,000、来源者 -999,999→-1,000,000 的最后合法转移通过；接收者已 +1,000,000 或来源者已 -1,000,000 时该项跳过，不越界。相反方向可离开边界；剩余候选仍等权，全项被排除仍双方经验 +1。保存重载核对百万级 signed 值。 |
| L2-17 | 缩放投影重建 | 正账本 1→2、负账本 -1→-2、正负翻转、回到 0 全部正确。只改变量而不重加 modifier 的控制样例保持旧 scale；正式 helper 删除旧投影并重加后读取新值，重复重建不叠加，0 清除正负两投影。核对同 effect 写后重建是否取得新账本，必要时验证隐藏事件提交边界。 |

强制分支夹具只能证明该生产分支正确，不能宣称经过真实随机抽选。实际 dispatcher 和原版接入都必须另外调用。夹具输出 PASS 必须对应具体账本、modifier 投影、经验和原生基础数组的前后断言；总技能读数或没有错误日志不能独自证明全部机制通过。

## P：实际发布与公开回读

正式发布前 L0/L1/L2/L3 所有阻塞项必须通过；发现机制缺陷先修复，再用新 attempt 复验受影响项。

1. clean master 源 commit/tag 的 staging、ZIP、manifest 冻结，GitHub release 附件回下载校验。
2. 用户已授权发布：通过本机 Steam native Workshop MCP 新建原创 item，冻结完整 Change Notes 文本的字符数、行数、SHA-256。不得把其他产品 ID 当目标。若出现需所有者接受的新 EULA，按仓库规则停止该发布动作并报告。
3. 上传 thumbnail 和至少一张合格实机 media，匿名回读公开标题、描述、标签、可见性、DLC、预览及媒体 CDN 实际字节。Change Notes 目标条目的 entry ID、解码/换行归一化后的全文、字符数、行数、SHA 必须完全匹配；EResult=1 不够。
4. 使用真实订阅/DownloadItem 取得干净缓存，逐文件核对正式 manifest；禁止从源码复制到缓存冒充下载。下载字节与已验收 production 投影相同则记录等价依据；有差异必须修复和复验。
5. 恢复 Steam 离线并保存新鲜画面；重建 staging 清除上传注入的 remote_file_id。只在外层用户 .mod 保留 canonical ID。
6. 最终永久 changelog 保存 `docs/release-changelogs/superman-qiang/1.0.0.md`，标明 initial baseline、item ID、tag/commit、发布事实、证据、存档及限制，并 commit/push master。公开上传、缓存核对和 changelog 均完成才能宣布发布完成。
