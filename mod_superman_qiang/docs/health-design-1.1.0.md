# 《超人强》1.1.0 健康转移设计

状态：**产品规则已冻结，健康机制、新进程重载及正常查询界面均已通过；正式发布待完成**。目标为实际 CK3 1.20.0.3、Steam build25652598，EXE SHA-256 `94b55397abb687a3dcd436805a5d885e6be90fa6c693feb44a9e3bbeeade02a6`。本设计复用只读研究与当前原版文件；下方实机结果另绑定实际进程、原生读数及保存文件，不以设计、源码或格式检查代替。

## 转移规则

健康成为六技能之外的第七个随机类别。每个合格类别权重均为1，全合格时健康概率为1/7；健康不合格只跳过健康，其余类别仍等权。原有参与者、经验方向、平手与计数规则继续生效，没有可选类别仍累计本次经验。

一次健康转移记为 **0.00075原始健康修正点**：接收者 `sxad_health_balance` 增加0.00075，来源者减少同量。Q100000表示下为双方 **+75 / -75 ticks**，原始账本增量之和为零。基础健康不改写；正负账本分别通过静态 `health=1` / `health=-1` character modifier 与非负scale投影。账本更新后删除旧两种投影，再按新余额重建；零余额不保留健康投影。

来源者当前有效健康必须 **至少3.00075**，低于该值跳过健康候选；接收者当前健康为0或负值仍可接收。3来自普通自然死亡月检查阈值，此条件是产品门槛，不是“不致死”或实际寿命变化上限的保证。

健康账本范围为 **[-1,000,000, +1,000,000]**。转移前要求接收者余额不大于999999.99925、来源者余额不小于-999999.99925；最后合法一步可恰好到边界，再向外一步跳过健康。此边界独立于基础健康，不能用面板最终数值判断账本是否守恒。

原版负健康抵消 `negate_health_penalty_add` 继续作用，有效健康可能变化不对称或不减少。已经完成的原始转移不能因此补抽、补扣或再次结算；本模组承诺的是同笔原始健康修正守恒。

## 数量级与“一个月”的准确含义

原版 `game/common/defines/00_defines.txt:326–329` 给出25岁开始的年度老年健康抽签参数：起始概率0.075，失败时健康损失0.125，概率每岁增加0.022。以25岁起始参数计算的**月均期望衰减锚点**为：

```text
0.075 × 0.125 ÷ 12 = 0.00078125
产品单笔健康修正 = 0.00075 = 75 / 100000
```

0.00075比该锚点低4%，是向下选取的保守平衡数值。这个算式只解释数量级，不是“健康点＝剩余寿命月数”的换算：衰减按年龄改变概率，18–24岁尚未开始该老年项，疾病、恢复、负健康抵消、角色pool罚值、战争与其他原版死亡规则都会改变实际结果。

因此产品只承诺每次健康转移的**原始修正量为0.00075**。不能承诺实际寿命最多、正好或至少改变一个月，也不把少量角色的死亡样本当作寿命上限证明。年度调度、生日采样及概率clamp本轮未定位，不把注释的线性增长外推成完整原生时序。

## 原版死亡规则的已知边界

同一defines文件第333–335行标注自然死亡概率使用quadratic chance，健康低于3时每月可能死亡，健康为0或以下时的月死亡概率参数为0.25。第337–338行的被标记死亡后延迟为15–20日。阈值、一个概率锚点与“quadratic”注释不足以恢复所有系数、额外修正及低于零的clamp，本设计不补造完整死亡公式。

第330–331行另有角色pool内年度0.1健康罚值与elderly 2.0死亡检查罚值，离开pool后消失；因此当前健康也不能单独决定实际寿命。`10_health_values.txt` 的旧注释仍写15–50天且引用当前defines不存在的 `DEATH_CHECK_INTERVAL`，只读研究保留该差异，采用当前明确的15–20日参数，不把旧注释当作现版精确间隔。

## 数值与界面入口

原版 `00_travel_values.txt:155–164` 的 `food_poison_value` 直接使用 `subtract=health`，与 `_script_values.info:19–27` 的同一组数值操作schema共同支持 `sxad_health_value={ value=health }`。没有找到原版直接写 `value=health` 的例子，因此该新getter仍须通过本轮真实夹具读回。

EXE中的 `CHealthTrigger` 继承 `CJominiCompareTrigger<CFixedPoint>`，支持小数比较的类型合同；已有观察接口使用scale100000。类型与表示只能说明75ticks能够精确表达，不能代替75ticks的实际增减、modifier快照、缓存刷新或保存重载验证。

`_modifiers.info:12–23` 将definition-local scale的root定义为接受modifier的角色，并在赋予时计算快照。原版 `07_ep3_modifiers.txt:1791–1829` 已有health0.1与角色变量scale先例，`00_activity_tours_modifiers.txt:199` 有负health先例。健康刷新时机需要实测，不能把六技能的 `force_character_skill_recalculation` 合同直接外推为健康刷新保证。

通知悬停第三行显示当前有效健康 `sxad_health_value|5` 与累计净修正 `sxad_health_balance_value|+5`，保留五位小数。标签使用原版 `$game_concept_health$`、图标 `@health_icon!`；原版没有小写 `$health$` 名称key。两个新健康modifier alias沿用“超人强：吸收属性/流失属性”加原版健康名；不另造寿命倒计时页面。界面设计与来源见[全模组可见界面审查](ui-review-1.1.0.md)。
