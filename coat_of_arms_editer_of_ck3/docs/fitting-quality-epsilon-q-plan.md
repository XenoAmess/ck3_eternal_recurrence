## 1. 目标与优先级

本期目标是在**相同输入、相同素材包、相同用户实例预算**下，让输出在浏览器和 CK3 中更像原图，尤其改善轮廓、五官、眼镜、发丝等小尺度结构。基线改为 Delta-Q v9；不得继续只与更早的 v14 比较，从而重复计算上一期收益。

沿用项目所有者明确指定的长期优先级：

1. **质量、效果、相似度第一。** 优化颜色布局、轮廓与关键细节；网页耗时不能让更差的结果胜出。
2. **同质量下，减少最终输出与游戏内压力。** 先比较实际绘制实例数，再报告覆盖重叠、素材数、block 数和源码字节数。源码更短不等于 CK3 渲染更快。
3. **网页生成性能是诊断项。** 几分钟级计算可接受；通过增加计算量换取质量，但必须能暂停、恢复、取消和保存当前最好结果。

用户实例预算 `B` 是输出的硬约束，不是整个产品固定为 1,024 的上限。128、1,024 是固定对照档；更大的预算继续由用户决定。搜索计算预算与输出实例预算分开，允许在不增加最终实例数的情况下多试候选。

原版素材的有限表达能力仍然存在。任意照片或插画不保证能在固定实例数下无损重建；本期要交付可核验的增量，不预先承诺“原图级还原”。

Delta-Q 在七图、1,024 实例预算、96px 感知 v2 口径下，相对 v14 的中位改善为 17.327%；但这不说明剩余误差已很小，也不等于真人确认了同等幅度的观感改善。

## 3. 建议路线

先做多分辨率选优和固定实例预算下的反复优化，再扩展轮廓表示及区域搜索。大型感知模型、可微渲染放在独立实验支线；第一阶段不以它们为前置条件。

```text
原图与固定输入预处理
  → 96 / 230 / 512 图像金字塔、轮廓与细节区域
  → 原 v9 候选 + 原生素材候选 + 轮廓候选
  → 完整 DDS 精排，保留内部多样候选集
  → 已有图层颜色/几何优化 + 满预算局部替换
  → 多分辨率评分与细节检查
  → 同质量减实例、减输出
  → serialize/parse → 完整 DDS 复验 → CK3 原生验收
```

### 3.1 多分辨率共同选优，并保留原始细节

第一步保持历史感知 v2 的定义和可复算性，将现有 v2 在三个分辨率上分别计算，形成质量向量：

```text
Q(C) = [L_v2_96(C), L_v2_230(C), L_v2_512(C)]
J(C) = 0.20 * L_v2_96(C) + 0.45 * L_v2_230(C) + 0.35 * L_v2_512(C)
```

以上权重是本规划的初始实验配置，不是已证明最优值。E0 在开发集校准后冻结配置，再开启留出集；后续调权必须新建 revision。三个绝对分数分别公开，不把一个加权平均当作全部证据。

同时修正已发现的结构评分问题：用一条贯穿边界的线分开两个背景区域，真实孔洞数应为 0，当前公式静态推导会给出 1。E0 先以最小夹具确认，再实现“从全部边界 flood-fill 排除触边区域，统计剩余连通块”的新版本；补细线、斜线、多触边分量和孔洞开闭夹具。新版本先 shadow，对 v9 与新候选同时重评，确认后在搜索前冻结。上面的 v2 向量始终保留为历史对照；若新版本晋升，另名记录新目标及相同规则的基线，不能覆盖 v2 数值或把公式修正本身计作拟合收益。

- 原 v9 完整结果始终作为候选保留。默认替换先要求三个分辨率均不劣于 v9（仅允许冻结的浮点误差），再比较 `J`；跨尺度存在取舍的结果作为备选供比较，不能因更小或更快自动胜出。
- 32px 索引用于粗筛；进入关键结构候选集后，按需解码完整 DDS，再在 96/230px 精排。512px 检查阶段最优候选和高细节候选，最终全部入围方案统一复验。
- 当前 `resizeFitImage` 使用四点双线性采样。为明显缩小的输入试验预乘 alpha、线性光面积滤波，检查细线是否被漏采样；保留现有输入裁切/适配语义。
- 预处理变化独立版本化。新旧算法都要在同一冻结目标金字塔上重评；旧口径结果另列，不将“目标图改变”计作算法提升。
- 不用生成式补细节、锐化或降噪改写目标图。重点区域始终从原始输入对应位置读取。

### 3.2 固定实例数下，重优化整幅构图

这是本期最重要的算法增量。现有局部参数优化继续复用，新增针对**完成构图**的多轮联合修正。

1. 按可见贡献与残差建立待优化图层队列，优先处理高误差区域，以及被大量后续图层遮挡的低效实例。
2. 固定几何时，依据纹理三通道、alpha、pattern mask 与上层透射贡献求解颜色。线性近似只生成 proposal，接受必须经过实际 DDS renderer；共享颜色的多实例 block 要联合求解，或先拆为等价 block。
3. 固定颜色时，分粗细步长优化位置、二维尺度、旋转及已有合法镜像表示。所有参数落到 serializer 可表达的范围，再重新解析、渲染、评分。
4. 对覆盖相交的少量图层尝试重排；用邻接交换及小组替换，避免对全部图层排列穷举。
5. 到达 `B` 后仍允许 `1→1`、`2→1`、`2→2`、`4→2` 等替换。也允许在候选副本中暂时移除低贡献组，再把释放的预算用于高误差区；每个完整可接受候选始终不超过 `B`。
6. 搜索副本可以经过暂时更差的中间状态；只有最终完整构图改善后才替换当前最好结果。保留最优档案，避免贪心删除永久损伤关键细节。

为小组创建前缀合成缓存及后续遮挡信息，减少重复重绘。旋转、层序或 mask 改变时正确失效缓存；最终验收仍走完整渲染。该缓存服务于增加可尝试的方案数，不改变评分语义。

判断价值的关键：picture-03/06 等满预算案例能否在实例数不增加的情况下明显变好，而不是只在有剩余层数的图上继续补方块。

### 3.3 按轮廓组织图元，减少方块边缘

新增“区域填色 + 方向化轮廓”候选生成器，与现有原生素材/矩形路径竞争：

- 从目标图提取颜色区域、长边界和局部切线；内部可用折线表示轮廓，按曲率分段。
- 对大面积平缓区域生成大图元，对弯曲边界与细线生成旋转矩形、椭圆/圆、楔形等候选；全部映射为当前已授权且可粘贴的 DDS、mask 和 instance 组合。
- 不把任意多边形、Bézier 曲线、程序化纹理或新 alpha 属性当作 CK3 已支持的导出能力。内部轮廓必须先编译为已验证的素材组合，才能计入候选质量。
- 分别尝试同一区域的“一个原生素材”“多个方向图元”“现有 tile”表示。用完整 DDS 测试其真实边缘，避免从素材名称猜形状。
- 区域拆分/合并与上一节预算重分配联动，让发梢、眼镜弧线、脸部轮廓获得足够实例；矩形 fallback 保留。

实验先选低复杂度头像、平涂图与细线夹具。能改善轮廓后再扩大到纹理丰富的插画，避免复杂图像掩盖图元本身的缺陷。

### 3.4 关键细节与搜索多样性

全图平均误差可能掩盖小面积但影响辨识度的结构。本期先用确定性的对比度、边缘曲率、细线及局部残差图构建细节区域，不预设人脸模型已具备动漫适配能力。

- 同时保留全局、大区域、细线和高残差区域种子；区域之间允许重叠，合成阶段统一处理层序。
- 将搜索宽度/深度从实例预算中解耦。开发集做 `beam 2/4/8`、语义深度 `3/8/16` 的分阶段消融，根据新增质量收益确定默认值，不全组合盲扫。
- 内部保留约 8–16 个按结构与残差分布去重的候选，数值待开发集冻结；最终 UI 仍可展示三项。增加名额必须产生新构图，而非重复的颜色近邻。
- 对细节区域保存原图、旧版、新版的同位置 crop，以及颜色、边缘和轮廓距离。区域只用于提出候选与质量诊断；全局质量向量仍参与默认选优。
- 七图中眼睛/眼镜/发梢可作为固定诊断 ROI，不能硬编码这些图片的坐标来驱动通用产品。通用区域算法在独立留出集验证。
- 增加一个消融检查：暂时取消旧 `1.03× legacy` 预筛，扩大 proxy shortlist 后再按完整新目标验收，测量是否存在被过早丢弃的优解。旧指标继续公开，不凭猜测直接删除保护条件。

可选的用户“重点保真区域”功能后置；本期自动质量提升不依赖用户手动标五官。

### 3.5 同质量减实例与输出

在质量优化完成后运行，而不是给质量分数叠加压缩惩罚：

1. 保留当前精确相邻同样式 block 合并；单独记录源码收益。
2. 复用 leave-one-out pruner，尝试去掉完全不可见/无贡献实例；再做多实例合成替换。
3. 每个压缩候选在 96/230/512px 和冻结细节 ROI 上均不得变差，仅允许重复计算测得的数值误差。默认不设“可牺牲 1% 质量换体积”的容差。
4. 通过质量等价检查后，再比较实际实例数、覆盖重叠估计、素材数量、block 数、UTF-8 字节数。估计量与游戏实测耗时分别列出。
5. 使用同一 CK3 场景、视角、可见家徽数量、缓存状态及帧采样方式做配对测试后，才宣称具体渲染耗时收益；若变化低于噪声，只报告实例数/字节数变化。

“同样 1,024 个 instance、少了 30% 源码”只能称为输出缩小，不能称为游戏绘制量降低 30%。压缩无收益时保留质量最好结果，不阻断质量工作包交付。

## 4. 备选研究，不列为第一阶段必做

### 4.1 可微或近似梯度优化

[DiffVG 原论文与项目页](https://people.csail.mit.edu/tzumao/diffvg/)展示了通过可微栅格化按图像损失优化矢量参数的路线。对本项目的启发是联合调整大量图元参数；CK3 DDS、mip、mask、层序及正规化与其矢量 renderer 不同，不能直接套用结果。

先完成确定性的坐标优化作为对照，再用本地实验验证平滑的 DDS 采样代理或有限差分是否更容易找到好解。代理只提出参数，必须投影回合法 CK3 源码并用正式 renderer 复验。只有冻结留出集上出现独立增量，才考虑浏览器端实现；Python/CUDA 研究环境不进入线上依赖。

### 4.2 学习型感知距离

[LPIPS 原论文项目页](https://richzhang.github.io/PerceptualSimilarity/)研究了深层特征距离与人类感知判断的关系。可将它作为离线辅助诊断，研究当前 v2 对“轮廓正确、五官错误”等样本的区分能力；其通用数据集结果不能直接外推到 CK3 和动漫头像。

先做本项目偏好样本校准，保留像素、颜色、位置和轮廓约束。不得只优化语义 embedding，让“像同类角色”取代“像这张原图”。模型版本、输入处理、权重使用许可和分发成本明确后，才讨论纯浏览器部署。缺少真人偏好数据时，记录证据不足，不宣称学习指标更接近用户审美。

## 6. 实验与验收设计

### 6.1 冻结基线与分组

- 七张历史真实图作为持续回归和已知难例，完整保存 v9 的输入、源码、实例数、三尺度指标和原生证据身份；它们已用于调优，不能再称为未见测试集。
- 沿用已有 64 例合成 holdout 验证确定性、素材检索与结构恢复，但说明其已被反复使用的历史。
- 新建 32 个独立场景，覆盖平涂/轮廓、细线/小结构、多色重叠、纹理/渐变四类，各 8 例；按场景族分成 16 个开发、16 个封存留出。使用可追溯授权输入或可重建的程序化夹具，避免同一场景的变换版本跨集合泄漏。
- 新素材未齐时先做已有基线与程序化夹具，外部真实图泛化结论记为未覆盖；不把原七图随机裁切后充当独立真实 holdout。
- 所有算法版本共享同一输入处理、pack、预算、renderer 与指标。检查点 seed 和运算顺序固定；以固定迭代配额定义可重建结果，墙钟限时只表示“当前最佳、尚未收敛”。

### 6.2 必做消融

按顺序比较 `v9 → 仅多分辨率选优 → 加联合优化 → 加预算替换 → 加轮廓/区域候选 → 加等质量压缩`。单独记录目标重采样变化；不把它与搜索算法混成一个无法归因的收益数字。

每阶段报告每图、每预算的三尺度 v2、legacy color/edge/total、固定 ROI、实例数、源码字节数、计算量、耗时、峰值内存及停止原因。对新增阶段区分“没有提出更好的候选”和“已有优解但选择器选错”。

无需重跑未变化的历史原生矩阵。复用历史 artifact，对新候选、渲染变更和新语法组合执行对应验证。

### 6.3 提议的质量目标

以下是规划中的目标，不是已有成果。E0 在开发集确认可解释性并冻结后才启动正式实验；若最终达不到，报告真实收益和未达目标，不为通过而移动门限。

| 维度 | 提议验收目标 |
| --- | --- |
| 默认选优 | 对同输入/预算 v9 基线，96/230/512px 均不退化，容差仅覆盖测得的数值误差；无新优解时回退到原基线 |
| 1,024 档七图 | 冻结联合目标 `J` 的中位相对改善至少 10%，至少 5/7 实际改善；同时逐尺度公开结果 |
| 128 档七图 | `J` 中位相对改善至少 5%，实例数全部不越界 |
| 已知难例 | picture-03/06 中至少一张在 1,024 档 `J` 改善至少 5%，并保留另一张的质量 |
| 新留出集 | 相同预算下 `J` 中位改善至少 5%；逐类报告，不能由单一类别掩盖其他类别退化 |
| 小区域细节 | 固定 ROI 逐项不退化；至少五个预先登记的细线/轮廓区域误差明显降低，E0 冻结具体度量和阈值 |
| 游戏兼容 | 新首选 parse/serialize、预算、原生 Apply/Copy/re-Apply 通过；同时评价输入→原生相似度和浏览器→原生一致性 |
| 同质量压缩 | 先通过质量等价检查再计收益；减少实例和减少源码分开报告，不设置牺牲质量才能完成的压缩指标 |

相对改善计算为 `(L_baseline - L_new) / L_baseline`。基线近零时只报告绝对变化，避免除零和极大百分比。新目标要求多尺度无退化，可能减少能自动接受的候选；若遇到明显的观感取舍，保留 A/B 和备选，不悄悄放宽。

全图 230/512px 对照、关键 crop 与真实 CK3 画面一起交付。真人判断独立记录，未完成时仍为 `pending-human-review`；自动分数通过只能声称机器质量目标达成。

## 7. 工作包与先后顺序

| 工作包 | 优先级与预估工程日 | 产物与退出条件 |
| --- | --- | --- |
| E0 基线、目标与失败分类 | P0，1–2 日 | 冻结 v9、新评估 revision、ROI、输入处理和留出划分；复现闭合区域计数问题并冻结修正版 shadow；定位难例属于选优/表示/搜索/渲染中的哪一类 |
| E1 多分辨率精排 | P0，2–3 日 | 完整 DDS 三尺度候选向量、保留基线、多样候选集；512px 已知次优选择有明确复现与修正或取舍说明 |
| E2 联合优化与满预算替换 | P0，5–7 日 | 可中断的颜色/几何/层序优化、实例重分配；满预算难例有固定实例数增益及消融报告 |
| E3 轮廓图元与结构搜索 | P1，4–6 日 | 可导出的方向图元和区域候选；轮廓误差降低并在正式 DDS、原生渲染成立 |
| E4 小细节与候选分配 | P1，2–3 日 | 通用细节区域、搜索深度独立配置、ROI 报告；留出集确认未过拟合七图 |
| E5 等质量压缩 | P2，2–3 日 | 复用 pruner、局部替换；逐候选证明质量等价，分开报告游戏实例/源码收益 |
| E6 收口 | P0，2–3 日及原生槽位 | 新候选完整 DDS、CK3、checkpoint、浏览器回归与正式 Pages 门禁；实施报告和公开版本回读 |

先执行 E0→E1→E2，约 8–12 工程日，形成第一个可独立验收的质量版本；再决定 E3/E4 的投入比例。全部主路线约 18–27 工程日，是工程估算，不包含可微/学习型支线或等待外部资源的时间，也不承诺质量目标必然达到。

E3、E4 的夹具准备可在 E2 期间并行，产品整合按依赖完成。每个工作包只做一次必要验证，提交、rebase、普通 push 后继续；已有结果复用，有新代码、新问题或新观察面再补测。

### 原生与发布边界

- 沿用当前 exact-build 授权 pack、纯前端和[Pages 合同](../../docs/ck3-coat-of-arms-github-pages.md)。新增研究依赖不进入线上路径。
- CK3 只用于开发验收，保持 Steam 离线，使用项目现有排他槽、MCP 和实机编号规则；浏览器无需游戏安装。输入预处理/序列化可覆盖的子集先离线验证。
- 浏览器→CK3 一致性只能证明 renderer 没有失配；另算原图→CK3 相似度，才能支持实际游戏效果改善。复用既有校准，不按每个候选重新找最优配准来掩盖位移误差。
- CK3 会正规化部分旋转值。输出正规化后的源码应再次评分，并做 Copy→re-Apply；不以文本差异代替像素效果判断，也不因正规化忽略实际退化。
- 代码实施后完整执行静态 pack、Vitest、无后端 Playwright、跨浏览器、离线缓存、production build 与构建后 pack 校验；正式 Actions 全绿后公开回读版本及素材包身份。

## 8. 第一项可施工任务

从现有最终候选入手，增加独立的三分辨率 v2 评分表与“当前选择 / 多尺度选择”对照，保留 v9 源码作为 incumbent。随后实现一个最小的、无需增加实例的颜色与位置优化器，优先跑 picture-03/06 和合成细线夹具。

这两步能分别回答“已有候选是否选对”和“满预算结果还能否变好”。若得到收益，再扩展轮廓与区域搜索；若收益不足，先根据残差与原生对照定位原因，避免直接用更多小方块或更大模型掩盖瓶颈。
