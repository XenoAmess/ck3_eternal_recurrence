# Defender continuation risk: Java leaf

This lane ports `ck3_autonomous_player/src/xar_autoplayer/formal_defender_continue_risk_v1.py` into the military-policy family, under `org.xar.ck3.control.military.defenderrisk`. It is a pure observation calculation. The Quarkus host can call it in process; this lane starts no server and has no Game, RPC, file, ledger, submit, cancel, or war-exit authority.

The Python producer has two reference sites in the checked source tree: `tests/unit/test_formal_defender_continue_risk_v1.py` and `native_bridge/research/project_h2743_attempt11_continue_risk.py`. The latter validates its immutable attempt-11 source, same-frame paused snapshot, exact defender identity, and sole siege before calling this leaf. Those checks remain the caller's responsibility. The Java leaf does not attest that a SHA-bound input was generated by CK3.

`DefenderContinueRiskCodec.evaluate(byte[])` accepts a strict adapter object with exactly `frame`, `contact`, and `siege`; the two optional observations use explicit JSON null. An absent key, null observation, empty list, and empty object remain different. Its result matches the original producer's JSON field domain. `decode` and `encodeRequest` support typed input round trips, while `DefenderContinueRisk.observe(Request)` provides the in-process API.

`Frame`, `Contact`, `Siege`, and `OffsiteArrival` are immutable records. State branches use enums and sealed results. IDs, raw dates, revisions, and scores retain the original Python arbitrary-integer numeric domain through `BigInteger`; they never pass through JavaScript Number. This input is not the map admission or cross-JavaScript decimal-string contract. Any future JavaScript consumer must add an explicit versioned adapter rather than silently convert these numbers.

The codec rejects boolean, float, string, missing, or null integer fields, unknown/duplicate keys, malformed UTF-8, crossed full source frames, lowercase or malformed source SHA, invalid contact horizons/arrival orders, duplicate/own-army offsite rows, empty/duplicate siege armies, crossed provinces, and out-of-range siege estimates. Nested source frames are independently checked before comparison, so Python equality between `True` and `1` cannot qualify a frame. The shared parser imposes the existing 65,536-byte boundary; textual identities use the shared bounded Unicode validation.

Opaque JSON entries in the original `conflicts` array are retained as validated immutable encoded JSON. This leaf only observes whether that array is empty. It does not invent a conflict schema or interpret a floating-point value inside opaque evidence. Mutable Jackson nodes are confined to the codec boundary.

The output preserves the original safety boundary: a contact-free day covers current orders and a single verified game day; a later waypoint remains outside that bound; listed offsite arrivals never prove the complete roster. A siege clock remains a current estimate, including at zero days. The current war score has no inferred trend or future bound. Material CB terms, territorial/asset exposure and valuation, finite-horizon loss and war-cash upper bounds, and complete encounter participation remain required blockers. Soldier counts are not converted into victory probabilities. Loss upper bound, win probability, surrender-versus-continue utility, recommendation, and action remain null; `material_comparison_ready` stays false.

It records exact source hashes, capture time, and `machine_id: xenoamess-full-tower-eb9d2c1186`; these are capture-machine facts, not another machine's runtime qualification. The original Python unit file was actually executed with 4 tests passing. Java tests use only this tracked fixture and do not invoke Python by default.
