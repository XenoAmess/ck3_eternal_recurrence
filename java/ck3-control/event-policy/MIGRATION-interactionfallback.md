# Pending interaction left fallback candidate

This package migrates the pure selection in `pending_interaction_fallback.py` and the eligibility guard in `strategy.choose_one_life_turn`. It produces immutable candidates. It has no MCP, HTTP, desktop, native transport, filesystem writer or canonical ledger access. The existing Quarkus host can eventually call this library within the normal planner; this package does not start another service.

`InteractionFallbackCodec.parseRequest` accepts the explicit v1 projection, validates exact fields and types, and constructs typed records. It does not accept the full legacy snapshot/context. The producer adapter must retain the original complete context for durable capture and supply the same-frame projection. Numeric native revisions use exact uint64 integers; signed generation-bearing pending IDs use int32 except CK3's `-1` invalid sentinel. No JavaScript numeric round trip is permitted for the uint64 projection. Missing, null and present legality entries survive request serialization independently.

The planner retains an existing selected plan, blocked marriage handling and an already-created fallback. Context status, instance ID, native revision and raw date must match. Normal notification order is the source-proved left Reject then right Accept, independently of legality dictionary insertion order. A disabled, unavailable, absent or unsupported left reply produces a diagnosis with no selected step. An auto-accepted notification uses its single acknowledgement channel. The source GUI SHA and three reviewed same-order variant SHAs are preserved. Built-in clerical-chastity classification requires both its canonical key and deterministic hash.

The immutable offline review loader, original-context capture, before/after incident files, action dispatch, receipt verification and completed-batch collection remain with their existing owners. This candidate API cannot inject an arbitrary JSON `reviewed_rule` as verified knowledge. Offline source/facts/file identity revalidation must be connected through its separately migrated source registry before dynamic reviewed entries can be marked known here. It is not silently approximated by a claimed SHA. This initial candidate contract covers the compiled reviewed rule and otherwise returns `offline_followup_required=true`.

The result schema is an explicit projection of the legacy plan/capture, not the complete old evidence ticket. It preserves phase, decision, GUI/source binding, displayed option order, native legality, candidate selection and reviewed rule. Candidate success grants no action/SAVE/material-effect credit. Integration must preserve a single Game submission authority and write the complete original before evidence before submitting once; UNKNOWN remains non-replayable. The existing after-capture contract separates command ACK, actual original-window advancement and unverified material effects.
