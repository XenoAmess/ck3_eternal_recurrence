## 1. 执行与判定口径

首版只允许已经实现并通过对应原型的 **12 项异能、8 项诅咒**进入生产抽取池。36 异能、32 诅咒和 10 联动是完整内容池；不做 `36×32×3×全部角色` 的笛卡尔矩阵。这里选择 4 个只使用首批异能的代表联动；其他内容启用前按本表模板追加用例。

每个 case 都先做：原生前态读回 → 通过真实生产入口触发 → 原生后态与生产账本对照 → 去重／负例 → 卸下。实机统一走仓库公共验收入口，机器、运行版本、fixture 与证据身份由总方案绑定。本文件不运行游戏、不登记本机通过事实。

`LW-A* / LW-C* / LW-X*` 是公共 **`core_continuous`** 中的逻辑子场景 ID，由产品 adapter 的一次 `run_case` 顺序编排并分别记结果；不是虚构一套跨 case 复用会话的 CLI 参数。现公共入口一次 run 只调用一个 case 并在 finally 关闭的边界保持。下文「复用」指同一公共 case 内的真实来源或已保存、身份绑定的生产检查点，不省略真实触发，也不把前一 run 已退出的游戏冒称仍可复用。

- **fixture 可以布置输入**：有效物品、槽位、rank、合法人物关系、现金、控制力、距离下次经验阈值、战争初始兵力、真实秘密的初始存在状态。可以固定模组自己的随机分支／目标选取，必须在回执写明覆盖了自然概率；这不证明自然掉率。
- **fixture 不得替代生产者**：不能直接调用异能结算 effect、写金币或经验后当作收益、把计谋强写成已成功、直接杀死骑士后声称验证了战斗死亡、直接写抵达／活动完成标记。战斗、活动、计谋、发现秘密、决斗、修复与月季调度必须真正完成原生流程，再进入本模组生产处理器。
- 随机分支固定值只在**真实源事件到达生产随机门槛时**消费；不直接触发处理器。普通正向 case 使用满共鸣、未镇压、无额外诅咒干扰；概率边界与低共鸣／镇压由总方案的公共 case 验证，不在每条重复。
- 数字均指**模组增量**。原生战利品、宴会收费、正常月收入、伤病与压力事件先单独计账，取得原生结果后态 `S`；再核对实际后态相对 `S` 的差。不能把整月正常收入算成梦中本金，也不能把原生压力消耗误算为异能代价。若没有可用中间观测，可使用同一原生输入的无目标词条对照，但不得伪造原生结果。
- 持续修正需读实际效果及来源；仅有变量、ACK 或通知文本不够。即时代价在卸下后不倒带；本件勇武、健康、速度等装备持续投影卸下即时撤销，物品经验停止、活物加成消失。债务、已经发生的秘密公开、关系损伤、原生伤病，以及A12已施加给他物的30日压阶按各自既有合同保留；A12自身勇武仍即时失去。
- 同一实际源事件在多入口到达、暂停后继续、保存重载或重新开管理页，都不能多发。优先观察真实多回调与重载，不为验收额外提交第二次真实业务动作；不能用向生产器手工注入假事件来取得业务 PASS。

case状态统一使用[执行合同](acceptance-execution-contract.md)的NOT_RUN/RUNNING/PASS/FAIL/BLOCKED/NOT_APPLICABLE。缺原生来源、参与者身份、准确读回或必要接口时，受影响子项记BLOCKED并继续其他可执行项；没观察到罕见事件不能判负例PASS。必需子项BLOCKED时该条不得完整通过；尚未启用内容可明确排除在首版之外。

特别是 **A02 的死者记忆与真实决斗回声、A07 的秘密收藏与新主原生知情、A12 的连续三月情敌与下一次突变偏向**都是该异能的必需机制。任何一项接口或真实来源缺失，整个对应异能记 `BLOCKED` 并不启用，不能凭它的基础威望／经验／勇武数值通过而缩减玩法后宣称完成。其他条目继续推进。

### 单条证据最小内容

保存 case／子项、角色与物品真实引用、是否玩家／NPC、实际装备状态、rank／共鸣／镇压、源事件与参与者／目标、源事件发生时间、fixture 布置和固定随机值、前态／原生结果态／模组后态、费用与 modifier、冷却／额度、卸下后态、实际用时及结果。原生事件没有可靠唯一 ID 时，先证明可靠身份或去重合同；不能用日志行号自行冒充。

## 5. 玩家／NPC、频率与后续扩池

每条主 case 至少由一种真实 actor 完成，不把「把玩家标签改成 AI 后直接运行 effect」当成 NPC 验收。选 **A01、A04、A06、A12、C01、C02、C04、C08** 再以 NPC 复验同一数字合同：让原生 AI 真正选择／完成相应战斗、拉拢、装备或自然调度，观察它按真实钱包、健康、军费、压力与统治局面取舍。fixture 可创造有吸引力的合法候选，不能强写 AI 决策结果。

NPC 在预算内不选择所需动作时，记为 `BLOCKED: source_not_observed`，不能判算法失败，也不能因此给通过；月／季来源仍可独立推进。涉及玩家与 NPC 的物品转移还需确认原物身份、共鸣重置与持续效果切换，没有一物两主或前后两人同时吃装备加成。

上表的墙钟预算包含本 case 正式动作与读回，公用原型、游戏启动和共享 fixture 准备单列，不按每条重复整套启动。到达次数／时间上限即收束当前 case，保存已有后验与缺口，继续其他有来源的用例；不无限重开同一场只为碰到自然骑士阵亡或秘密。冷却／两年关系期限可在同一次受管运行中推进，不能直接改截止字段来冒充到期；同源重载与短期冷却负例优先复用已有生产检查点。

新增内容复用模板：`caseID → 图鉴合同版本 → 启用状态 → 角色/物品输入 → fixture范围 → 真实源事件 → 数值后验 → 负例/限额 → 卸下及既有后果 → NPC代表 → 次数/时间预算 → 实际证据与结论`。每个新事件来源先做一次共享资格，再验证内容自己的数值与独特生命周期；不能用来源资格代替玩法通过，也不要求已通过条目随每次扩池重做全部组合。
