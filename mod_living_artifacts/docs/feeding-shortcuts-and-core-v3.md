# 四档喂养入口与连续核心验收 v3

日期：2026-10-22。**本文说明当前开发源码及下一场验收方案；新增喂养流程的实机状态为 `NOT_RUN`，不是通过记录或发布声明。** 规则来源是[核心生成器](../tools/living_artifacts_core.py)、[数值合同](../tools/living_artifacts_model.py)、[连续核心合同 v3](../tools/core_continuous.contract.json)及[实际适配器](../tools/acceptance_adapter.py)。

## 玩家如何喂养

1. 打开决议 **“倾听活武器”**。指引页 `xalw.12` 可直接打开一件自己已装备的活武器，优先等级最高者；需要指定其他物品时，仍可右键自己的头像，使用 **“管理活武器”** 的原生宝物选择器。
2. 管理页 `xalw.10` 提供普通、大师级、名作级、卓越级四档材料入口。某档只有在目标能够成长且库存存在该档合格材料时才显示。
3. 选择一档后，从该档安全材料中挑选**耐久度最低的一件**，打开确认页 `xalw.11`。此时只是选中候选，尚未销毁材料或增加经验。
4. 确认页显示目标、具体材料名称、本次经验及食性收益。选择“让它吞下这件装备”才提交真实消费；选择“保留材料”则取消。两条路径均在目标仍合法归自己所有时回到管理页，可继续选择下一件。

四档入口是便捷候选方式。原有 **“喂养选定的活武器”** 交互及原生材料选择器仍保留，可精确指定食物。若候选并非想消费的物品，可取消，再通过 **“切换喂养保护”** 将其标为保留，或改用自选交互。

候选入口、自选入口和实际消费处理器共用安全检查：材料必须是自己的未装备、非活个人装备，不能是目标本身；目标必须已装备、持有人在世且未被镇压。唯一物品、显式保留物品，以及当前代码列出的剧情、禁止转赠、家族/王朝旗帜、历史或宗教重要标记均被排除，也排除持有人信仰的圣物。**新入口没有放宽重要物品保护，也不提供通过确认页绕过这些限制的方式。** 确认消费时会再次检查目标、材料及归属。

| 原版稀有度 | 基础经验 | 匹配食性后的经验 |
| --- | ---: | ---: |
| 普通 `common` | 80 | 100 |
| 大师级 `masterwork` | 200 | 250 |
| 名作级 `famed` | 500 | 625 |
| 卓越级 `illustrious` | 1,200 | 1,500 |

食性倍率为 `×1.25`、向下取整，稀有度仍取物品真实的原生字段。实际销毁成功后才发放经验，立即依次结算所有达到门槛的等级。**确认的是材料消费，不是升级许可。** 不存在升级确认、主动锁级或喂养冷却；同一暂停日期可以连续喂多件。卸下免费停止成长并失去活武器持续效果；仍装备时只能付出代价暂时镇压，镇压期间也不能喂养。

## v3 将如何取证

`core_continuous` v3 仍是第一阶段核心用例，范围为原生装备、装备月结自动升级、卸下月结停级，以及四档连续喂养。夹具只提供冻结的初始物品和状态；业务阶段通过真实装备接口、自然日推进及正常管理事件执行，不由夹具直接写入经验、等级或材料销毁终态。

下一场从来源绑定的1066年罗贝尔开局，在每个检查点调用真实保存，保留原始存档并使用严格 melter 解析，未知 token 不忽略。保存状态与当次独立原生观测交叉核对角色、目标物品、主人、装备状态及库存。不能用通知文字、按钮 ACK、同名物品或人为填写的目标 ID 代替这些后验。

| 检查点 | 必须真实完成的过程 | 预期目标状态 |
| --- | --- | --- |
| 1 | 1066.9.15保存初始输入，绑定目标与四件材料的实际身份 | 未装备，1级/92经验，成长序号0 |
| 2 | 原生装备后推进16个完整自然日，到1066.10.1月结；不打开成长通知或批准升级 | 已装备，2级/0经验，成长序号1 |
| 3 | 原生卸下，再推进31个完整自然日，到1066.11.1月结 | 未装备，仍为2级/0经验，成长序号1 |
| 4 | 重新装备，通过管理页真实消费普通材料并保存 | 2级/80经验，成长序号1 |
| 5 | 同一暂停日期消费大师级材料并保存 | 3级/80经验，成长序号2 |
| 6 | 同一暂停日期消费名作级材料并保存 | 4级/280经验，成长序号3 |
| 7 | 同一暂停日期消费卓越级材料并保存 | 6级/580经验，成长序号5 |

表中四次喂养以初始存档实际证明的**甲胄食性目标、四件剑类材料**为前提，因此使用非食性基础经验；不把这组结果冒充食性倍率验收。每次消费后，原生库存必须证明该件及此前已消费材料的真实 ID 不再存在，其他尚未消费材料仍在；本次真实存档则必须只保留预期的剩余材料，目标身份、主人、装备状态、等级、经验和成长序号全部吻合。四次喂养及保存之间不推进游戏日，才能证明此路径无需等待冷却。

进入管理页走与玩家相同的普通决议路径：原生 MCP 的 `ck3_open_ingame_decisions_v1` 打开决议列表，`ck3_select_ingame_decision_item_v1` 选择 `xalw_manage_decision`，`ck3_confirm_ingame_decision_outcome_v1` 确认，并核对实际出现的 `xalw.12`。之后的 `xalw.12 → xalw.10 → xalw.11` 选项也使用原生 MCP。适配器从冻结生成器推导原始选项索引，再与实际事件实例、定义、角色、暂停日期和当前显示/可用选项核对，不用 OCR、鼠标选择事件或猜测第几个可见按钮。每次提交后独立检查原窗口是否被预期事件替换；结果未知时保留证据，不重放消费。这是待实测的接口路线，接口支持不等于本场业务已通过。

检查点3的通过范围仅是**卸下期间经验和演化停止**。持续修正是否完整撤销、重新装备后的下一次月结恢复、食性倍率、取消和保护负例、AI/NPC自主培养、诅咒与联动、传承转赠及冷载仍需各自的实际证据，不能从本核心用例外推。
