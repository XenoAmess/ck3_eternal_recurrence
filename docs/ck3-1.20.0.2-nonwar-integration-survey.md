## 集成路径

master 已包含长期积累的 M5 非战消费者、状态机与私有传输口；从旧迁移分支反向导入它们会连带导入大型 Python 和原生依赖图。因此保留 master 的 DTO、消费者与策略，再把 1.20 的独立 adapter 接到公共接口。

`game_adapter.cpp` 按 EXE SHA 选择 1.19 / 1.20 实现；1.20 的 worker adapter 在 Application-main 发布原生快照并执行需要该线程的查询。新版使用自己的 PeekMessageW、TLS、RNG 和命令队列绑定。提供新版 build profile 时，mailbox 不安装旧 SDL PollEvent 绑定。没有提供 profile 的旧版路径保持原样。

master 的 69 个固定 executor 字段全部保留。1.20 semantic executor 使用新增的 `permitted_executor_semantic12002`，不会覆盖 master 的第 14 个固定字段。生产使用 `RegisterNonwarMailboxExecutorsV1` 接入逐域 callback；共享源树默认仍关闭原有非战私有编译选项。

| 非战接口 | 1.20 生产路径 | 数据/结果兼容方式 |
| --- | --- | --- |
| LIFE 43 | `ExecutePlayerLifestyleFormalWireMailbox12002V1` | 旧 formal-wire DTO 的新版派生 context；新 focus/perk validator、points/XP 字段及 owning queue；保留旧策略/receipt 合同 |
| ECON 42 | `ExecuteConstructionMailboxV1` | 同帧 world/held source、实际 native cost/legal；请求 action 时在同一个新版 executor 调用新 direct-submit；旧 GUI cache 明确未采样 |

`RenderQueryBuildIdentity` 仅用于新版 provider 已经产生的数据，把已有纯 serializer 的 build/backend/SHA 元数据渲染为实际 adapter。它不授予旧版 native 读取器新版资格。

公共 `GameAdapter::ReadArrangeMarriageFamilyCandidatesV1` 已接入实际新版 provider；Worker 通过自己的 semantic mailbox 执行并完整传递 subject ID、候选行、诊断与 available / subject-not-found / unavailable 状态。ranked 38 单独使用原生 Strategy 的真实排序、signed score 和容器生命周期，不把基础候选的行号当作 rank。

rich 48 与 child-value 的生产 JSON body 提取到 `ck3_12002_family_wire.cpp`；原桥接 wrapper 与实际 provider fixture 调用同一纯 serializer。five-row rich 48、child-value 和 ranked 38 的实际 C++ 输出已交给联合策略的 Python consumer 做跨语言检查。

## 已执行静态验证

使用 MSVC 19.51 / Ninja，`--jobs 64`；所有构建输出、TEMP、Python cache 留在 Z 盘 artifact 下。默认生产 DLL 与 injector 已成功链接；开启现有 LIFE、ECON 查询/动作、FAMILY ranked/alliance/heir/child 私有选项的独立候选配置也成功链接。

中央已通过 adapter、semantic adapter、thread runtime、LIFE、完整 campaign-root、FAMILY 当前婚约 / rich projection / child-subject / outbound、adapter registry 及生产非战 executor 注册 fixture。新增 ranked provider / shared serializer fixture、公共 family 查询路由与 17-request Worker fixture、真实 five-row rich serializer fixture也已通过。旧 mailbox 源码顺序 fixture 已适配实际 Worker 生命周期并通过；其 install-before-Hello、旧安装路径及全部 slot 断言保持有效。逐域已有的 Od/O2 和冻结 EXE ABI 证据直接复用，没有为了合并重复跑相同矩阵。

中央收口文件位于 `artifacts/offline-nonwar-2026-10-01/integration-final-manifest.json`，包含两种 Release / 64 配置、DLL / injector、实际 Ninja 编译输入与头文件、latest fixture 与 owned-ready 文件哈希。`family-ranked38-native.json` 及 provenance sidecar 保存真实 ranked C++ wire 与对应 provider / serializer / test EXE 资格。源码冻结后的最后一次增量构建不重复逐域矩阵。

保留的失败包括中间集成编译 RED（DTO 字段、遗漏 parser、同时包含头文件的常量命名、施工中的 outbound 定义），以及一次测试 harness 参数错误。泛用 runner 把 frozen EXE 作为 LIFE fixture 的 JSON 输出位置参数，导致冻结副本被写成 1168 字节 JSON；协调者保存失败文件后已从实际安装的相同 SHA EXE 恢复。实际游戏安装文件和正在运行的游戏未被修改。中央 CMake/runner 已按每个 fixture 的真实 CLI 传参，并只重跑受影响的 LIFE fixture；没有添加新的门禁。

本轮不启动、关闭、重启、注入或查询本地 CK3，不占用桌面或实机 pipe。此文与静态 artifact 只表示 `static-ready`，不能把此前另一份 DLL 的 live 结果外推到此次集成产物。最终 paused 查询、原生动作、独立 requery、cold recovery 与 M5 联合运行仍需要本次候选 DLL 的真实实机 artifact。
