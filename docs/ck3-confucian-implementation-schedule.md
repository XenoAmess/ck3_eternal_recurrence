# 儒家宗教与礼仪重构：实施排期

制定日期：2026-10-04。依据：[总规划](ck3-confucian-flavor-mod-plan.md)、[36项礼仪与36张信条设计清单](ck3-confucian-rites-and-tenets-design-list.md)。

状态：条件性工期估算。当前已完成设计与初步考据，尚未启动mod实现；下面日期按2026-10-05开始持续开发计算，不代表已预约实机或已安排自动执行。

## 1. 预期周期与投入假设

**首个可玩样板预计4—6周，覆盖完整设计清单的基础版预计18—20周；风险缓冲保留到第24周。**

排期假设：

- 一名主要开发者负责数据模型、集成和验收，每周约25个有效工时。
- AI协助考据、文案、脚本草拟和静态检查；实机、接口定案和跨模块集成按实际资源串行协调。
- 可以获得符合仓库现行合同的CK3实机时段；其他高优先级任务不长期占用本项目预定开发量。
- 基线为CK3 1.20.0.3；使用原生素材和简洁界面，首轮以中文、英文内容为主，发布语言格式按项目门禁处理。
- 明清学派作为宗教内容纳入；架空思想发展及可选时间线配置不包含重建完整明清地图、人物与战争剧本。

预计工作量约380—520小时。18—20周是上述投入下的排期基准，不是对未验证接口的确定承诺。少于25小时／周、无法及时实机或版本适配返工时，日期相应后移。

按工程依赖采用较稳妥的18—20周基准。仅把名称、说明和被动加成填入36个槽位可以更快，但不符合本项目对宗教实践、真实差异及领袖职能的验收要求。

## 3. 内容分批与首版范围

### 第一批：先证明核心差异

优先从经疏、孟荀、郑王、朱陆、李氏等选择6—8条原型。具体取舍以M0结果为准，验证以下四种差异：

- 性论：扩充四端与师法化性。
- 祭礼：祭天、郊丘、祖先配享的不同解释。
- 经典与传承：经疏解释、受业和圣贤认可。
- 成德工夫：居敬穷理、发明本心、复性与省察。

样板必须形成实际宗教实践，能够保存、重载并在角色继承后继续发挥作用。

### 第二批：约12条首轮试用路线

建议采用孔门、孟氏、荀氏、董氏公羊、郑氏、王氏、经疏、韩氏、李氏、关学、朱子、象山，约需20张信条。

这批覆盖经典、性论、灾异、祭礼、修身和学统，适合先检验共同框架。将其他学派继续纳入后续批次，不改变36项设计目标。

### 第三批：先秦至宋目录

补齐R01—R23，包括古文、跨界玄儒、濂溪、二程、象数、新学、苏氏、湖湘、永嘉、永康等。已有样板的事件模板可以复用，但各路线须有可体验的解释差异。

同faith分歧配置应在批量数据之前确定；主礼仪变化或核心认可池调整以后，检查受影响组合。

### 第四批：元明清及改革内容

完成R24—R36：草庐、白沙、甘泉、阳明、江右、泰州、蕺山、东林、船山、颜李、乾嘉、常州及经世综合路线。

默认采用已明确标注的历史年代或架空思想发展方式。若希望严格延长至清代后再按史开启学派，终期与晚期运行配置须单独验证；完整明清历史开局属于额外工程，不计入本宗教mod基础排期。

领袖与军会不是等到第四批才开始研究：M0先验证，M2—M4逐步完成宗师、礼官、奉祀及国礼职能；军会按原型确定的承载和战争适用范围实现。

## 4. “基础版完成”的最低标准

| 对象 | 完成要求 |
| --- | --- |
| 每项礼仪 | 年代与依据可查；至少一种可参与的宗教实践和一种体现本派解释的实质选择；相近路线至少有两项可体验差异；进入、改换、继承与重载正确 |
| 每张信条 | 至少接入一处有成本、结果或失德反馈的有效实践；不只显示文本和被动加成 |
| 宗教权威 | 约定角色有任命、实际职能、退出或继任；国礼、奉祀、师承权限分别验证 |
| 军事修会 | 约定方案能创建、供养、征用，并实际用于符合条件的战争；明确同faith不同rite、原生AI及普通内战等适用边界 |
| 共同宗教 | 神圣叙事、经典、德性、祭祖及孝谏形成统一框架；存量钩子等迁移有证据 |
| 产品交付 | 中文／英文内容与发布格式校验、支持的DLC／兼容说明、可复现构建、实机证据与发布闭环完成 |

基础版不要求36派各自拥有多条独立长剧情、完整新活动界面或专用美术。若追加这种深度，预计再留6—10周深化期，实际按追加内容重新排期。

原生接口无法承担某项时，按设计清单采用角色、关系、事件等可验证方式保留宗教功能；不能删掉功能后仍把原节点记为全部完成，也不能把替代角色冒称原生faith／rite领袖。

## 5. 关键依赖与重新估算节点

| 依赖 | 为什么影响工期 | 最晚决策节点 |
| --- | --- | --- |
| 同faith分歧及主礼仪更换 | 决定36条核心组合是否会创建新faith或成为异端 | M0；批量配置前定案 |
| 领袖任命、权限与继承 | 原生全faith权威未必能表示各国国礼或各派宗师 | M0确定承载；M2验证完整职能链 |
| 军会创建及实际使用 | 能建立组织不等于能参加约定战争；faith参数及AI入口可能要求改方案 | M0确定范围；M4前完成战争使用证据 |
| 玩家范围与原生传播 | 新事件的玩家门禁不能自动限制共享被动教义和原生AI行为 | M0建立框架；每批验证 |
| 晚期学派时间线 | 宗教内容与完整明清历史剧本的工作量不同 | M0明确基础版采用的启用方式 |
| 孝道存量与存档迁移 | 已有钩子、父母子女参数和旧rite引用可能独立影响结果 | M2前验证迁移 |
| 实机时段与游戏升级 | 占用等待或新版本可能使旧结果需要重新适配 | 每个里程碑按实际资源更新 |

首次校准在**2026-10-18—10-25的M0验收后**：记录实际工时、可复用接口、已通过证据和未闭合问题，更新M1—M5日期。若原型失败，应在当时调整方案与排期，不到最后阶段才暴露。

考据、文本、数据草案和静态检查可以并行；共享模型定案、集成和受管实机有顺序依赖。排期未把增加AI线程简单当成成比例缩短全部工期。
