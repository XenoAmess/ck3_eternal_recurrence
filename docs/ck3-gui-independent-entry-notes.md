## 独立入口与覆盖范围

通过 `gui/scripted_widgets/` 注册产品命名的 GUI 控件，可以在不覆盖原生视角栏文件或同名类型的情况下显示独立入口。该产品实测使用屏幕右下角锚点，把圆形按钮放在原生“＋”附近；原生常驻栏和“＋”仍可使用。相对于直接投影整份原生栏，这能消除该入口新增的同文件/同类型覆盖面。原产品的其他 GUI 覆盖仍需分别分析，第三方 HUD 的不同布局也可能产生视觉重叠；“独立注册”不能作为所有视角 Mod 兼容的证明。

不要把 `attachto` 的目标直接等同于几何父控件。本项目较早场次的按钮在真实布局中出现在右侧边栏中段，而非预期的视角栏附近。改用已实测的屏幕锚点后才满足该产品的位置需求。这是特定控件树下的观察，不推出引擎中所有附件定位均不可用。

## 字号、状态和值必须由引擎验证

结构解析和可逆投影不验证控件继承属性。字号为 10 或 12 的角标都曾因继承的 `fontsize_min` 约束被引擎拒绝；显式设置合法的最小字号后，诊断才消失。因此检查字号时应同时检查最小值和实际继承，静态花括号通过不能替代加载日志。

首次进入成功不能证明可重复进入。该产品原生活动说明窗口会复用；以不变活动类型触发的已完成动画，在第二次打开时没有再次完成自动确认。加入显示/隐藏条件标记的候选也没有解决真实重复进入。最终采用每次用户点击显式写入 `yes/no`、交替选择两个命名进入状态，并在同一进程内连续三次进入验证通过。普通宴会仍保持人工确认，并能进入自己的选址流程。其他产品应按其实际窗口生命周期选择方案，不把这个产品的两状态设计当作通用强制实现。

不要让离线 GUI 解释器替引擎发明变量值。失败候选使用 `Toggle`，却按字面 `yes` 做 `HasValue` 判断，解释器也假定 Toggle 写入 yes，结果静态通过而实机第二次进入失败。最终显式 Set 值并修正解释器；需要判断存在时使用存在语义，需要判断字面值时由明确写入建立合同。没有有效值读回时，不宣称已经证明 Toggle 的内部字符串。

## 验证与保全

这次验收分别观察普通按钮、悬停、原生展开菜单、重复进入、收起/恢复、退出恢复地图模式、筛选刷新和普通活动规划。地图模式恢复不包含相机位置或缩放恢复；一个窗口尺寸的显示也不覆盖所有 UI 缩放。

R0013–R0018 的字号、位置、重复状态及解释器假设失败保留，最终 R0019 单独验证全部关键路径；不拼接失败场次的局部成功授予最终通过。静态测试、实机业务和正式发布分别记录。仅本页文档富化，没有修改框架实现或增加实机测试；验证为来源证据核对、链接检查和 Git whitespace 检查，不重复 parser/全量回归。
