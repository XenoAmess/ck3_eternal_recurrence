# 群雄割据阶段保留朋党：mod 修改方案

> 2026-10-10 主线整合：恢复来源提交 `373c03198557e211b4830bb6cc29cc746e92e784` 的研究。下文“当前”均指原调查时的构建与样本；没有新增实机验收，也没有把结论外推到 CK3 1.20.0.4。文中外置原始路径是历史定位，本次未重新读取那些原件。

适用构建：当前原版 CK3 **1.20.0.3**。调查日期：2026-10-05。本文按用户要求仅列理论修改方案，没有实施玩法修改或进行实机验证。二进制调查依据见[研究记录](ck3-1.20.0.3-dynastic-cycle-movement-persistence.md)。

**可以通过 mod 的脚本与 GUI 修改处理已定位的问题，不需要修改 EXE。** 用户已让 `h_china` 不销毁，下面以此为前提。还需要区分：头衔有持有者、旧朋党成员标记没有被删除、角色实际留在对应参与组、界面没有强制显示“解散”。

以下路径均是 mod 相对根目录的覆盖位置，对应当前安装的 `game/` 原版路径。应在自己的 mod 中修改已有覆盖，保留其他原版逻辑和用户现有改动；不直接改 Steam 游戏文件。脚本文件使用 UTF-8 BOM。本文所称朋党是 `participant_groups` / `movement`，不涉及普通叛乱派系 `common/factions/`。

## 修改点总表

| 修改点 | 改前 | 改后 | 是否需要 |
|---|---|---|---|
| 天下分裂 effect 的末尾清理 | 删除全部参与者的 `movement_member`，再重算组 | 保留旧标记，按有效性重算 | 保留原成员关系的直接修改点 |
| `on_vassal_change` 的清理 | 独立者或领主属于 `other_rulers` 时，删除本人及所有封臣的标记 | chaos 阶段跳过这块清理；其他阶段沿用 | 割据时会换领主/独立的情况下需要 |
| `h_china.holder` 与旧天子退位 | 不销毁头衔，仍可能执行旧天子的全领地退位 | 持有者存在；是否让同一天子留下另行选择 | 必须确认 holder 存在；取消退位是条件性修改 |
| 参与组 `is_character_valid` | 五组最外层都要求有天子；已有标记时匹配原类别 | 可在 chaos 用已存标记直接决定留组 | holder 始终存在时通常无需改；要容忍无天子时才增加 |
| `dynastic_cycle_no_movement` | chaos 为六组配置“解散”提示 | 删除这六处参数 | 要消除轮盘/阶段效果中的旧提示时需要 |
| GUI 的 chaos 限制 | 隐藏朋党页签和内容，强制显示王朝页 | 允许打开朋党页，并由页签变量选择主体 | 要在 chaos 查看朋党列表时需要 |
| 选择/切换朋党决议 | chaos 时不显示 | 可解除该阶段限制 | 可选；仅保留原成员不需要 |

**当前有天子的最小方案，重点是取消两处标记清理、删除“解散”参数并放开所需 GUI。不要默认把所有参与组条件全部放宽。**

## 1. 保留天下分裂 effect 末尾的成员标记

文件：`common/scripted_effects/10_dlc_tgp_dynastic_cycle_scripted_effects.txt`。

定义：`tgp_chaos_shattering_effect`，当前原版末尾清理在第 665–670 行。

改前：

```text
hidden_effect = {
    situation:dynastic_cycle = {
        every_situation_participant = {
            remove_variable = movement_member
            recalculate_participant_group = situation:dynastic_cycle
        }
    }
}
```

改后：

```text
hidden_effect = {
    situation:dynastic_cycle = {
        every_situation_participant = {
            recalculate_participant_group = situation:dynastic_cycle
        }
    }
}
```

变化：保留尊王/进取/攘夷/守旧/中立的旧类别标记，让重算依据现有类别进行。这里仍然检查组资格，不需要每天让角色重新加入。只取消头衔销毁而保留原清理，仍会主动抹掉这份归属。

## 2. 在 chaos 时跳过换领主的朋党清理

文件：`common/on_action/title_on_actions.txt`。

定义：`on_vassal_change`（第 4845 行）；目标是其中第 5002–5021 行的单个清理块。

改前：

```text
if = {
    limit = {
        exists = top_participant_group:dynastic_cycle
        NOT = {
            has_title = title:h_china
        }
        OR = {
            liege = root
            liege.top_participant_group:dynastic_cycle ?= {
                participant_group_type = other_rulers
            }
        }
    }
    remove_variable = movement_member
    every_vassal_or_below = {
        remove_variable = movement_member
    }
    recalculate_participant_group = situation:dynastic_cycle
}
```

改后，在现有 `limit` 增加“当前不是 chaos”条件：

```text
if = {
    limit = {
        exists = top_participant_group:dynastic_cycle
        situation:dynastic_cycle = {
            NOT = {
                situation_current_phase = situation_dynastic_cycle_phase_chaos
            }
        }
        NOT = {
            has_title = title:h_china
        }
        OR = {
            liege = root
            liege.top_participant_group:dynastic_cycle ?= {
                participant_group_type = other_rulers
            }
        }
    }
    remove_variable = movement_member
    every_vassal_or_below = {
        remove_variable = movement_member
    }
    recalculate_participant_group = situation:dynastic_cycle
}
```

变化：在群雄割据过程中，独立或改换领主不再经这块逻辑清掉原朋党；其他阶段仍执行原来的退出规则。

必须修改原有清理块。另加一个 on_action 并不能阻止原块先清空标记。同名 on_action 定义覆盖而不合并，所以覆盖 `on_vassal_change` 时保留其全部其他逻辑，只修改上面的条件。

## 3. 头衔不销毁，还要确认有持有者

仍在 `tgp_chaos_shattering_effect` 内。用户已经修改的销毁逻辑在本方案中继续保留，不再重复要求修改。

原版在末尾第 660–663 行另有：

```text
scope:old_emperor_temp = {
    force_step_down_landed_titles = yes
}
```

改前：旧天子仍被要求放弃其有领地头衔。因此“未执行 `destroy_title`”不等于“同一天子继续持有 `h_china`”。

改后有两种目标，按用户 mod 的设计选择：

- **只要求朋党继续存在，允许换天子：** 可以保留退位逻辑，但需要 `h_china.holder` 持续存在，且新持有者/换领主过程不清掉朋党标记。不能仅凭头衔定义存在判断这一条件已经满足。
- **要求原天子也继续持有：** 移除上面这块全领地退位调用。它会改变旧天子的退位结果，不只影响朋党，因此不是所有方案都必须删除的代码。

如果希望即便没有天子也保留朋党，使用下一节的 chaos 资格分支；这种情况下受宠、天子互动等其他依赖 holder 的玩法仍需各自处理。

## 4. 条件性修改：允许无天子的 chaos 继续留组

文件：`common/situation/situations/tgp_dynastic_cycle.txt`。

改前，五个 movement 的 `is_character_valid` 最外层都有：

```text
exists = title:h_china.holder
```

**原版已经有保留类别的分支。** 角色存在 `movement_member` 时，会进入匹配 flag 的分支，不再按首次选择逻辑检查其天子封臣/朝贡身份。因此只要 holder 始终存在，且前两节没有清掉标记，独立后的旧成员也有静态留组路径；不必为了独立身份一律重写资格。

只有目标还包括“没有天子也保留旧朋党”时，才把该组现有资格完整放入 `trigger_else`，新增 chaos 分支。以进取派为例，下面两块都是完整 `is_character_valid`，可用于比较；其余组保留各自原有非 chaos 条件，不要把进取派的首次选择 trigger 复制给其他组。

进取派改前：

```text
is_character_valid = {
    exists = title:h_china.holder
    trigger_if = {
        limit = {
            NOR = {
                exists = var:movement_member
                top_participant_group:dynastic_cycle.var:movement_leader ?= root
            }
        }
        OR = {
            is_vassal_or_below_of = title:h_china.holder
            AND = {
                is_tributary_of = title:h_china.holder
                subject_contract_has_flag = celestial_investiture_politics
            }
        }
        should_pick_advancement_movement_trigger = yes
    }
    trigger_else = {
        var:movement_member ?= flag:advancement
    }
}
```

进取派改后：

```text
is_character_valid = {
    trigger_if = {
        limit = {
            scope:situation = {
                situation_current_phase = situation_dynastic_cycle_phase_chaos
            }
        }
        has_variable = movement_member
        var:movement_member = flag:advancement
    }
    trigger_else = {
        exists = title:h_china.holder
        trigger_if = {
            limit = {
                NOR = {
                    exists = var:movement_member
                    top_participant_group:dynastic_cycle.var:movement_leader ?= root
                }
            }
            OR = {
                is_vassal_or_below_of = title:h_china.holder
                AND = {
                    is_tributary_of = title:h_china.holder
                    subject_contract_has_flag = celestial_investiture_politics
                }
            }
            should_pick_advancement_movement_trigger = yes
        }
        trigger_else = {
            var:movement_member ?= flag:advancement
        }
    }
}
```

五组对应标记：

| 参与组 key | chaos 分支的匹配值 |
|---|---|
| `pro_hegemon_movement` | `flag:pro_hegemon` |
| `advancement_movement` | `flag:advancement` |
| `expansion_movement` | `flag:expansion` |
| `conservative_movement` | `flag:conservative` |
| `undecided_movement` | `flag:undecided` |

变化：chaos 阶段的旧成员按原标记留在各组，不受有无天子的这项门槛影响；其他阶段仍用原版资格。它只保留已标记成员，没有定义新成员如何首次选择朋党，通用地域和参与资格也仍然有效。不要把五组都改为 `always = yes`，否则第一个有效组会抢走后面组的角色。

## 5. 删除轮盘/阶段效果中的“解散”参数

文件：`common/situation/situations/tgp_dynastic_cycle.txt`。

位置：`phases → situation_dynastic_cycle_phase_chaos → modifier_sets → dynastic_cycle_government_effects`，当前六处参数在第 1881–1906 行。

以进取派为例，改前：

```text
advancement_movement = {
    parameters = {
        dynastic_cycle_no_movement = yes
    }
}
```

改后：

```text
advancement_movement = {
    parameters = {}
}
```

同样删除 `hegemon_ruler`、`pro_hegemon_movement`、`expansion_movement`、`conservative_movement`、`undecided_movement` 的这项参数，合计六处；其他参数不动。也可以省去修改后完全空的子块。

变化：界面不再由该参数生成“解散”这一项。它的中文文本是 `situation_parameter_dynastic_cycle_no_movement: "#weak 解散#!"`，所以成员重新加入并不会自行让提示消失。删除参数只修正这项显示，不能替代前面的成员保留改动。

阶段长描述还写着摧毁霸权、废黜天子、解散参与组。按实际修改结果同步修正简中和英文的 `situation_dynastic_cycle_phase_chaos_desc`；无需把“解散”全局翻译键改成“未解散”，否则会影响其他仍使用它的情境。

## 6. 放开 GUI 的朋党页，避免两个主体同时显示

文件：`gui/window_tgp_dynastic_cycle.gui`。

只修改三个对应位置的 `visible`，保留各 widget 的其他内容：

| 位置 | 改前 | 改后 |
|---|---|---|
| 第 93 行，`dynastic_cycle_tabs` | `[Not( SituationDynasticCycleWindow.IsInChaosEra )]` | `yes` |
| 第 153 行，`dynastic_cycle_scrollarea` | `[Or( GetVariableSystem.Exists( 'dynastic_cycle' ), SituationDynasticCycleWindow.IsInChaosEra )]` | `[GetVariableSystem.Exists( 'dynastic_cycle' )]` |
| 第 649 行，`movements_scrollarea` | `[And( GetVariableSystem.Exists( 'movements' ), Not( SituationDynasticCycleWindow.IsInChaosEra ))]` | `[GetVariableSystem.Exists( 'movements' )]` |

实际赋值形式分别为：

```text
visible = yes
```

```text
visible = "[GetVariableSystem.Exists( 'dynastic_cycle' )]"
```

```text
visible = "[GetVariableSystem.Exists( 'movements' )]"
```

变化：群雄割据也能点开朋党页；王朝主体与朋党主体由原有页签变量切换。第二处必须一并处理，因为原版在 chaos 时强制显示王朝主体，仅放开朋党页会使两个主体同时可见。

二进制中的 `IsInChaosEra` 直接比较当前阶段是否为 `situation_dynastic_cycle_phase_chaos`，不检查霸权头衔是否保留。这里修改它的 GUI 使用条件即可，不需要修改这个原生函数，也不要把全文件所有 chaos 条件一律删掉。

## 7. 可选：开放切换朋党

文件：`common/decisions/dlc_decisions/tgp/tgp_dynastic_cycle_decisions.txt`。

定义：`situation_dynastic_cycle_choose_movement_decision` 的 `is_shown`。其第 254–258 行改前：

```text
any_character_situation = {
    situation_type = dynastic_cycle
    NOT = { situation_current_phase = situation_dynastic_cycle_phase_chaos }
}
```

改后：

```text
any_character_situation = {
    situation_type = dynastic_cycle
}
```

变化：该决议不再仅因 chaos 阶段而隐藏。保留其玩家限定、参与组身份、成年、冷却等其余规则。只希望原成员不解散时，无需做这一项；受宠、请愿等其他玩法也不会因为本项自动全部开放。

## 理论交付边界

上述“改前”来自当前原版脚本与 GUI，原生阶段判定已静态核对。“改后”是待实施的 mod 修改方案，没有运行游戏验证，也没有声称对用户具体 mod/存档已生效。用户现有 `h_china` 保留实现尚未提供，因此 holder、退位及其他自定义清理需要结合其实现选择。

已有存档若已经清掉 `movement_member`，取消未来清理不会自动找回过去的成员；需要另做一次性恢复，不能用永久反复加入替代。本文没有实施这项恢复，也不把它作为此次理论文档的前置要求。
