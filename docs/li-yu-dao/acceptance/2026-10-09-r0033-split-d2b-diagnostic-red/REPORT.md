# R0033 split-D2b native diagnostic — RED

The R33 source-only overlay split D2b into three intended event continuations: create the title/vassal transaction, change the new title holder, and resolve the transaction. Six diagnostic overlay files were pinned and statically validated; production's 71 files were not changed. The signed R31 B3 save was copied byte-for-byte into a new CK3 1.20.0.4 cold run.

Native cache observations were 45 at D0, 45 after D1 and its save, 45 after D2a and its save, and **45 after selecting the event-20 option intended to create the D2b transaction**. D1 and D2a checkpoint bodies are retained externally with exact SHA-256 in `INDEX.json`. The subsequent `lyd_factory_diag.21` event did not open: querying expected event instance 122 returned an active-event mismatch, and an independent native snapshot at revision 8 showed `active_event: null`. The overlay's intended continuation therefore failed; no R33 holder-change or resolve operation ran. The current native readback does not independently prove that `create_title_and_vassal_change` executed, so this run cannot isolate the original 45→40 loss to a later operation or prove that the transaction scope survived the event boundary.

The first bridge attach was attempted before the campaign finished loading and returned “native campaign has no bound played character”; that client was closed without retry. After the game visibly reached the paused campaign, a new client attached and verified native state. One copied R32 cache request used revision 4 before R33 had advanced past revision 3 and was rejected; a separately named request at the correct revision succeeded. Both failures and their exact request/result bytes are retained.

The frozen normal-exit source inventory was made while CK3 was loading. The game later changed `pdx_settings.txt`, so the official normal-exit context tool refused with “actual source bytes changed”. On the exact observed CK3 HWND, the OS window-close semantic opened CK3's own exit confirmation. The original 1920×1080 screenshot was reviewed, the pointer move verified the target region and foreground HWND, and `desktop_coordinate_map.py` clicked “退出到桌面” with a fresh receipt. The original CK3 process handle reported exit code 0; the SDK clients closed. A new post-exit desktop frame was visually reviewed and still showed Steam “离线模式”. The autosave_exit body is retained externally but is not treated as a valid continuation seed or as formal acceptance.

This is diagnostic RED. It grants **no** Phase I I3b, successful T cold reload, C3, I4, or whole-mod GREEN credit. Next run must determine why the event boundary loses the continuation (including whether the guarded inner effect ran and whether its saved change scope was available), then re-run from the signed B3 seed with a newly frozen profile and source inventory **after full campaign load**. Do not reuse this run's partial state as a baseline.

`raw-evidence.zip` preserves the exact diagnostic source, manifests, SDK requests/responses/receipts, screenshots, logs, screen lease, and offline reviews. `ARCHIVE-VALIDATION.actual.json` records extracted-byte verification. Save bodies remain in the outside runtime and are bound by size and SHA-256 in `INDEX.json`.
