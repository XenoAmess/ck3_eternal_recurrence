# C3 shared factory realm-law protection candidate

This source-only experiment is motivated by R14 round 3 B4 on fixed HEAD19:
new owned temporal HoF title 18373 was real, but five protected political title
succession ASTs and the actor realm-law projection changed. The original 80/87
protection RED is preserved. A successful native head receipt is not a whole
political protection pass.

The shared factory records only whether same_faith_succession_law already
exists, before native creation. It resets a saved scope value to 0 on every
authorized invocation and sets it to 1 only when that law already exists.
After native title setup, it removes this one law only if the snapshot exists,
equals 0, and the law now exists. An absent snapshot rejects cleanup. It uses
no persistent character flags, no realm-law list replay, no inherited heir IDs,
no title holder rewrite, and no rollback of native state. A preexisting law is
preserved. Both shared templates remain identical; gen_leadership generates
the single changed production file, and all other 11 leadership outputs remain
byte-for-byte equal to HEAD19.

Current stock 00_decisions_effects.txt:1681-1697 demonstrates character-scope
has_realm_law plus remove_realm_law. Stock 00_religion_effects.txt:347-380 has a
separate explicit same-faith-law add that LYD omits. Actual 1.20.0.3 EXE static
disassembly shows set_religious_head_title enters native realm-law maintenance
after writing the Faith head title and resolving the new holder. This explains
why omitting the stock explicit add does not guarantee protection. It does not
prove a later maintenance pass or reload will leave the law absent.
