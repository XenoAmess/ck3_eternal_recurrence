# 0.1.2 Alpha：建立宗主与 36 信条玩法源码候选

用户要求修复原版儒家中建立宗主的入口，并让每项 doctrine 更有特色、更强。本候选已实现，尚未发布；当前 Steam 仍为 0.1.1 Alpha 内部测试。

原版 `confucian_faith` 中采用新增礼仪的合格玩家可以发起真实世俗宗主议案。经学、道学及全部实际礼仪进入完整名单；每个活跃派分别提名、授权和签署，所有玩家另行同意。原 Faith、主礼仪与信条保持原值，宗主制度的全信仰影响在条款中明确显示。创建决议的具体资格移入可见条件，不能发起时可以查看原因。操作步骤见 [产品说明](../../../../mod_li_yu_dao/README.md)。

新宗教头衔先检查专用继承法例，再更改已获授权的宗主教义、绑定头衔，最后执行一次授予事务。授予前失败会拒绝或恢复本次改动。这个顺序修复不能代替原生验证：空头衔法例能否持久生效，以及原政治头衔、候选继承人与玩家继承人的保护，仍待本轮实机证明。历史 B4 失败未追认为通过。

36 项常驻与个人效果已按学派主题重做，保留稳定 ID 和原核心组合；另有 36 个专属行动、52 个真实选择分支。每条行动都要求实际核心或已选个人信条、资源及情境，确认时再次检查，具有个人冷却；AI 不执行。T33 使用真实状态保存“问学→践行”两阶段。设计和完整数字见 [常驻效果](../../2026-10-12-36-tenet-strength-and-native-specialties.md)与[主动玩法](../../../../mod_li_yu_dao/docs/tenet-active-practices.md)。

内容/运行生成核对、L0 静态检查、可复现构建、打包负例和受影响机构/诊断/原版接入测试已通过。最初将所有产品测试放进一个解释器，暴露旧契约、旧夹具和同名模块污染；原失败保存，修正后相关模块分别运行。精确命令、实际返回码、输出 SHA、分支回执及源码输入在 [VALIDATION.actual.json](VALIDATION.actual.json)。这份记录只授予源码与离线检查信用，不授予新玩法、完整宗主流程或政治继承保护的实机信用。

并行工作包括：宗主流程及政治保护顺序、36 常驻效果、36 主动玩法、旧反馈 adapter 数值同步，以及原公开版本的 Alpha 文案/Notes 收尾。CK3 现场保持单机排他。未上传本轮候选，未运行新的 36 项业务矩阵；下一门槛是实际功能验证和后续发布。
