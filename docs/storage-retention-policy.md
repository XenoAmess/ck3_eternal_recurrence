# 全执行机器通用存储策略

版本 **1.0.0**，2026-10-10 生效。共同参数以 [storage-retention-policy.json](storage-retention-policy.json) 为准；修改默认值必须同步本文并增加版本。适用于本项目所有执行机器、代理、开发、构建、实机、宣传制作和交付工作包，不依赖 Windows、某个盘符、机器名称或固定目录。

用户要求资料具有时效性，过时的存档和原始证据也须清理，尤其大文件。该要求覆盖旧指南和交接中的默认永久保留条款。**失败记录不等于永久占盘许可，文件原始也不等于永不过期。** 当前确有用途的原件采用明确、有期限的保护；不通过无限保留一切来维护历史真实性。

本版交付的是所有执行者必须遵守的策略与机器可读参数。统一自动 GC、自动空间预留、跨机内容对象管理尚未实现，也没有自动部署到远端机器。实现前，执行者必须落实同样的判定、空间检查与精确操作并留下小型回执，不能把“没有自动工具”作为省略检查的理由。

## 1. 范围与机器适配

机器本地配置只记录 `machine_id`、operator、项目获准根目录映射、所在卷、系统增长预留、配额例外及策略版本。配置与完整本机库存留在机器外置工作目录，不把盘符和隐私路径变成全项目合同；仓库记录策略版本、必要结果与引用即可。

逻辑内容或资产组使用稳定 `asset_id`，每个机器上的实际副本另有 `replica_id`，位置使用 `machine_id + root_id + relative_path`；同一资产的某个副本删除不能误标其他副本已删除。路径大小写与链接语义按实际文件系统处理；比较前解析真实路径并确认仍在获准根内。UNC、网络卷、可移动盘和云目录必须单独确认实际可写、可读与容量；无法可靠核验时阻止对应重型写入或最后副本回收。

本策略授权处理执行者拥有且属于本项目的过期资产。个人文件、其他项目/用户任务、安装中的软件、游戏本体、当前依赖、未消费下载和系统文件不因名字像缓存就纳入。涉及其他所有者的资产先取得其任务级授权；不擅自接管失联任务或删除目录树。

Git 跟踪的源码、正式发布与审计记录按正常内容维护评估，不进入本机通用逐文件删除器；不得为腾空间重写已发布历史、强推或手删 `.git`。这不授权继续向 Git 提交大原件、全量库存或重复压缩包。

## 2. 分类、默认期限与保护

统一用 UTC，期限从所属任务闭场与最后一次**明确实际使用**的较晚时点起算。尚未闭场的任务不能伪造结束时间。访问时间、扫描、哈希、复制到冷目录或续写审计不会自动刷新“实际使用”。缓存以明确使用记录为准；只有 mtime 时先作候选线索，核实用途后再回收。

| 类别 | 内容 | 默认期限 |
| --- | --- | --- |
| `derived` | 完整文本导出、抽帧、解包副本、可重建分析和中间编码 | 48 小时 |
| `cache` | 可重下的软件缓存、已知用途缓存 | 7 天 |
| `build` | 已闭场的构建中间物、冻结源码副本、旧执行树 | 14 天 |
| `checkpoint` | 存档、profile、阶段 checkpoint、测试数据副本 | 14 天 |
| `raw_evidence` | 原始 trace、日志流、截图、失败现场及不可重建采样 | 30 天 |
| `delivered_media` | 已完成并验证交付的视频源媒体和配套素材 | 30 天 |
| `record` | 结论、精简出处、发布记录、最终交付物及小型删除回执 | 180 天复核归纳，不自动破坏交付或发布合同 |

期限是回收资格判断的默认值，不保证文件一定留满，也不允许到点无条件删。已有精确摘要、可从保留输入重建的派生物，或已被实际核验的后继替代的对象，可以提前回收。超过 **1 GiB** 的对象在 7 天内提前复核；容量不足时优先评估最大可重建派生物与重复副本。

混合资产组须分级，不能为了方便把整个 run 都标成最长保留。原片、生成字幕、正式交付、可重下素材的用途不同。游戏/驱动着色器缓存须考虑版本兼容和重新编译成本；不能作为 HTTP 缓存按名字一并清掉，也不能无限复制到每个新场次。

保护只针对必要对象：当前基线、实际活跃输入、尚未解决问题的最小关键证据、尚未完成交付的必需素材。每份保护必须有 owner、具体用途/引用方、下一步使用、截止时间，最长 **7 天**，**禁止自动续期**，未答复不等于续期。续期须重新证明用途；连续 4 次续期必须收缩到最小集合、确定替代/恢复方案或报告容量需求，不能批量给全部旧场次续期。到期未处置的巨型资产阻止同工作包继续扩张，不能以“尚有引用”绕过容量限制。

任务“未结束”本身不能无限保护其所有输出。失去新鲜租约的任务先核状态、进程与恢复需要；无法确认归属的资产 48 小时内完成分类和责任认领，未认领时停止同一工作包继续大规模生产，不将不确定性变成静默无限增长。

任何删除必须同时满足：已闭场/明确废弃、无活跃进程或写入、无当前用途引用、无有效保护、期限已到或有提前回收理由、所属类别和路径在授权范围、已完成最小知识提炼及所需替代验证。读到未知状态则停在待处理项，不能标为已释放。

“当前用途引用”指后续任务真正消费的输入、当前恢复基线或待解决问题的必要对象。旧报告中历史出现的路径、已经失效的任务和目录存在本身，不形成永续引用。相反，删除当前需要的唯一存档后再称“有哈希就够”也不成立。

## 3. 保存什么、怎样减少重复

每个尚未解决的问题默认保留一套最有代表性的失败原件与当前必要基线；确需多个对照时逐个说明差异。旧版本、旧 PID、旧 attempt 不因不同名称自动获得保留资格。失败结论、错误原因、边界和关键出处先提炼，再淘汰被替代或失去用途的全量现场。

对不可变大输入优先采用单份内容对象加引用。只有已核验内容相同、没有未来写入且链接语义可靠的对象才能去重；同大小/文件名不是相同证明。游戏会写的 profile、存档或可变 Steam 缓存不能与历史原件建立可写共享。同机硬链接按卷和文件身份识别共享占用；跨机同 SHA 的副本仍分别占盘，不因内容相同就合并容量数字。

最后一份本地原件若依赖远端/其他机器副本继续保留，必须验证对应精确对象已经实际可读、大小和哈希吻合并有明确保管方与到期时间；上传 ACK、同步图标、路径存在和旧回执均不够。网络不可达时阻止这个动作。冷存储也记期限与配额，迁移不重置寿命，不把无限膨胀转移给另一台机器。

原件回收后保留小型可用性记录：`deleted` 或 `external_verified`、时间、原因、原身份、替代摘要/来源、执行结果。旧 GREEN/RED/UNKNOWN 不改写；旧报告可保留历史路径，但须能明确查到该对象现在是否可读。哈希能证明历史身份，不能替代被删原件的现有可用性。

## 4. 按卷预算，先防满再回收

每个输出卷分别检查，不能把另一盘或另一机器的空闲算进来。实际分配量可测则记录；只能得到逻辑量时明确标注，不能据逻辑大小承诺物理回收量。硬链接、压缩、sparse、云占位和并发写入均须考虑。

写入前需满足：

```text
可用空间 >= 本次预计新增峰值
          + 其他任务尚未消费的空间预留
          + 本卷系统增长预留
          + 安全余量

安全余量 = max(2 GiB, min(20 GiB, 本卷容量 × 5%))
默认项目配额 = min(100 GiB, 本卷容量 × 10%)
```

2 GiB 以下且无法满足安全余量的小卷不承接重型任务。配额针对同一卷上的本项目全部执行树、运行、素材及缓存，不能按代理各领一份。已有超配额历史先登记并停止扩大，按用途缩减；必要超配额由 owner 写理由、明确字节上限和截止复核日期，最长 7 天，到期失效，继续使用须重新判断，不能无限沿用旧例外。

本次峰值需包括源快照、profile、allocator 输入副本、临时构建、ZIP、完整导出、日志及复制中暂时双份的空间。未验证压缩收益不得抵扣预算。Windows 的分页文件或其他平台的交换/系统写入增长由机器配置明确预留，不能忽略，也不能跨机套用某次 7 GB 的历史观测。卷总容量、可用空间、本次峰值、其他未消费预留、系统预留、当前项目占用或生效配额任一未知时，重型写入为 **BLOCKED**；null、缺台账和未扫区域不能当成 0。

并发任务不能各自读取同一 free 后全部通过。必须由卷的协调者在同一个临界区核验并登记任务、卷、预留字节、owner 与到期；共享卷必须覆盖所有机器的写入方，共用一份协调/台账，不能各自按本机批准。无法获知其他写入方的预留时为 **BLOCKED**。释放或转换预留要与实际剩余写入对应，不重复计入已经占盘的字节。统一预留器尚未实现时，利用现有任务总线让指定协调者串行处理重型写入准入和登记；不可假称普通只读容量快照完成了原子预留。租约过期不直接删除其产物，先核活跃写入再释放预留。

预算或配额不满足时：暂停新重型写入，依次处理可重建派生物、已验证重复物、被替代存档/构建、失去用途的原件；必要时缩小采集、调整执行地点或报告容量缺口。不能继续生成直到磁盘写满，也不能静默降低产品验收要求。

## 5. 所有机器的执行流程

1. **任务开始**：读取仓库策略版本，绑定本机根目录/卷/owner，检查已到期资产、有效保护、配额与可用空间。复用小型台账，不重复全盘扫描或全文件正文哈希。
2. **重型写入前**：确认路径归属、估算峰值、系统预留和其他任务预留；在本机协调临界区完成准入。建资产组时即记录类别、期限与用途，不能结束后才猜哪些可以删。
3. **闭场**：准确关闭进程及租约，保存结论和必要出处，标明原始数据是否完整，登记最终大小与期限。主动处理已可重建的巨型导出，更新当前恢复基线，失效保护及时解除。
4. **巡检**：每日最多一次常规到期评估；低空间或重大产物完成时可触发增量评估。未访问的其他机器标为未执行，不替它出清理成功回执。
5. **精确回收**：生成不可混淆的候选清单及理由，执行前复核当前状态。解析路径、拒绝链接越界、核文件身份和占用；仅删除清单内精确文件，不进行宽泛递归删树。变化/占用/权限失败保留逐项失败，不强抢权限或把计划算完成。进程占用与身份保护按操作系统正确实现；没有可靠方法时不执行该对象。
6. **读回**：确认实际删除/迁移结果，分别记录逻辑候选量、可测分配量及前后卷空闲。并发变化不得全部归因于清理；更新原件可用性与保护/预留。无需重跑与清理无关的业务矩阵。

已满足本策略的项目过期资产不再因旧“永久保留”措辞重复询问保留许可。仍有归属、当前用途或具体授权冲突时，只暂停冲突对象并报告依据，其他候选继续处理；本策略不授权用户范围之外的删除。

## 6. 台账最小合同与审计自身限额

按资产组和副本登记，字段见 JSON 的 `asset_group_required_fields`。组可引用既有 manifest；精确删除计划在执行时展开为文件，禁止为每次审计再复制全部大清单。保护另外记录批准者/执行者、理由、截止和续期次数；时间必须带 UTC，大小以 bytes 为单位，unknown 保留 null。

过期计划与实际删除回执必须分开。回执只保留策略版本、机器/任务、时间、计数、结果、原清单哈希及必要出处；精简回执 180 天复核，大型逐文件 ledger 压缩保留 30 天，之后归纳进摘要，重要争议未解决时按同样的 7 天保护机制处理。普通巡检只写变化，不生成新的完整库存副本。过时的策略审计材料自身也适用期限。

常规单次盘点默认最多 120 秒、100,000 条 metadata、1 MiB 报告，精确回收每批最多 1,000 文件。达到上限即保存游标和小型摘要，下次增量继续，不把未扫描区域标为 0；确需扩大时先记录范围、理由与输出预算。不要为了节省磁盘先生成新的巨型库存、全量导出或 hash 副本。

## 7. 一致性检查与边界案例

策略必须在各机器得到相同语义结果：

- 旧失败场次已被明确后继替代、无用途引用且到期：保存精简失败结论后可回收 raw 和存档。
- 旧存档虽大但正被当前验收基线使用：只保护必要对象并设 7 天复核，不能删唯一基线，也不能顺带保护全部旧场。
- 10 GB 全文导出已有精确摘要及可读 ETL：可提前回收全文，原 ETL 自己仍有期限，不永久豁免。
- 云端只有上传成功 ACK：不能据此删除仍须保留的最后本地副本；若原件本身已到期无需再保留，则按回收条件评估，不为清理而强制制造云副本。
- 机器盘符不同或卷容量很小：只更换根映射及容量输入，生命周期与安全公式不变。
- 两任务并发申请写入：先计入现有预留，后申请者空间不足则阻止；不能同时消费一份 free。
- 当前目录存在无法确认归属的巨型 partial：48 小时内完成归类并停止同工作包继续膨胀，不按名字立即删除，也不无限期豁免。

用户明确要求保留、正在进行的交付与产品正式发布合同构成具体用途约束，也须记录复核时间。历史文档中的旧永久约定不构成新例外。策略可以按实际恢复与容量效果调整，但所有机器从仓库接受同一版本，不私自形成不同默认规则。

本机问题样本及当前实现缺口见 [2026-10-10 只读审计](maintenance/storage-retention-2026-10-10.md)。样本不参与其他机器的容量判定。
