## Minimal semantics-preserving refactor candidate

Do this in a disposable branch/fixture first; do not hand-edit the generated
file.

1. Add two parameterized scripted triggers in a generated file under
   `common/scripted_triggers/` (for example
   `zg361_workforce_endgame_generated_triggers.txt`):
   `zg361_we_m360_external_collective_route_a_precheck_trigger` and
   `zg361_we_m360_external_collective_route_b_precheck_trigger`.
   Move the exact output of `_collective_external_checks(1/2)` into those
   definitions. Replace every `$TICKET_*$` use inside the moved body with
   trigger parameters (`TICKET_OWNER`, `TICKET_SUBJECT`, `TICKET_CYCLE`,
   `TICKET_CASE`) and pass those four values at every call site. Keep route A/B
   as separate fixed definitions: this avoids relying on dynamic identifier
   concatenation (`forced` versus `exception`) while retaining every check and
   every symbol.
2. In `render_collective_producer`, replace the two inline blocks at lines
   5,766/5,780 with the corresponding trigger call. In `resource_checks`, when
   `mid == 360` and `choice in (1, 2)`, return the corresponding trigger call
   instead of expanding `_collective_external_checks`.
3. Extract the exact `central_checks` body into one parameterized scripted
   trigger (for example
   `zg361_we_m360_central_preflight_trigger`). Replace the owner-scope inline
   body in both route materializers with a call passing the four ticket
   parameters. The preceding quota prelude remains unchanged, so the
   `expected_central_m360_total_quota` temporary value is still available.

This leaves the same route branches, scope transitions, variable names,
identity-slot checks, and CK3 operation ordering. Only duplicate AST text is
deduplicated. It also avoids a speculative generic trigger that synthesizes
variable names from a `KIND` parameter; such dynamic-name support must be
proven separately before considering it.

Expected effect payload after the candidate is approximately 3.60 MB; the
three helper definitions add approximately 0.31 MB in the scripted-trigger
file, for an estimated total of roughly 3.91 MB versus 4.64 MB today. Exact
bytes depend on call formatting and generated headers. The important invariant
is that the 324 original effect symbols remain unchanged; the helper trigger
symbols are additive and namespaced.

The same estimate lowers the four pathological effect blocks to approximately
171 KB, 170 KB, 121 KB, and 113 KB respectively (before exact formatting),
instead of 478/470/336/319 KB. The helper definitions themselves stay near
108/104/94 KB. This reduces both total duplicated AST and the maximum
single-definition size; a file-only split would not provide either property.
