# CK3 1.20.0.2：Sway current completion Python transport

本独立增量消费原生 Scheme storage 中一个完整 SchemeID 对应的当前行，覆盖 native manager
purge 前仍保留的 terminated 实例。原生研究及语义依据见
[completion source](ck3-1.20.0.2-sway-completion.md)、
[phase/roll input](ck3-1.20.0.2-sway-completion-phase.md) 和
[cancel/invalidation source](ck3-1.20.0.2-sway-completion-cancel.md)。既有 active query、
启动 ACK、独立启动 receipt 和宗教 transport 均保持冻结。

## 方法及真实协议

新增模块：
`ck3_autonomous_player/src/xar_autoplayer/bridge/active_scheme_sway_completion_private_transport.py`。

方法：
`query_active_scheme_sway_completion_private_v1(driver, *, expected_revision, target_character_id, scheme_instance_id, timeout_seconds=30.0)`。
复用既有 G2 read-only seam，显式开关为
`allow_private_active_scheme_sway_completion_query`，默认为关闭。

协调者接通的生产入口为
`NativeHeadlessGameplayDriver.query_active_scheme_sway_completion_private_v1`，MCP 为
`ck3_query_active_scheme_sway_completion_private_v1`，CLI 开关为
`--private-active-scheme-sway-completion-query`。默认关闭时 discovery 不显示该工具；显式启用后
工具带 `readOnlyHint=true`。本叶不修改上述共享文件。

native selector 为 `query-sway-completion-v1-private`。请求的 revision 取当前 paused snapshot
对应的 native revision，actor 取当前玩家，target 与 SchemeID 由调用者明确指定。
target/actor 是有效且不同的 positive int32；SchemeID 是 full uint32 reference，合法 0 保留，
`FFFFFFFF` 是 native invalid marker。完整 generation 高位不会被裁掉，也不从数组下标重造 ID。

实际 `command_result.result.sway_completion` 使用 schema `xar.ck3.sway_completion.v1`，
outer backend 为 `native-headless`，outer status 为 `available` 或 `unavailable`。
exact version/SHA/adapter、revision/date 和请求身份在 inner DTO 中。
Python 绑定 CK3 `1.20.0.2`、EXE SHA-256
`AE1BA6FF060BA603842F6F4A2DED0AF4B7D3666B3DD271F75FB01B0DA8E81B2D`
及实际 snapshot hello，再按 source schema 保留全部 35 个字段。

## 观测字段的含义

| 原生字段 | Python 消费含义 |
| --- | --- |
| `instance_source_observed` | native storage source 本次是否读取到 |
| `instance_present` / `storage_slot_reused` | 该 exact full-ID row 是否仍保留，或其 slot 已被其他 full ID 复用 |
| `exact_instance_join_ready` | 原生 type/target/full ID 等当前行 join 是否成功 |
| `native_owner_raw` | nullable uint32；`FFFFFFFF` 原样表示原生终止路径清空的 owner |
| `native_status_raw` / `native_status_key` | nullable int32 与对应原生枚举名；0=`continue`，1=`invalidated`，2=`invalid` |
| `native_terminal_state_observed` | 原生 provider 对当前 retained row 的 terminal fact，原样返回 |
| `native_success_chance_raw` | nullable signed int64，实际 getter 的当前 phase roll input |
| `native_success_chance_scale` / `native_success_chance_unit` | 100000 / `percent`；100% 原生值为 10000000 |
| `terminal_cause_observed` / `terminal_cause` | 实际来源是否区分 cause；首 current-row provider 保留 `false` / `unknown` |
| `current_instance_retention` | `until_native_manager_purge`；不是持久历史档案 |

状态 1 由原生取消与 authored end 路径共同使用，所以它能证明 terminated row，却不能独立确定
结束原因。Python 不把 `invalidated` 翻译成已知取消，不把 nullable chance 改为 0，也不根据行缺失、
slot 复用、进度归零、opinion 100、当前成功率或看不见 outcome event 构造 terminal。
hidden phase result/history 和精确 cause 留给各自原生来源增量。

本包仅允许 source/mock/file 工作，禁止 CK3 process、pipe、UI、Steam 和 live profile 访问。
七个 actual native full `command_result` fixture 已逐字节复制到
`ck3_autonomous_player/native_bridge/research/fixtures/ck3_12002_sway_completion/`，保留 source/run/wire

dispatch 未包含在本次原生 fixture 中。原生 Debug `/Od`、Release `/O2 /W4 /WX` 同样输出由 native
owner 取得，Python 直接复用，不重复编译或执行矩阵。

core-unavailable 实际帧保留原始 actor/target/full ID，并在 Python 中成功消费。
