## Why this is not yet a production resolver

`D0/DC` belongs to a qualified **window receiver**, not the global FocusDB.
The getter reads no visibility flag, age, child ID, or player state. That
does not prove that the collection is initialized, current, complete, or
available when the window is closed. Its population and lifetime producer
remains unknown. Current child-query bindings supply module/actor/frame;
they supply no admitted window receiver or owner-to-child binding.

Consequently this package adds no native reader, guessed global offset,
window invocation, or synthetic production qualification. Existing final
validator, afterstate, unavailable result and ordinary continuation stay
unchanged. Native29, current SDK and Service are untouched.

The smallest next source work is the actual producer of this window's
`D0/DC` collection, or its independent education-definition registry lookup.
It must prove how the five education keys become canonical definition
pointers, and whether that lookup can run without opening or relying on a
UI instance. A future reader must match the returned stable key to the
requested education key, reject fallback, retain exact-build admission and
same-frame lifetime, then use the existing original validator. Five GUI
slots alone do not authorize a five-pointer global layout.

If that producer closes, meaningful memory fixtures should place adult
lifestyle rows in the old F08 span while education definitions live in the
proved independent domain, then cover exact target resolution, wrong key,
fallback, unreadable or changing owner/collection, and mismatched lifetime.
They must not invent a window receiver contract or supply live focus-write
credit. No such implementation or test was run here because this essential
