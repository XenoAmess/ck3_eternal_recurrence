# 共享圣地：供奉、替换、取出、放弃的成本与归属

机器 `4-8e1c2f1861`；整理时间与逐源核验时间见同目录 [script-costs.evidence.json](script-costs.evidence.json)。这是 CK3 1.20.0.4 固定原版脚本和既有有限原生源码包的离线研究，EXE 来源绑定 SHA-256 为 `98702f88a547cde2eaf29a85f93b85f68ee4cf8148336a4f7afaeb75319dd518`，本次没有重新扫描 EXE、操作游戏或提交动作。原文件完整 SHA、精确行号、小型摘录和 R7/R8 来源均在 JSON；未把脚本预测当作实机结果。

约定：A 为执行角色，F=A.faith，S 为圣地，H 为圣地县持有者，N 为新供奉物，O 为原槽位旧物，`R(X,f)` 为原版 `is_holy_relic_for=f` 的实际判定。认可必须按当前信仰原生求值，不能只靠名称、动态圣化列表或宗教大类推断。

各处 `R` 表示该处的实际求值；没有证明深层脚本的 RNG 纯度，不能缓存一次认可后替代所有后续调用。下述条件用于解释原文和规划输入，动作提交仍绑定原生 preview。

## 归属与返还：先区分三个路径

| 操作 | 新物与旧物具体去向 | 条件及边界 |
| --- | --- | --- |
| 空槽供奉 N | N 交给圣地 S，退出 A 的角色拥有库存 | 原生命令把角色 owner 与 holy-site owner 分开设置；供奉后不是 A 私有，也不成为 F 的一份私有副本。R7 已实测这条路径。 |
| 在有物槽供奉 N、替换 O | N 给 S；O 交给本次执行者 A | 既有完整 receiver 的 `29AAFFF -> 252FDD0(O,A)`；A 必须成功解析为有效角色。接收者不是原捐赠者、H 或宗教领袖。无有效 A 时本条交付分支跳过，不能自行补一个返还对象。替换会触发 N 的供奉与 O 的移除两段 on_action；R7 没有实测替换。 |
| 显式取出 O | O 从 S 交给本次执行者 A | `29ABAD9 -> 252FDD0(O,A)`。无有效 A 的后备分支检查实际装备成员后调用 `22E5310` 移出装备库存，没有“给 H/原捐赠者”分支。本项目 typed action 仍须事先绑定有效玩家；后备分支不是可调用策略。R7 已实测正常有效 A。 |
| 放弃 F 对 S 的关联 | **有其他关联信仰：不执行退物。没有任何其他关联信仰且 H 存在：全部已供奉物给 H，然后移除 F 关联。H 不存在：退物分支跳过。** | S13:374–396 的明确先后顺序与两个 AND 条件。H 是否等于 A、是否同信仰、是否认可圣物，不在该退物条件内。H=A 时才恰好回自己；没有返还原捐赠者或宗教领袖的后续优先分支。R8 只实测有其他关联信仰且空槽，未测最后信仰或非空退物。 |

替换/显式取出是原生专门圣物命令；放弃决议先执行的是通用 `set_owner`。S14:322–325 明确专门移除 on_action 不由通用库存 effects 触发。不能把放弃造成的退物自动计成一次显式取出、再套用其虔诚/奉献经验损失。通用 owner 变化仍有 S14:1–29 的事件与宣称处理，不能进一步宣称放弃退物完全没有别的事件风险。

原生归属证据复用 `permission-candidate-a01/source-guard/{enshrine,remove}-receiver-complete.asm`；完整文件与所引行的 SHA 见 JSON。本次只读既有包，未建立新的原生行为资格。

## 供奉的条件不能按注释反写

S14:138–164 的真实分支是：**当 O 存在、O 被 F 认可且 `O.rarity_level >= N.rarity_level`，把 `replacing_with_better_artifact` 设为 `no`；否则设为 `yes`。随后只有 N 被 F 认可且该值为 `no` 才进入下面的虔诚与正面意见段。** 变量名和“不要从差/等物获利”的注释不能代替这一比较方向。

在上述分支内，A 的 `add_piety` 为 `B(N)-B(O)`；原版四档 B 为普通 50、精制 100、名作 250、卓越 500（S14:167–243；S15:1132–1157）。等档是 0，降档是负数；升级不进入这段。这里写的是 `add_piety`，不是移除段使用的 `add_piety_and_experience`；不能据此许诺供奉会增长奉献等级经验。无旧物的脚本保留原文 `scope:replacing ?=`，本研究不靠臆测可空 scope 语义为所有空槽创造奖励；R7 的具体空槽供奉钱包实测没有变化。

同一分支内还会使以下角色对 A 获得 `enshrined_holy_relic_at_holy_site`，即 **+15，10 年，逐渐衰减**（S14:245–295；S16:117–120）：

- A 的 zealot 立场直属封臣，且 N 被该封臣的信仰认可；这里没有额外要求封臣信仰等于 F。
- A 的各级领主，且 `ai_zeal>=50` 或有 devoted/zealous 特质，并且 N 被其信仰认可。
- F 的宗教领袖存在、不是 A，并且 N 被其信仰认可。

它们是具体角色对 A 的意见修正，不是一个无条件的“所有同宗角色/信仰好感 +15”。成就分支 S14:297–318 另行判断，不能当作资源回报。

## 取出与替换的负担

O 的移除回调把同名值设为 `no` 的条件是 **`R(O,F)` 且（没有 N，或 `N.rarity_level < O.rarity_level`）**；否则为 `yes`（S14:333–353）。注意这里比较方向与供奉回调的 `>=` 并不相同，不能只读变量名称。

当 `R(O,F)` 且值为 `no`，**A** 承担 `add_piety_and_experience=-B(O)`：普通 -50、精制 -100、名作 -250、卓越 -500（S14:385–398）。这是虔诚及奉献经验的脚本操作，不能只把钱包损失当作全部代价。若是降档替换，N 的供奉回调还可能另外执行上一节的 `add_piety=B(N)-B(O)`；规划器必须保留两段计算并读原生总 preview，不能只计算新旧稀有度差。

这一路径内，以下角色对 A 获得 **-20，10 年，逐渐衰减** 的 `removed_holy_relic_from_holy_site`（S14:401–459；S16:111–115）：同 F 的 zealot 和 minority 立场直属封臣；A 有领主时，同 F 的领主直属 zealot 封臣，以及满足上述宗教热忱/特质条件、且认可 O 的各级领主。逐个循环可能覆盖不同人群，不能把展示行数当作已实测人数或统一净意见。

另有独立的宗教领袖段：当移除值为 `no`，遍历 **S 的各关联信仰**，要求该信仰 `num_county_followers>0`，宗教领袖存在、不是 A、且其信仰认可 O，才给予该领袖对 A 的同一 -20 修正（S14:355–383）。它可能跨信仰，也不是“每个关联信仰必有损失”。

后续 `else_if` **没有 `limit`**（S14:462–522），不只对应注释声称的“不是你信仰的圣物”。前一个联合条件不成立就可落入这里，包含认可 O 但等档/升级替换的情况。它展示夺回圣物 CB 提示，并检查 A 的封臣、有领主时的领主直属封臣与各级领主：须认可 O，且（其信仰不同于 F，或移除值为 `no`），才对 A 加 -20。这里没有 zealot/minority 限制。**等档/升级避免前述本信仰虔诚及经验扣除，不等于免除跨信仰意见与旧物转为角色私有后的风险。**

两段 on_action 本身没有声明金币扣款或一个无条件的按钮虔诚费用。原生 effect preview 与当前许可仍是动作前必须读取的最终输入。

## CB：提示不等于已经获得可宣战争议

S14:465–467 是 `custom_tooltip`，没有直接授予 CB 的 effect。须再检查 `reclaim_relic_artifact_war`（X01:342–427）和它调用的 trigger（X02:2223–2248）。常规圣物分支要求：圣物被攻击者信仰认可、**不被防守者信仰认可**、没有 `artifact_prevent_transfer`；双方信仰不同。攻击者不能是 landless adventurer；AI 还要 `ai_zeal>=100` 且至少公爵，玩家不受这两个 AI 条件约束。AI 检查防守者自有物；玩家还可检查防守者麾下异于攻击者信仰的封臣所持物。战争系统的一般宣战资格仍须另外读取。

因此，多信仰共同认可 O 时，不能从“取出触发 CB 提示”推断其中任意信仰立即有这个常规 CB：若防守者也认可 O，常规 trigger 的 NOT 条件就失败。伊比利亚斗争圣物另有分支，不能用常规结论覆盖。实际战争胜利会把符合 trigger 的物交攻击者（X01:450–510），不是自动返还某圣地或原捐赠者；本研究没有宣战/CB 实测。

## 放弃关联有自己的价格，不是取出按钮

S13:337–371 要求当前可管理信仰圣地、S 属于 F、**S 对 F 不是 eminent**、F 的圣地数严格大于其 religion 的下限。A 支付 1000 虔诚；若 F 的 `free_holy_site_actions>=1`，费用乘 0，且执行后消耗 F 的一次免费 action（X05:1990–1998；X06:1286–1293）。决议基础冷却 5 年，有免费 action 时冷却为 0（X07:14–28）。不能把这些免费次数/冷却应用到供奉或取出按钮。

若 H 存在且 H!=A，H 对 A 获得 **-50，10 年，逐渐衰减** 的 `holy_site_demoted_county_holder_opinion`（S13:398–408；X03:11–15），不要求这是最后一个关联信仰，也不要求圣地有物。A 还得到 10 年 `holy_site_demoted_modifier`：`zealot_same_faith_opinion=-20`、`parochial_same_faith_opinion=-20`（S13:410–413；X04:12–16）。本决议费用写 `cost.piety`，没有单独写 `add_piety_and_experience`；奉献经验实际变化本次未测。

## 给游玩智能体的决策规则

1. 先读当前版本、玩家/信仰、S 的关联信仰、县主及其信仰、实际 slots、owned refs、角色 owner/holy-site owner。持有县/最高领主/教区统治者的脚本权限，与自身信仰关联、角色拥有和装备成员是不同条件（S02:6–26、52–64），都要保留原生许可。
2. 优先比较自有候选放入空槽，与替换后的 **S 当前有效稀有度/Active 和受益对象**。共享的是同一个 S 和同一件圣物；“关联同一圣地”不保证每个信仰都认可该物或得到同种效果。不要为激活另一个空圣地，先盲目取走 Baghdad 的最后一件有效物。
3. 替换有实际价值：在兼容槽有限时，把较高有效稀有度的物放到槽内，旧物回到执行者供再分配；相较先取出再放入，可能避免一次“没有 replacement”的本信仰经验损失。是否值得取决于两物对县主/有关信仰的原生认可和两个 on_action 的总 preview，不能只比较 rarity 数字。
4. 动作前读取有效目标槽、实际替换物、当前按钮 predicate 与完整 effect preview；绑定 revision、player、faith、site、artifact、slot/replacing 和 preview SHA 后只提交一次。ACK 只表示受理，后验另读 owner、owned refs、slots、当前值与缓存值，以及实际钱包；经验、意见、CB、受益属性若没有专门读回就保持未验。
5. 放弃前枚举其余关联信仰及 H。共享情况下，放弃不会按上述脚本把物退给自己；最后信仰情况下，退物接收者是 H。不能用放弃冒充一个“无移除代价的个人领回”按钮。

## 已实测的边界

R7（机器 4；2026-10-17 15:37–15:50 UTC）的 N=237、卓越稀有度 4、A=15893/F=50、S=32：空槽供奉后角色 owner 15893→空、holy-site owner 空→32，owned refs 去掉 237，slot0=237，当前和缓存 Active false→true、总稀有度 0→4，钱包 2250→2250；显式取出后上述归属/slots/Active 反转，钱包 2250→1750。关联信仰 `[51,50]` 保持不变。这里只实测 F50 的认可；没有测 F51 认可、替换、实际奉献经验、意见、CB 或所有受益角色的属性。

R8 是另一次独立输入（不是 R7 连续后态）。16:22–16:24 UTC，空 S32 的 F50 关联 6→5，F51 关联继续存在，县主 15436 未变，钱包 4250→3250。它证明共享情况下可只撤掉 F50 关联；不能证明非空圣物返还、最后信仰退物或免费分支。所有脚本与原生包静态结论均未冒用为这两场实测。
