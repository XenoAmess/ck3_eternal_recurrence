# CK3 1.20.0.2 G2 private Python / MCP 接线

本轮把已有原生 provider 的实际 JSON 交给现有 Python transport，再通过正式 MCP SDK 调用同一 driver 方法。这里的 `static-ready` 只证明隔离内存、原生 callback、serializer、Python 和 MCP 之间的接口可用；不代表新版 paused 实机、行动结果或 G2 里程碑已经验收。

Exact build 为 **1.20.0.2 Crozier**，EXE SHA-256 **AE1BA6FF060BA603842F6F4A2DED0AF4B7D3666B3DD271F75FB01B0DA8E81B2D**。旧 1.19.0.6 transport 和历史证据继续保留自己的身份。新版返回值通过当前 snapshot 中既有的 hello 绑定版本；namespace 名称、ACK 和 DTO 字段本身不能代替 native build 证据。

## 显式 typed command

`--private-active-scheme-sway-action`、`--private-realm-law-crown-action`、`--private-council-action`、`--private-faction-gift-action` 和 `--private-prisoner-ransom-action` 启用已有原生报价所约束的单次 typed command；默认均 OFF。法律必须由调用者显式给出 `law_key` 和资源 budget，议会必须显式选择 native candidate，不设置默认 CA1 或新策略。Gift 沿用已有 checkpoint / pending ledger、独立 receipt 与 cold fact read，显式 reserve 随已选候选持久化，普通 planner 的既有默认不变。ransom 只返回 `submitted_verification_pending`，release 仍须当前 custody / treasury 实际观测。pending ACK 保持非 material；只有真实后置查询满足该域的条件时才返回已应用。

Feast service 仅在显式 `allow_private_activity_feast_lifecycle_observation` 下读取既有 ledger 的 hosted activity，返回 `activity_feast_lifecycle_observation`，不替换原先的 `selected_step`。缺行、缺 terminal flags 或活动消失都保持 unknown；completed/invalidated 两个原生标志分别保留。原生 prestige / stress / reveler presence / XP 的 before / after 值可独立观测；计数变化和 terminal 都不代表已归因的收益。

## 证据与实际接口修复

- 政府：实际 available/unavailable C++ serializer → Python/driver/MCP **6 项通过**；真实 owning caller 的完整 `command_result` 新增 **1 项 SDK 通过**。实际 packet 曾缺少约定的 `accepted/private_build/read_only/advertised` 字段，已由 native caller 最小修复；没有在 Python 人工补成功字段。证据位于 `artifacts/g2-offline-2026-10-01/python-routes/government-python-wire-result.json` 与 `government-actual-caller-sdk.json`。
- 家族：实际 lineage provider → owner mailbox → 完整 packet → SDK；另一份 constructed DTO serializer 只证明 send vector / outcome penalty 的 wire 合同。**6 项通过**，保留选中母系但 effective=false、CanSend=false 和合法 null lineage。send 的 prestige slot 为零时仍保留独立 stock prestige penalty，不把不同 resource/timing 相加为虚构总成本。证据为 `family-obligations-native-python-sdk.json`、`family-obligations-send-penalty-contract-fixed.json`。
- 囚犯：真实 two-row collection、真实 empty 与 unsupported-build unavailable → Python，非空集合再经 SDK。**4 项通过**。首次 fixture envelope 把 observation epoch 误用成 revision，修正为 native quote 的独立 epoch 后只复验受影响两项。受影响旧 transport/consumer **31 项通过**，默认 ordinal 的旧 SDK 接口 **1 项通过**；原失败日志保留。typed ransom MCP 的额外 **1 项合同测试通过**，明确引用 constructed quote DTO 和 pending ACK，不冒充 native evaluator 或 release 证明。
- 囚犯既有 retention 依赖：production 1.20 reader → serializer 的真实 positive / known-empty packet → 实际 primitive / normalizer → MCP → 既有 ransom join，新增 **1 项 SDK 测试通过（两 packet）**。known-empty pair list 仍保留 primary / successor commitment，不能把它当作可赎任何囚犯。只复用用户明确允许的既有赎金依赖，未扩展战争规划或研究；receipt 为 `python-routes/prisoner-retention-native-sdk.json`。
- Feast：实际 native fullcost/hosted wire **5 项通过**，受新增 hosted 字段影响的既有 transport **36 项通过**；新增真实 driver wrappers → MCP SDK **2 项通过**，保留负资源费用、CanStart=false 和 completed 原生标志。后来解冻的四项 outcome counter parser 另以实际 baseline / 四帧 trace **2 项通过**，改动后的 durable consumer **15 项通过**。详见 [Feast Python transport](ck3-1.20.0.2-feast-python-private-transport.md)，SDK / counter 增量 receipt 为 `artifacts/g2-offline-2026-10-01/feast-python/mcp-wire-result.json`、`counter-append-result.json`。

## 战争停止后的范围

本轮早段已完成并验证的 current military expenses / generic termination send-fee Python SDK 合同保留为历史离线成果，当前 candidate profile 不启用它。其原生 actor-global expense 只计一次，不推导 future upper、reserve 或完整 immediate cost。用户后来要求停止战争事务后，未验证的 Python prewar 草稿已移出 active source；不继续新战争 query、forecast 或 policy 接线。

剩余验收是新版真实 paused 查询、具体候选动作、独立 pre/action/post/next-turn、自然 terminal/value 与 cold restore，由唯一 live owner 安排。当前文档不增加任何 G2 完成项、生产 loop 或游戏经过天数。
