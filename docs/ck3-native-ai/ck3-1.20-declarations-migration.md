当前为 `static-ready`。只读取冻结 EXE、使用代理拥有的合成对象运行测试；没有打开、注入、暂停、输入或重启正在运行的 CK3。

构建固定为 `1.20.0.2 (Crozier)`，Steam build `25588574`，EXE SHA-256 `AE1BA6FF060BA603842F6F4A2DED0AF4B7D3666B3DD271F75FB01B0DA8E81B2D`。冻结副本位于 `artifacts/migrations/2026-09-30/post-update-1.20.0.2/installation/binaries/ck3.exe`。

这次不是统一增加 RVA 偏移。原生 `CDeclareWarInteractionWindow` 的枚举函数 `0x118C6C0` 闭合了以下变化：

| CB 数据库类型数组 / 数量 | `+0x68 / +0x74` | `+0x50 / +0x5C` | `0x118C71D..0x118C725` |

CB 规范 key 的 MSVC string 仍在 `+0x18`，size/capacity 在 `+0x28 / +0x30`；新构造器 `0x31F1AEB..0x31F1B1E` 单独证明了这一点。配置元素仍为 `0x98` 字节，claimant 在 `+0`、目标 TitleID 数组在 `+8`。新析构器是 `0x111F190`，数组 copy/append 分别为 `0xC858C0 / 0x9E3790`。

`DeclarationsBindings` 使用本构建的 `CoreBindings` 和 `CommandBindings`，实现显式目标枚举、全体有效角色枚举及提交。枚举按原生最终 evaluator 结果过滤，不推导额外信仰规则。原生行为保留：零配置或者 bit 20 时合并为一项，其余只发布目标 title 数组非空的单项。

提交重新枚举完整 choice，逐字段比较目标 CharacterID、CB ordinal/key、配置 ordinal、claimant 和 TitleID 数组。随后构造 `0x338` 字节原生 interaction context，填入原生 `CWarDeclaration`，清理 evaluator scratch，调用 refresh `0x3078A60`、finalize `0x3078C90`、validator `0x307C040`，构造 `0x368` 字节 `CSendCharacterInteractionCommand`。原生 UI `0x10451DA..0x10451FB` 证明通道 flags 是 `0x0E`，command 内 context 位于 `+0x20`；原件与 command 副本均调用 `0x30773A0` 销毁。共享提交器再通过原生 vtable `+0x40` clone 和 `0x37F06F0` 队列交接所有权。

基础 context 构造器 `0x3076C90` 最后一个 bool 是角色重定向开关，内部调用的新重定向函数现在处理六个 CharacterID，包括新增 `+0x2EC` 角色；不能再把旧“五角色”调用签名直接搬过来。

合成 fixture 使用旧数据库位置和旧死亡位置的干扰值，验证新数组偏移、禁用 CB、非空配置选择、合并配置、零配置、SSO/heap key、完整 CharacterID generation、过期 choice、validator 失败、队列拒绝和三个 context 副本的析构。MSVC 19.51 的独立构建成功，fixture 返回 0。固定 ABI 清单 `research/ck3_1_20_0_2_declarations.json` 冻结 20 个唯一字节签名、3 个 vtable prefix、43 条关键指令与 31 项 C++ 源常量。原生 clone `0x86D77A` 明确分配 `0x368` 字节，context 起于 `+0x20`、后续标量起于 `+0x358`，独立闭合了 context 的 `0x338` 字节大小。
