# Council final-gates read with no candidate payload

N40 P02 AUTO163 stopped while ordinary planning read private council final gates. The public MCP error says the completed query lacked a candidate payload. The native final-gates serializer intentionally omits that payload when its gate result is unavailable: it reports zero candidates, zero rows and zero native helper invocations. The old Python normalizer rejected every missing payload before checking this unavailable shape.

The initial P03 transport normalizer accepted only a narrowly predicted completed, private, read-only final-gates envelope. It retained the native envelope status and query sequence, returned `status=unavailable` to the council planner, and supplied no candidate or build attestation derived from an absent payload. That prediction required a nonempty unavailable reason, zero helper calls and zero gate rows. The council planner maps an unavailable query to `QUERY_UNAVAILABLE`; no assignment is selected. Its independent optional-check cadence defers further council opportunity checks for 30 game days only after three completed no-action reviews. Pending assignments retain their priority.

Explicit assignment ACK or receipt, action submission evidence, pending/action status, wrong actor or frame, or changed episode, connection or PID still reject.
