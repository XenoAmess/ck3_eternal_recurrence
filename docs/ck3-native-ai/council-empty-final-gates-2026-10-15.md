# Council final-gates read with no candidate payload

N40 P02 AUTO163 stopped while ordinary planning read private council final gates. The public MCP error says the completed query lacked a candidate payload. The native final-gates serializer intentionally omits that payload when its gate result is unavailable: it reports zero candidates, zero rows and zero native helper invocations. The old Python normalizer rejected every missing payload before checking this unavailable shape.

The [transport normalizer](../../ck3_autonomous_player/src/xar_autoplayer/bridge/council_private_transport_v1.py) now accepts only that exact completed, private, read-only final-gates envelope. It retains the native envelope status and query sequence, returns `status=unavailable` to the council planner, and supplies no candidate or build attestation derived from an absent payload. Any malformed frame, nonempty candidate claim, native helper call, or available gate result still raises. The existing council planner maps this to `QUERY_UNAVAILABLE`; no assignment is selected. Its existing independent optional-check cadence records a no-action review and defers further council opportunity checks for 30 game days only after three such completed reviews. Pending assignments retain their priority.
