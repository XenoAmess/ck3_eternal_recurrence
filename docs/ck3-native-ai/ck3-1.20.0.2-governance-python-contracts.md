# 1.20.0.2 议会、派系与赠礼 Python 契约迁移

本页记录 G2 M4 的 Python 接口迁移。原生字段、地址与查询来源由对应的 exact-build provider 专题维护；这里不把 DTO 通过校验等同于实机能力。

## 来源与兼容边界

新版固定为 CK3 **1.20.0.2 Crozier**，EXE SHA-256 为 `AE1BA6FF060BA603842F6F4A2DED0AF4B7D3666B3DD271F75FB01B0DA8E81B2D`。旧版 1.19.0.6 的 `2D00FF3101EF70B566F2FCBAE292F09263199C80E9DC8F139B82D7D96F83DB86` 继续作为独立来源保留，不把旧 DTO 改写成新版来源。

`player_faction_alerts_contract.py` 通过现有 `version_identity.require_exact_native_backend` 识别两组来源。新版 backend 为 `ck3-1.20.0.2-native-player-faction-alerts-v1`。调用方可传 `expected_game_version` 和 `expected_executable_sha256`，把来源与已连接的游戏 build 绑定；帧日期、revision 与派系战争 ID 的同帧检查继续复用。`GameplayBridgeService` 的 `build` 输出已经来自规范化后的 `provenance`，无需另设版本常量。

议会候选、指派 ACK 和独立 incumbent receipt 继续使用原 v1 DTO。版本信息位于原生结果外层 `exact_build`，不是候选行内部的新字段。Python 不重算原生候选合法性，也不把 `native_helper_invoked_verification_pending` 当作 `applied`。

新版 SDK 通过 `council_private_transport_v1.py` 消费实际 private mailbox 入口。候选与 final-gate 查询先发送一次原步骤，再轮询 `private-council-application-main-status-v1`；`pending` 和消费后的 `idle` 都不会被投影成候选可用。查询、指派和 receipt 共用这条既有异步协议。指派复用原请求/ACK 契约，receipt 必须对应后续原生帧的真实 incumbent。SDK 的查询与动作开关分别是 `--private-council-query` 和 `--private-council-action`，默认关闭；连接时的实际 version/SHA 由 driver 传入。

private transport 的 `SnapshotRequest` 使用 `native:N`，DTO 的 `public_revision` 与 `native_revision` 都是原生 published counter `N`。SDK 自身 public revision 可以不同，保存在外层 `queried_revision` 与 `source_frame`；不得重写实际原生 DTO 的帧编号来假装它已经是 public query 的生产入口。

赠礼继续使用既有四个 private steps、预算选择器和 pending ledger。新版原生 provider 负责送礼定义、最终 CanSend、成本、意见与派系独立重读；Python 无需修改旧业务 schema。完整的原生合法性拒绝仍由 `gift_preview.interaction_legal=false` 或 `auto_accept=false` 表示，选择器返回 `no_legal_candidate`。来源缺失与已知没有合法候选继续区分。私有 SDK 查询开关为 `--private-faction-gift-query`，动作开关为 `--private-faction-gift-action`，默认均关闭；这两个开关不启用普通 planner 的 `allow_private_faction_gift_formal_trial`。

本轮实际 C++ 样本复现了两项接口问题并已修复：原生 `no_legal_candidate` 外层状态虽附有完整 `preview_ready` 观测，却被旧 Python 误判为非终态；现在继续读取该完整观测并由既有选择器返回拒绝。SDK 显式传入的预算储备必须跟随 `choice.minimum_gold_reserve_raw` 写入提交 ledger，不能被提交函数硬编码为 `10000000`；普通 planner 和 SDK 默认值仍为 `10000000`。

派系的实际生产路径离线样本已由 native provider 输出：`artifacts/g2-offline-2026-10-01/factions/fixture.json`，逐字节副本保存于 `ck3_autonomous_player/tests/fixtures/native_12002/governance/faction-alerts.json`，SHA-256 `769eec6c0b0b5e0dbbe76319e8e196c5ffa5d70b7609825a9c2d5d9bc708e8ba`。样本包含三个 targeting faction、无角色 leader 的 county-only faction，以及从玩家县 joined-faction span 读取的县暴露；县暴露的目标不必是玩家的某个祖先。native `/Od` 和 `/O2` fixture 均完成七项检查，这仍是离线 fixture，不是游戏捕获。

该来源的 power、threshold 与 discontent 使用原生百分比点乘 `100000`：例如 `110%` 的 power 为 `raw=11000000`，`25` 点 discontent 为 `raw=2500000`。GUI ratio 另有除 `100` 的投影，不能把其数值直接替换本 DTO。现有赠礼选择器只检查派系指标是否可读，不比较 `1.0` 阈值，因此无需在赠礼 Python 路由中再除 `100`。
