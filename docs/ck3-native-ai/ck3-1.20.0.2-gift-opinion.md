## 不能照搬旧地址之外的三处变化

1. **角色 extension 从 `+0x1A8` 移至 `+0x1B0`。** 旧偏移在本版本对应其他角色数据。modifier pointer 在 active 行 `+0x08`，group rows/count `+0x08/+0x14` 保持。
2. **定义有效性不能再调用旧 primary vtable 第零槽。** 新 `COpinionModifier` 的 primary 第零槽为析构；new named value 第零槽是空 `RET`。原生 initializer 以 `definition+0x38 == 0x4744624F`（`ObDG`）判定有效对象。生产 reader 已改用该 tag、真实 primary/secondary vptr、canonical hash/key；modifier secondary 从 `+0x80` 移至 `+0x88`。named secondary 仍为 `+0x88`。
3. **named source descriptor 改用 interned name。** 新 evaluator 的 `0x20` source descriptor 为 intern pointer `+0x00`、zero `+0x08/+0x10`、byte one `+0x14`、signed `-1` `+0x18`、zero `+0x1C`。它由 `0x3F79B20` getter 和 `0x3F79DF0` interner 构造，旧 data pointer / length 的 `0x28` descriptor 不兼容。interner 可更新引擎字符串缓存，但这些读口没有 gameplay mutation。

scope `0x168`、support `0x118/0x2A8`、internal context `0x28` 的布局与 stock teardown 顺序已从新调用链闭合。新 clone 与 support 构造、内部 scope/support 指针、evaluation flag `0x5D1DADC`、teardown `0x889700/0x889780/0x9D7340` 都使用本版本入口。

## 真实付款与 present-zero

冻结 `game/common/character_interactions/00_gift.txt` 的 `on_accept` 在 `scope:puppet_or_actor` 中执行 `pay_short_term_gold = { gold = gift_value target = scope:recipient }`。付款定义位于 `common/script_values/00_scheme_values.txt`，`send_gift_opinion` 位于 `00_basic_values.txt`。

因此 generic on-send cost 的 gold 槽为零不能代表送礼免费；送礼 proposal 必须使用原生 `gift_value` 的固定点结果作为这项实际付款，避免与 generic 成本重复计入。`ReadGiftValueExact12002` 的 root=actor 适用于普通非 puppet 操作；调用方若明确支持 puppet，须将 stock `puppet_or_actor` 身份作为共享 named evaluator 的根角色。

`gift_opinion_present` 与 `gift_opinion_modifier_value` 分开。真实 active 行存在、native sum 为 `0` 时发布 `present=true/value=0`；没有对应行时发布 `present=false/value=null`。定义读取或角色代际不匹配属于 unavailable，不得冒充 absent。总好感合法零和 named 固定点合法零仍可发布。
