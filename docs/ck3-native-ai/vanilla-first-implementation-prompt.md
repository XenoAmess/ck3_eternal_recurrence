# 原版优先实施与优化提示词

2026-10-16 用户重申：先拆解和学习原版怎样完成任务，再设计我方实现，使结果更优或至少不更差。
本提示词细化 [AGENTS.md](../../AGENTS.md) 的已有要求，供根代理和被委派代理共同使用。
它不替代 [研究工作流](research-tooling-workflow.md)、已有授权和实际能力合同，也不要求停下有效自动游玩等待研究完成。

## 可直接使用的工作包提示词

```text
任务：{用户要求的可见结果或已证实的性能/玩法问题}。
输入：{当前实际版本/EXE SHA、已加载实现身份、已有原版专题和实际回执}。
范围：{唯一可写文件、输出预算、运行/只读权限、已运行主线的负责人}。

先学习原版，再设计实现：
1. 先复用已有研究，核其版本与证据范围。把当前原版实际流程写出来：
   触发/调度 → 候选来源与枚举 → 索引/缓存 → 廉价过滤 → 评分/选择
   → 最终合法性验证 → 执行 → 独立后置结果。
   核实际producer/caller/consumer与对象生命周期；玩家GUI、原生AI和我方桥接分别记录。
   只找到末端函数、GUI字段名、脚本条件或旧版RVA，不算还原整个流程。
2. 更新原生专题的证据正文和Mermaid。每条边分别标static-confirmed、live-confirmed、
   inference或unknown；unknown用虚线，并写具体下一定位入口。不得先写我方优化再补原版故事。
   未定位当前版本的旧入口保持unknown；调用原版函数不等于复制其搜索、缓存或调度方式。
3. 对照现实现，指出具体差距及实际成本：扫描对象数、昂贵调用次数、重复查询/分配、
   失效/重算频率、墙钟与产出。已有证据直接复用；不能只因猜测开新审计或大矩阵。
4. 基于已证链设计最小改进，明确复用哪段原版做法、为何改变、与原行为的差异。
   裁剪条件必须是已证明的必要条件或返回完整候选超集；目标依赖、脚本覆盖、
   defender重定向或索引完整性未闭合的部分保留现路径，不把缺数据解释为无候选。
   不能把只交换循环顺序称作降复杂度，也不能把局部机会查询冒充完整目录查询。
5. 验证“更优或至少不更差”的具体范围：同一输入/帧下比较完整候选身份、配置和决策，
   再比较原生调用次数与端到端墙钟，计入索引构建、缓存失效、MCP、队列和回执开销。
   有随机或状态写入的原版函数先查调用副作用，不能直接重复调用来制造对照。
   差异未解释前不替换原实现；有用的窄范围先收口，不要求穷举所有游戏场景。
6. 性能修改保持玩法策略中立；需要改变机会范围、战争意愿或风险偏好时另列玩法变更，
   不能把它计作性能收益。不以模拟/ACK/单个样本宣称真实战果或普遍优于原版。

研究与离线验证不阻塞当前有效自动游玩。必须修复的真实主线错误另由运行负责人处理，
不能让研究者抢Game/pipe/SDK/state或热换DLL。已授权实现继续推进，不重复请求许可。
委派时先核代理状态：已 completed/idle 的代理需要 `followup_task` 才会继续工作，
`send_message` 只投递消息，不会唤醒它；代理已 errored 时立即接手或重派，避免空等。
等待新工具前先查现有工具是否已覆盖当前控制与回执合同。

交付：原版实际流程与证据边界；我方差距；最小实现或可施工入口；真实验证及性能；
部署/未部署状态；剩余债务和下一步。若尚无原版对照，不得宣称“至少不差”已经成立。
```

## 宣战查询的具体纠偏

已核来源、接口缺口及候选方案见 [1.20.0.4 候选生成评估](declaration-candidate-generation-12004.md)。

- 已有 [1.19.0.6 宣战树](war-declaration.md) 研究了战略目标、粗军力筛选及后续 CB/配置枚举。
  它不能作为 1.20.0.4 的可直接调用 ABI；先迁移候选生产和消费链，再决定复用方式。
- 当前桥接的“角色存储 × 启用 CB”只证明它调用原版评估函数，不代表学习并采用了原版目标搜索。
  不能把对我方代码画的流程图当成原版 AI 流程图。
- “先借口、后对象”只有在借口能导出更小且完整的候选集时才省调用。
  例如宣称关联头衔和持有人是候选来源研究方向；已知 TitleID 的 claim 查询不等于完整宣称枚举。
  `allowed_for_character` 之类字段也须核实其实际 scope 依赖，不能仅按名称当作纯攻击方条件。
- 玩家 GUI 已给定 recipient 的 CB 列表、原版 AI 的战略候选列表、完整合法宣战目录是三个不同合同。
  复用战略候选或缩小自动游玩机会范围前，须说明是否改变完整性与原有决策。
- 对新旧查询比较完整目标/CB/配置/claimant/头衔身份及实际原生评估次数和墙钟。
  没有当前版本的候选完整性与实测，就记录为研究或候选，不写成已提速。

## 本次反思

此前把“原版单个 CB 评估与交互提交已核实”扩大成“原版候选搜索流程已经学习”。
同时，已有旧版候选树未落实到当前版实现，性能优化集中于调用后的开销，漏掉了上游搜索范围。
修正执行与委派要求，以原版候选生产链、同帧行为和端到端成本作为比较依据；
保留历史研究及失败事实，不追认当前搜索已等价于原版，也不声称本次提示词修改已经加速游戏。
