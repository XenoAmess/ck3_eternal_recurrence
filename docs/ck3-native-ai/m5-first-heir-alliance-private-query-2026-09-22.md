# M5 首继承人五候选联盟投影：私有接线

状态：原五候选 pair 投影已由 R0133 在真实 paused 帧读回；2026-09-26 新增的婚姻/订婚预测字段仍是 `static-ready`，未实机复验，不代表联盟会建立、M5 联合选择完成或 G2 状态改变。R0133 五行中八个潜在 pair 的 `would_attempt_if_accepted` 全为 `false`，不能记作联盟收益。冻结 CK3 1.19.0.6，EXE SHA-256 `2D00FF3101EF70B566F2FCBAE292F09263199C80E9DC8F139B82D7D96F83DB86`。来源与界限见 [候选联盟投影 ABI](m5-r0082-candidate-alliance-projection-abi-2026-09-22.md)、[R0082 五候选缺口](m5-r0082-joint-selector-field-gap-2026-09-22.md) 和 [原生婚姻树](marriage-and-alliance.md)。

默认关闭的 `XAR_CK3_ENABLE_G2_M5_ALLIANCE_PROJECTION_PRIVATE_QUERY_V1` 依赖原有私有首继承人合法性查询选项，但不依赖私有婚姻动作选项。只有原有公共 campaign-root 在同一 native revision 指明首继承人、接着私有 `query-observed-first-heir-marriage-legality-v1` 返回合法候选行，才能调用新 `query-first-heir-candidate-alliance-projection-v1-private`。调用者提供 `expected_revision`、`legality_query_sequence` 和动态发现的 `candidate_id_0` 至 `candidate_id_4`；五个完整 CharacterID 必须互异且各自唯一存在于当前 final-legal 行。R0082 的五个示例 ID 仅供证据定位，不写入查询或策略。

该查询在已验证暂停的 application-main mailbox 依次重新构造每一候选五角色 context，执行原生 redirect、refresh、finalize、Can Send、接收者最终答复，核对身份与先前合法行后，在 context 销毁前调用精确构建的原生联盟 pair helper 和已有的 `marriage_native_outcome_classifier_v1`。每行返回 matrilineal option 是否选中、**仅在对方接受后**预计发生 `marriage` 还是 `betrothal`，以及最多三个潜在 pair 的完整 CharacterID、当前是否已结盟、双方是否有 realm data、若被接受是否进入联盟创建尝试。预测依据是同一 finalized context 中实际双方成人阈值与 grand wedding 选项；分类失败时 `predicted_outcome_if_accepted=null`、`outcome_failure` 给出原因，整行 `unavailable`，不把未知写成 `false` 或婚姻。查询前后核对同一 paused snapshot/date/revision。输出没有原生排名、效用、婚配成功承诺或联盟结果，且不提交任何动作。

2026-09-26 `NW-FAMILY-VALUE` 再将现有玩家关系读取所用的 exact-build `CCharacter+0x1A0` family data 读法用于**首继承人本体**，而不是读取玩家本人的配偶状态。每个可用候选行新增 `heir_betrothed_character_id`、`heir_primary_spouse_character_id` 与完整 `heir_spouse_character_ids`；同一 heir 在五行中必须一致，读取前后必须相同。不可用行把三项置为 `null`，不会把缺失伪作未婚。该字段仅说明当前关系，不能单独证明新候选会带来正收益，也不能证明 dynasty/lineality 结果；这版源码和聚焦测试仍缺 Robert paused 实机回读。

`NW-FAMILY-DYNASTY` 在相同默认关闭查询中为玩家、首继承人、每候选分别增加 `*_house_id` 和 `*_dynasty_id`，返回原生完整 ID；合法无 House/Dynasty 时为 `null`，generation 不符或 store 不可读使该行 `lineage_unavailable`。依据 [原生婚姻树](marriage-and-alliance.md)和 [既有 exact-build House/Dynasty reader](combat-phase-events.md#dynasty-perk-exact-build-reader-abi)，路径是 `CCharacter+0x150` → House store/`CHouse+0x10` → `CHouse+0x2C` → Dynasty store/`CDynasty+0x10`。每行前后重读三个角色；同一玩家和继承人的身份须跨五行一致。另复用 native 候选评分函数和既有 outcome classifier 均读取的 `CCharacter+0x199`，发布继承人和候选的 `*_sex_selector_raw`，仅保留 `0/1` 原值。exact 婚配执行 `0x2282E76–0x2282EAB` 在相同 selector 时取继承人 selector，否则取 context matrilineal option，并把该位传入 marriage/betrothal native 操作；新字段 `effective_matrilineal_if_accepted` 明确是**对方接受条件下的执行位预测**，非提案接受保证或子代宗族结果。当前身份与执行位仍不能单独推断未出生子代的宗族、婚配价值或联盟成立。本包没有发出提案、更新游戏日期或验收 Robert paused 帧。

Python 私有入口为 `NativeDriver.query_first_heir_candidate_alliance_projection_private_v1(legality=..., candidate_character_ids=[...])`。它不进入正式 step registry、公共 capability 广告或 MCP；与既有下游/open_kaishek 的接口影响为**无公开协议变化**。私有实验 DLL 必须显式开启上述 CMake option。下一门是新冻结 DLL 对五条真实 final-legal 行的 outcome、继承人关系和三方 House/Dynasty 的 Robert paused 读回；之后还需子代宗族结果、候选目标估值、联盟价值与长期承诺、联合机会成本、正式动作、独立后置和下一轮消费，不能因本页的静态测试通过宣称 M5 GREEN。

`NW-FAMILY-PROPOSAL` 新增默认关闭的 bounded `--allow-private-family-marriage-formal-trial`，在正式 turn 的低优先 `life-advance` 机会用同帧合法性与现有五行投影筛选一项首继承人成人婚姻；其窄收益和未知字段见[原生婚姻树](marriage-and-alliance.md)。提交前写入 durable pending，后续 native resolution 与双向关系分别保留；冷 PID 仅凭关系可确认成立，缺关系时仍为 unresolved，绝不推断拒绝或重复发案。其 Release/测试属于 `static-ready`，还没有 Robert paused 正机会、提案、日期、下一 turn 或 cold-restore 实机证据。该私有消费者不改变本页读口的公共广告或 M5 `formal_action_ready=false` 边界。
