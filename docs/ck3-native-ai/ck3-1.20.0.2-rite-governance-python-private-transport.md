## 分组件状态与字段语义

顶层 `frame_available` 表示共同 paused 玩家帧已读取；`available` 表示至少一个组件完整可用；`observed_components` 是三个组件中 available 的个数；`all_components_available` 表示三个都可用。这些状态分别保留。顶层成功 `unavailable_reason` 为原生字符串 `"none"`，各可用组件的 reason 为 `null`。

| 组件 | 保留内容 | 实际语义 |
| --- | --- | --- |
| `state_rite` | actor Rite/Faith/main Rite、top liege、玩家与 realm primary title 的 state Rite/Faith | 玩家 Rite、Faith main Rite、自己领地 state Rite 与 realm state Rite 是不同引用，不互相代填 |
| `heads` | actor Rite head、Faith main Rite head、Faith religious head title/holder | 四个结果独立保留，不把其中一个当作统一宗教领袖 |
| `organization` | current-player Rite、county count、character follower count | 原生缓存计数，不是完整成员列表 |

所有 nullable 引用保留完整 `uint32` 值，含高位 ID 和合法 `0`；`null` 保持原样。组织计数保留 nullable signed `int32`，合法零值不转成 unknown。没有 actor Rite 的成功读取可以 `available=true` 且 Rite/counts 为 `null`，不能因此把整个结果判为失败。

失败组件保留自身 reason、原生 frame defaults 及已输出的部分字段；不能因 head getter 失败抹去可用的 state Rite 和组织计数。`capture_epoch` 是原生 owner-pump identity，不等于 bridge `snapshot_revision`，也不重写成该 revision。归一化返回独立的嵌套字典，避免后续 buffer 复用改变已交付的 DTO。
