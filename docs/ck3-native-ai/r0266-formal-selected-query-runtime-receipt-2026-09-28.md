## Entry and evidence

The `native-auto-run` CLI accepts `--formal-war-query-receipt-dir <fresh-external-directory>` together with `--formal-war-query-source-commit <40-hex>`. This opt-in requires one bounded turn, a cold checkpoint, and no caller interceptors. The normal run path is unchanged. A new directory is created with `intent.json` before launch; after managed cleanup it appends `formal-selected-query-receipt.json`. Each run needs a new directory. The operator must separately obtain the exact frozen pair, official no-launch and fresh Steam offline/screen lease evidence before starting; these CLI flags do not perform those approvals.

The runner calls the real `service.auto_turn()` with a pre-submit guard. It refuses any candidate except the exact formal `query-war-termination-options-16777231` selected step and its typed `read_only_query` command. This dedicated mode skips the normal optional camera-follow presentation action. The driver preserves its parsed Python protocol request and received `command_result` envelope, request ID, protocol version, native query sequence and WarID. It also captures the native semantic snapshots before and after the query. The receipt builder requires one active WarID, equal six-field actor/episode/date/native/public revision/snapshot identity, paused and map-ready state, **exact Q100000 player treasury raw unchanged across the outer snapshots and both inner driver observations**, matching plan and response, and an unchanged runner gameplay-action count. Missing, malformed or changed treasury blocks the receipt even when all revision fields match.

Before launch the runner hashes the frozen input driver-state file as the source pair anchor. The process check then samples the CK3 PID and Windows creation FILETIME before reading process paths and again after hashing. It verifies the actual running `ck3.exe` path, the unique mapped native DLL path, and SHA-256 of the mapped paths' **disk files**, the launch injector file and restored driver-state file. The restored JSON must bind `bridge_pid`, actor and episode to the observed process and frame. It repeats the process check after the query. This does not hash live code pages, prove the DLL's query implementation is read-only, or prove that a source commit built the DLL. The injector is a launch binary, not a loaded CK3 module. Cold restore normally rewrites `bridge_pid`, so the prelaunch pair SHA and restored driver SHA are independent observations; the file may acquire a read-only query history row and the receipt records its postquery SHA separately.

The driver preserves parsed protocol objects, not raw named-pipe bytes. The receipt is conditional diagnostic evidence even when `status=same_paused_query_postcheck_passed`: `immediate_war_action_cost_raw=null` and `formal_cash_receipt_eligible=false`. Direct H2743 query evidence from PR #448 has no formal selected plan or typed command and cannot be spliced into this receipt. A failed selection, response, frame, process or managed cleanup produces a blocked append-only receipt. No historical H3770/H3774/H3778/H3860 frame may be retrofilled.
