# Player religion doctrines: private Python transport

The readonly selector `query-player-religion-doctrines-v1` reads the current player's native doctrine context. It uses domain `player_religion_doctrines_v1` and backend `ck3-1.20.0.2-native-player-religion-doctrines-v1`, bound to CK3 1.20.0.2 / EXE SHA-256 `AE1BA6FF060BA603842F6F4A2DED0AF4B7D3666B3DD271F75FB01B0DA8E81B2D` from the real snapshot hello. The permission `allow_private_player_religion_doctrines_query` defaults to off.

The shared driver method is `query_player_religion_doctrines_private_v1(expected_revision)`. MCP publishes `ck3_query_player_religion_doctrines_v1(expected_revision)` as a readonly tool only when `--private-player-religion-doctrines-query` explicitly enables the permission on the existing native-headless entry. No gameplay action or default policy is enabled.

`player_religion_doctrines_private_transport.py` reuses the existing execute-step endpoint and paused-frame query transport. It sends one readonly request using the snapshot's native revision, then preserves the complete `ck3_12002_current_doctrines_v1` producer DTO. The owner-pump `capture_epoch` remains distinct from `snapshot_revision`; the serializer's fields and full unsigned reference identities are retained.

The DTO keeps three observed scopes:

- `current_rite.rows`: effective doctrines for the player's current Rite, each with `source = rite_effective`.
- `faith_main_rite.rows`: doctrines for the Faith's main Rite, each with `source = faith_main_rite`. The player's `rite_id` and `main_rite_id` can differ.
- `boolean_parameters`: separate current-Rite and Faith-main-Rite parameter bags. The native producer emits boolean presence entries with `value = true` and an explicit `boolean_parameters_complete` marker. These are boolean bags, not numeric parameters or intrinsic values.

A successful empty doctrine list or complete empty parameter bag stays available and empty. A native read failure stays unavailable with its typed `unavailable_reason`; the aggregate provider resets the child DTOs on failure, and Python preserves those reset values. It never substitutes a success-shaped empty bag for a failed read. Escaped quotes and UTF-8 doctrine or group keys pass through unchanged.

This query does not compute Tenet choices, doctrine eligibility, intrinsic or numeric parameter effects, hostility, conversion legality or religious actions. It supplies current observations only. Static fixtures originate from production native getters/serializers executed against owned process memory and callback bindings; they do not establish a paused live CK3 result.
