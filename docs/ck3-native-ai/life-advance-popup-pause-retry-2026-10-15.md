# 弹窗到达时的 life-advance 暂停恢复（2026-10-15）

N38 的一次普通推进在游戏日期前进后，清理用的第二次原生 `pause-map` 返回 `CK3 map state is unavailable`。随后的独立语义帧显示同一局游戏出现玩家事件。原有 [暂停拒绝恢复](life-advance-pause-map-unavailable-recovery-2026-10-01.md)只覆盖首次拒绝后一次重试，因此这次 MCP 结果为错误，不能把已前进日期记作成功。

本次 `NativeHeadlessGameplayDriver._pause_life_advance` 在首次或第二次精确错误后读取新语义帧；只有连续两帧确认相同非空事件或角色交互、同一 bridge PID／连接代次／角色／episode／本地玩家／日期、角色存活且地图就绪时，才允许在原 deadline 内再发送幂等 `pause-map`。最多三次暂停请求，每条拒绝保留在 `actions`；最终仍须真实读到 `paused=true`。事件变化、跨日、连接或角色变化、缺少弹窗、第三次拒绝、超时和其他错误均停止，不补造暂停或业务结果。活动弹窗在组合结果中保留，`final_screen` 为空，供后续规划处理。

队列对这种结果须逐条验证 action 与初始规划帧绑定，并要求配对的推进后指标确认日期；观察到推进不授予政务、战争或事件成功，也不授权重放。普通无弹窗的既有两次暂停契约与严格单日推进不变。当前仓库测试用合成原生端点覆盖首拒后弹窗、次拒后弹窗、第三拒绝和既有无弹窗路径。实机故障后的新恢复成功尚未宣称；冻结候选及离线分类器证据保留在该场次外置目录。
