# 采用别人的圣地，买到的究竟是什么

> 2026-10-18 后继更正：新稿使用“圣地名单、总数名额、主要圣地名额、类型与选址限制”取代含糊的“网络资源”，并统一官方术语。缩放总数的缓存来源、参数、等级及9/3动态研究见[v4机制更正](faith-and-power-episode01-v4-mechanics-corrections-12004.md)。下文保留上一轮研究与分支余额，不倒改历史证据。

采用的直接结果是把一个既有圣地加入自己的 Faith 网络。它不夺取土地，也不自动把本站变成主要圣地、供奉圣物或建好特殊建筑。值得不值得，取决于**受益者是谁、当前缺哪一层条件、完整方案还要投入什么**，不能只比较圣地数量。

适用 1.20.0.4/build25734779；`machine_id: 4-8e1c2f1861`。本篇是离线研究，静态源码核读和小型历史回执投影时间见[来源索引](faith-and-power-adoption-value-12004.sources.json)。本机安装源码按完整 SHA 绑定；R4、R7、R8 的实例 ID 和状态只证明各自当时的实验局面。本期采用累计额外+5000虔诚、个人礼仪改Maliki的已披露独立机制实验，不计为普通战役积累。本文没有新实机操作或净属性验收。

## 先把收益分给正确的人

| 所求收益 | 要看什么条件 | 收件人和本期材料 |
|---|---|---|
| 地方和县主类型收益 | 类型的县主/伯爵领块、持有人Faith、独立Active/有效稀有度和原生适用Title输入 | 普通等级仍保留这类定义资格。Nadjaf32的县主是封臣15436；Samarra326和历史Baghdad14的县主是玩家15893。不能仅因由皇帝采用，就把地方项记为皇帝自己的学习或收入；实际收件人还要读原生Title两族输入。 |
| 全Faith类型收益 | 本Faith的**主要**关系、县主持有人Faith；固定块与稀有度scaled块分别判断 | 另一个Faith把同站列为主要，不给Faith50同等主要资格。普通站点不能领取`faith_character_modifier`和其scaled块；不能把地方固定块的Active门统一套给全Faith固定块。 |
| 特殊建筑 | 特定建筑已建/启用状态、实际地产持有人、该建筑自己的宗教AND/OR、槽位与施工条件 | 建筑规则独立。采用可补某个缺失的关联谓词，却不能证明整座建筑已经启用，更不会代付建造金币。 |
| 朝圣 | 当前主持人、朝圣类型和实际候选/地点合法性、首都、近期访问、旅费/路线/健康 | 网络关联只提供可能的目的地价值。Hajj只去麦加；非冒险者不能去自己当前首都朝圣。 |

这里的“定义资格”还不是“属性已经到账”。类型说明、原生适用判断和角色/伯爵领净属性后读必须分开。原生消费者进一步区分：地方固定项要求Active、实际接收角色Faith关联，且须来自原生选择的Title两族输入，不能简化为任意同Faith角色或臆造的`holder==actor`条件；伯爵领scaled项要求Active和县主Faith门。全Faith固定项检查本Faith主要资格及县主Faith匹配，不能因Inactive的GUI预览为空就断言也停效。scaled项还取决于有效稀有度。完整源码闭合见[主要等级价值专题](holy-site-major-grade-value12004.md)，本期净属性仍未测，伯爵领聚合receiver绑定亦有窄缺口。采用决议中名为`active_site`的提示实际检查“任一关联Faith有伯爵领信众”，也不是圣物模型的`Active`。[S01 529–534、S02 32–78、NS01；所有编号见来源索引。]

## 场景一：为了个人成长，先看自己已有的巴格达

本期Faith50已经关联Baghdad14，不能再付一次钱“采用”。R4独立读回的县主是玩家15893，站内神器64、有效稀有度2，当前/缓存Active均true；这不等于最新帧，也没有证明净属性到账。若目标是学习和经济，先评估这个已有站点的当前状态或主要候选，比直接盯着新地标更有依据。[S01 512–517、H01]

Baghdad类型的县主块声明学习+1、`development_growth_factor=0.05`；稀有度2时，伯爵领scaled定义算得建造金币费−2%、劫掠耗时+4%。**若**进一步满足Faith50主要和全部受益条件，Faith块还声明学习+1、教会地产建造费−10%，稀有度2对应发展增长倍率+2%、月收入倍率+1%。这些是源文件的条件计算，不是本期测得的净收益；我们没有查询“现在升级Baghdad”是否合法，也不能据此称它最优。[S03 359–383]

对照Nadjaf32：它的县主固定项是教士好感+3，不是皇帝学习+3；R8县主是封臣15436，站内为空、Active false、有效稀有度0。只为皇帝即时学习/收入而采用空纳杰夫，缺少对应的兑现路径。若另有建筑或朝圣目标，应把那个目标单独查清再估值。[S03 842–865、H02]

若打算把封臣的地方发展折算成皇帝收入，还要另读实际持有链、契约和税入，不能把县级收益原数全记进玩家钱包。

## 场景二：想要全Faith收益，1000只是第一步

Nadjaf的主要块是每奉献等级外交+1、教士好感+5，以及每有效稀有度1%的月虔诚倍率。普通采用不会直接取得这套主要收益。若本Faith主要名额已满，还要比较“降掉哪一个主要站点会失去什么”，再决定是否升级纳杰夫；不能把降级看成免费腾位。[S02、S03、H04]

固定外交/教士好感与按稀有度放大的月虔诚是两种目标：前者按原生消费者的主要资格和县主Faith门判断，不能把“先捐一件圣物”写成它的统一必要条件；后者在有效稀有度0时没有scaled幅度。于是“只要固定宗教政治收益”和“还要月虔诚倍率”应列成两份投入方案，净属性仍需实际getter验证。

无免费次数且各步最新报价1000时，**未采用起点**的采用→降一处→升级计划合计3000虔诚。这是条件预算，不是本期实际跑过的一条三步账单。C2已经采用，采用费在那一支是沉没成本；R7实际只测了降级26再升级32，钱包4250→3250→2250，边际支出2000，各动作有独立冷却后读。免费行动是Faith共享的有限池；用掉一次也有机会成本。相同“五年”时长不能推出所有动作共用同一个决议冷却。[S01、S07–S10、H04]

如果目标还包括按有效稀有度放大的月虔诚，就要另外筹措合格圣物；不能把这一投入说成固定Faith项的统一前提。R7把237供奉到32，所有权从玩家转到圣地，Active false→true、有效稀有度0→4；它就不能同时作为玩家装备或另一站点的投入。之后合法撤回又实际花500虔诚，不能称作回滚。撤回预览还列出奉献损失及宗教狂热/少数族群封臣各−20好感、十年；本期未独立读回这些关系和奉献变化。宗教政治成本应进入比较，但不能把该撤回预览泛化为“采用一次就受同样惩罚”。[H05]

## 场景三：什么时候宁可新建在自己的腹地

若目标是个人学习和长期建设，把类型放到玩家实际持有的县可能比给封臣的地方项更贴合目标。R8在Samarra的barony6622新建普通`site_of_wisdom`326，独立证据确认玩家为县主、Active true、有效稀有度4，237归圣地所有；实际钱包3250→1250。它付了2000，也占用了圣物和网络资源，不能只拿“2点学习”与采用费1000作无条件比较。[H03]

智慧类型的县主定义是学习+2；有效稀有度4时，伯爵领定义为金币/威望/虔诚建造费各−4%，`development_growth=+0.04`是**增长加法**，不是发展增长倍率+4%。该站点仍是普通，所以全Faith学习/外交生活方式经验各+4%的主要块不能因此领取。实际净学习、发展、建造价格和全Faith修正都还未后读；新建当前合法性、王国/容量约束、免费次数和创建锁也必须当场读。[S02、S04、S09、H03]

若日后要在纳杰夫主要与智慧主要之间选一个，二者的“每奉献等级外交+1”原始类型项相同，换位不会再多一份这项外交。真正要比较的是失去纳杰夫教士好感+5和按稀有度放大的月虔诚，换取智慧的两类生活方式经验，以及各自所在地和圣物条件；这是条件式源系数比较，不是本期实际净差值。[S03 856–863、S04 87–94]

更不能把这次新建解释成“解锁萨迈拉大清真寺”。那座建筑的宗教条件是伊斯兰/与伊斯兰融合 **OR** 地产持有人Faith的圣地；对已经满足伊斯兰分支的Sunni地产持有人，新建圣地不是满足这个分支的必要条件。本期也没测该建筑是否存在或启用。相反，伊玛目阿里清真寺是“持有人Faith圣地 **AND** 伊斯兰/融合”；若已建且只缺前者，采用才可能补上所需关联。仍要用建筑自己的实际持有人和启用后读确认。[S05 983–991、1306–1330]

若新建是为了朝圣，还应先核首都：**如果**萨迈拉仍是该地主持人的当前首都，普通朝圣会受首都排除；智慧圣地也不能取代Hajj的麦加。本文没有读取当前首都，没有执行朝圣。R8先弃用32后创建326是实际实验路径，不证明弃用是创建的必要条件。[S06、H03]

## 给游玩智能体的使用顺序

1. 先写目标和受益者；分别读县主、地产/建筑持有人、barony holder和玩家的Faith/身份。核对已有Faith名单，先排除重复采用。
2. 列出已有站点管理、采用、新建和保留资源的候选，计算完整后续链及被降级站点/圣物原用途的损失。未知收益保留unknown，不能记成0，也不能预支成已实现收益。
3. 保持原生AI候选、GUI过滤、脚本资格和最终原生Can/报价分层。原版AI会保留一个站点名额给玩家，其兼容性候选权重不是收益最优化证明。每个动作提交前都需新鲜normalCan、bypass0、资源和相关冷却；不提交disabled动作。
4. 一次提交后读独立世界状态：Faith关联/等级、钱包、当前Active/rarity、完整圣物owner/槽位、实际受益者/修正及本动作冷却。ACK、pending或创建窗口重置不算收益已实现，也不授权重复提交。
