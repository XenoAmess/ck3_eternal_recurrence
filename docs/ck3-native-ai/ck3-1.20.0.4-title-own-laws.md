# CK3 1.20.0.4 physical title own-law query

This capability observes the ordered law array owned by one complete TitleID.
It does not evaluate `has_title_law`, the realm law, or the title's effective
inheritance policy. Its immediate use is to distinguish RMTM's observed
`has_title_law = false` from an unobserved physical title-law collection.

The public MCP entry is `ck3_query_title_own_laws_v1(title_id,
expected_revision)`. The unsigned TitleID retains all generation bits; values
from 0 through 4294967294 are valid selectors, while 4294967295 is absent.
Both arguments are strict integers. The corresponding typed native step is
`query-title-own-laws-v1-<canonical unsigned decimal TitleID>`.

The route runs through the existing semantic worker mailbox on the owning game
thread. The public revision must match a current, paused, living-player frame.
The provider samples the core player/date/speed identity before and after the
physical law read, resolves the current player's complete CharacterID again,
and resolves the requested complete TitleID again. Failure clears all optional
law fields. The array reader independently captures all law rows twice and
compares title identity, holder raw reference, array header, ordered law
pointers, law definition IDs, full string headers, and complete keys.

The `title_own_laws` result uses schema `xar.ck3.title-own-laws.v1` and returns
exact game version and executable SHA, revision, date, current actor, full
TitleID, `available`, and `unavailable_reason`. An available result includes
`native_law_count`, ordered `laws` containing `native_definition_id` and `key`,
and `single_heir_member`, derived from the complete key
`single_heir_succession_law`. An empty physical array is available with count
0, `laws: []`, and member false. An unavailable result has null law fields and
a reason. No typed title-holder identity is inferred.

The implementation reuses `ck3_12003::title_properties::BindImage`'s existing
actual .4 selection and `ck3_12003::title_laws::Read`. The actual .4 title and
law vtables are 0x4712A28 and 0x48B88A8. It accepts at most 256 laws; each full
ASCII key has fewer than 256 bytes. The old Faith-specific selector, its
temporal-head membership field, and the Faith graph opt-ins remain separate.
Linking the shared physical leaves does not enable Faith capabilities.

Source basis: the finite AddTitleLaw chain shows that a successful insertion
can be followed by a callback that removes an own-law row when the engine
considers it equivalent to the realm inheritance baseline. R10 hitting that
path, and the exact semantics of its script trigger, remain unproven. Sources:
`C:/workspace/ck3-upgrade-20261007/rmtm-add-title-law-static-tail-01/ADDTITLELAW-FINITE-SOURCE-CAUSAL-CHAIN-24.json`
and `RMTM-MINIMUM-OWN-LAW-OBSERVATION-SOURCE-CARD-25.md` in the same directory.

Validation is limited to the new contract, strict MCP input, provider fake
memory, and its real affected native compilation graph. No game qualification
or RMTM business pass is implied. A later current .4 managed scene must consume
the new DLL and independently bind the desired title before interpreting the
physical rows. RMTM's existing law-and-heir acceptance condition is unchanged.
