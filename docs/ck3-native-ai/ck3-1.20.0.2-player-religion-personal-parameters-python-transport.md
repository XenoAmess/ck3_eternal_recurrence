## 实际 wire 与完整性

[portable full wire](../../research/religion_doctrine12002_personal_parameters_mailbox_wire_fixtures.json) 的 inner key 是 `player_religion_personal_parameters`，schema 为 `ck3_12002_character_personal_parameters_v1`。实际字段为 `schema`、`game_version`、`executable_sha256`、`source`、`available`、`unavailable_reason`、`capture_epoch`、`date_raw`、`played_character_id`、`has_character_extension`、`supported_keys_complete`、`personal_parameters_complete`、`personal_tenet_keys`、`parameters`。source 固定为 `character_personal_tenets`；每个 parameter 是 `{key, value}`，value 保留真正的 JSON Boolean，包括 `false`。

`parameters` 发布完整原生 supported registry 中每个 key 的个人 Tenet 最终 Boolean。被列出的 key 值为 false，表示该 key 受支持，而当前实际 owned personal Tenet 不满足其条件；不能过滤 false 只留下 true。只有在 registry 读取成功且 `supported_keys_complete=true` 时，未列出的 key 才可解释为 **unsupported**；不能把它当成 known false，也不能在 registry 读取失败时声称 unsupported。本 API 没有返回额外的 per-key unsupported DTO，消费者须按完整 registry 判断。实际样例中的 key 数量只属于 fixture，不是 CK3 或 mod 的固定数量契约。

| 实际响应 | 状态与含义 |
| --- | --- |
| `personal-true-and-known-missing.json` | observed；完整 supported registry，个人条件满足为 true，不满足为 false；保留 actual personal Tenet keys |
| `extension-absent.json` | observed；`has_character_extension=false`，两个 completeness flags 为 true，个人 Tenet list 为空，每个支持 key 均为 false |
| `empty-owned-tenets.json` | observed；`has_character_extension=true`，两个 completeness flags 为 true，actual owned list 为空，每个支持 key 均为 false |
| `database-unavailable.json` | unavailable；reason `parameter_registry_unavailable`，两个 completeness flags 为 false；空 lists 和 extension=false 是失败 reset，不能解释为已知空/真实 extension absent |
| `state-changed.json` | unavailable；reason `state_changed`，两个 completeness flags 为 false；保留本次 owner actor/date/epoch，不把失败值写成 known false |

个人参数不依赖 Rite/Faith getter。原生 extension absent 的 all-false 语义来自 Character trigger 的真实分支，不是从 Rite cache 推断；有 extension 时只读实际 owned personal Tenet definitions。Doctrine authored personal 字段与 Fulfillment 参数不属于本 capability 的 completeness 范围，也不能据此宣称最终互动合法性、接受度、费用或结果已可用。
