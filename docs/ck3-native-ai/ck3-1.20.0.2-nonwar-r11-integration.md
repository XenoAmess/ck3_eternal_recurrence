# CK3 1.20.0.2 R11：Sway 材料意见只读查询

本批发布已经闭合的 `ReadSwayOutcomeOpinionV1`，让 M4/M6 能实际取得目标对玩家的总意见及 Sway 专用 modifier。它填补现有 producer 没有共享 dispatcher 调用的消费缺口。本批只接这一项只读功能，不改变谋略启动、重定向、事件选项或战争路径。

游戏版本固定为 `1.20.0.2`，EXE SHA-256 为 `AE1BA6FF060BA603842F6F4A2DED0AF4B7D3666B3DD271F75FB01B0DA8E81B2D`。原生输入与测量语义继续使用 [Sway outcome 专题](ck3-1.20.0.2-sway-outcome.md) 和 [gift opinion 来源](ck3-1.20.0.2-gift-opinion.md)。既有 R9 产物及运行中的冻结 runtime 不变；本批后台构建和冻结记录在 `artifacts/g2-offline-2026-10-01/nonwar-integration-r11/`。

## 真实接口与中央接线

| 项目 | 本批值 |
| --- | --- |
| 唯一 selector | `query-sway-outcome-opinion-v1-private` |
| 默认关闭的 build flag | `XAR_CK3_ENABLE_G2_ACTIVE_SCHEME_SWAY_OUTCOME_OPINION_PRIVATE_QUERY_V1` |
| 新独立 owner 许可 | `permitted_executor_sway_outcome_opinion12002` |
| executors 成员 | `sway_outcome_opinion` |
| 既有 owning callback | `ExecuteSwayOutcomeMailboxV1` |
| 既有 handler | `HandleSwayOutcomeEventV1` 的 `opinion_only` 路径 |
| DTO | `result.sway_outcome_opinion`，schema `xar.ck3.sway-outcome-opinion-v1` |

请求保留现有三个整数：正数 `expected_revision`、玩家 `actor_character_id` 和不同的 `target_character_id`。中央 worker 使用现有 `JsonUnsignedField` 读取 revision，符合领域 handler 的原始请求语义。共享 router 只匹配 `kSwayOutcomeOpinionStepV1` 并转发原始 payload，没有新增 API 别名或复制 reader。`query-sway-outcome-event-v1-private` 不在本批注册集合内。

`MainThreadQueryInstallEnvironmentV1` 与 runtime 均增加新 callback identity，既有 install 实际复制此字段，owner admission 实际识别它；`NonwarMailboxExecutorsV1` 与默认关闭的登记对应同一 `ExecuteSwayOutcomeMailboxV1`。领域 context 继续使用真正的 `QueryMailboxEnvelope`，在 application owning thread 上进入、读取并核对同一 paused frame，然后 Finish、wait/reclaim 和输出完整 `command_result`。

CMake 对 `ck3_12002_sway_outcome` 系列作明确选择：只有新 flag 启用时才登记已经 READY 的 `ck3_12002_sway_outcome.cpp` 与 `ck3_12002_sway_outcome_mailbox.cpp`；fixture source 不进入 DLL。其他已经使用的 core、gift opinion、event-window、semantic adapter、protocol 和 mailbox 来源保持各自真实绑定。这里没有新增 packet serializer translation unit，完整意见响应由现有 `SerializeSwayOutcomeOpinionResponseV1` 提供。

## 材料含义

查询独立读取 `target_opinion_of_actor`、`scheme_sway_opinion` 和 `sway_blocker_opinion`。每个 modifier 的 `observed`、`present` 与 nullable `value` 分开保留：真实存在且为零，和真实不存在是两种状态。事件已消耗后仍可读取这项材料；读数不要求当前事件窗口存在。

总意见并不替代 Sway 专用 modifier 的原生阈值输入。读到某个 modifier、总意见改变或某实例消失，都不单独证明某一 phase、隐藏消息或事件选项造成该效果，也不表示实例终结。与先前 exact actor/target/instance 意图及其他结果来源的关联，由实际 consumer 单独完成。

## 最小必要验证与冻结

原有 exact-build ABI 与 provider/library 矩阵直接复用。本批只补发布链路缺少的证明：中央注册 OFF/ON 两配置只执行新 callback 的 0/1 次，旧 callback 实际执行次数为零；router probe 只检查唯一意见 selector、原始 actor/target/revision payload、对象 identity、完整输出和未注册的事件 selector。

领域新增一项 O2 `/W4 /WX` 实际 owning-envelope → independent native provider → full response 场景，保留事件已消耗后的 present-zero / absent 样本。新的专用 named identity 由其实际队列或中央注册的独立证明覆盖。Python 使用这些完整生产 packet 验证原有 parser/cache/Driver/官方 MCP；不重复原生旧矩阵。

双配置 DLL/injector 用 `tools/run_native_msvc.py` 与 `--jobs 64` 构建。root 作为唯一 Git 写者提交冻结源码后，记录当前实际 compiler dependency graph 的 Git 状态，并对已完成构建作一次 metadata-only FINAL 冻结。最终 manifest 记录 configured flags、实际 target source selection、build/source HEAD、binary SHA 与现有必要证据。

后台接线只能标记 `static-ready`。本批不触碰 CK3、pipe、桌面或运行中的 DLL；root 使用独立冻结 runtime 做 paused 实机读取后，才可为实际观测授予相应 live primitive 资格，不能用 schema、ACK 或 fixture 宣称完整 Sway OODA 已完成。
