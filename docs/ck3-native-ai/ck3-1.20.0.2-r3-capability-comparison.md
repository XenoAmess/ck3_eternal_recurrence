## 最有价值的剩余执行入口

以下是给协调者的精确 MCP 工具/参数名。`R` 每次取新的公开 snapshot revision；`A/B` 为当前完整公共 CUnitID，`P` 为实际目标省；`C/S` 分别为真实 CombatID/SiegeID；所有数字从新版响应取值，不能复制旧例子的 generation。日期、旧 full ID 和后置内容决定结果，ACK 或 revision 增长不算完成。

1. **pending P1–P4 已完成，复用结果。** [现有矩阵](events-and-pending-1.20.0.2-live-matrix.md) 与 attempt-14 已有完整 query/query/reply 或 ACK/旧 full ID 消失证据，不再重复这四格。后续生产 canary 真遇到 ordinary I 时，入口仍为 `ck3_query_pending_character_interaction_context_v1(pending_interaction_id=I, expected_revision=R)`，按当前原生判定与已实现 policy 调用 `ck3_reply_pending_character_interaction(accept=true/false, interaction_instance_id=I, expected_revision=R)` 或固定 `ck3_acknowledge_pending_character_interaction(interaction_instance_id=I, expected_revision=R)`；通用语义和 stock 长跑按原有未完成边界保留。

2. **title-map 只补合法 missing key。** 正向、barony identity 与 repeat 的四次完整相机回读已通过，不重跑。下一暂停地图仅调用 `ck3_center_map_on_landed_title_v1(title_key="c_xar_m120_missing_title", expected_revision=R)`，应得到 native `title_key_not_found` 且相机不变。此前 `xar_m120_missing_title` 缺 tier prefix，Python 正确拒绝且没有 native request，不能作为此 negative。此工具 explicit-only，不要求加入 planner。

3. **军队原子变更 + 路线/到达。** 从 [既有 military 请求生成器](../../artifacts/migrations/2026-09-30/post-update-1.20.0.2/live-1.20.0.2/fixtures/military/prepare_requests.py) 用新 snapshot 生成：`ck3_execute_step(step="split-army-half-A", expected_revision=R)`→新 sibling B；`ck3_execute_step(step="merge-armies-A-with-B", expected_revision=R)`→B 消失且 A 合计兵力正确。再 `ck3_execute_step(step="preview-move-army-A-to-P", expected_revision=R)`，`ck3_move_army(army_id=A, target_province_id=P, expected_revision=R)`，用现有一日切片到达后 `ck3_disband_army(army_id=A, expected_revision=R)`。需要新军时调用 `ck3_raise_troops_default(expected_revision=R)`，观察真实新增/集结完成。军力用 `ck3_query_army_strengths(army_ids=[A,B], expected_revision=R)`，不从 snapshot 的 null soldiers 猜人数。

4. **宣战与真实围城。** `ck3_query_declarable_wars(expected_revision=R)`→从实际结果取 choice→`ck3_declare_war(declaration_id=D, expected_revision=R)`→新 WarID；旧版有真实新增 `16777290`，本版本必须取得自己的新 ID。沿 M04/M05 移到已观测 enemy objective，保存 active S、fort/garrison/work 与同 S 下一日 work。强攻开关属于高价值额外 smoke：仅在原生 can-start 为真时 `ck3_start_assault(siege_id=S, expected_revision=R)`，刷新再 `ck3_stop_assault(...)`，用 false→true→false 后置确认；不把该旧未验项说成 R3 必须恢复的旧能力。
