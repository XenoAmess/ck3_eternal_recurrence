## Sway 执行记录器的生命周期

记录器与 installer 是 bridge 的全局对象，随已 pin 的 DLL 存活。新版本 suspended startup 调用 `InstallSwayCompletionExecution12002`，三个真实 vtable slot 全部安装成功后才设置 attached。真实 native Execute 入口捕获 copied records 并转发原函数一次；查询通过 named owner callback 读取同一个记录器。worker 退出时调用 `UninstallSwayCompletionExecution12002` 恢复三个 slot。

记录仅证明当前 observer session 捕获了执行来源。历史未捕获、材料效果、scheme 终态与 OODA 成功仍是独立语义，不能用记录或安装 ACK 代替。当前 scheme 状态由第三批 completion 查询独立提供。

## 实际故障与必要增量

第二批实机宗教上下文为 `tag_unavailable`。所有者读回实际 Religion definition 后发现 CString 位于 definition `+0x18`，原绑定读取 `+0x28`，因而把 size/capacity/hash 当成字符串。本批领域叶修复保持 API/DTO 不变，具体来源、paused 证据与 fixture 记录在宗教上下文专题和独立修复 manifest。
