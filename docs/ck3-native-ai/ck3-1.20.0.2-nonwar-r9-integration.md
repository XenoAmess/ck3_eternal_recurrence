本批只新增 `query-player-religion-ai-reform-inputs-v1` 一个只读查询，并纳入 R8 实机已经暴露的 Construction 收入报价容量、Tenet 合法空槽和 Faction 查询 envelope 故障修复。R8 及更早 bundle 保持不可变；新构建、源冻结和报告统一位于 `artifacts/g2-offline-2026-10-01/nonwar-integration-r9/`。本专题记录后台接线，不授予实机或完整 OODA 资格。

游戏输入固定为 CK3 `1.20.0.2`，EXE SHA-256 为 `AE1BA6FF060BA603842F6F4A2DED0AF4B7D3666B3DD271F75FB01B0DA8E81B2D`。原生 provider 与必要修复都按此构建闭合；旧版路径继续保留各自版本绑定。

CMake 显式登记三个已经 READY 的生产来源：`religion_reform12002_schedule.cpp`、`religion_reform12002_ai_context.cpp`、`religion_reform12002_ai_inputs_mailbox.cpp`。读取动作只在既有 owning-thread paused frame 中发生，没有新增线程、scheduler 调用或改革操作。

组合观测先读取玩家角色对应的真实 AI holder table，再读取所有匹配的 ordinary / player-special controller 与每项 schedule inputs。合法没有 controller 时保留 `observed_no_ai`；controller 指针只用于当前 owner 的原生读取，不进入 wire。当前独立状态、缓存独立状态、缓存 government bit、active/special 原值、全局开关和 rare period 分开保留。`rare_countdown_prepare_ticks` 的单位是 prepare 调用次数，不能称为游戏天数或下一次改革时间。

`gate_inputs_observation_complete` 表示这些实际输入已经取得。native prediction、改革 score、最终合法性、controller 优先级及我方策略仍由各自来源证明，本查询不替它们作出结论。

## 本批实际故障修复

- Construction：真实可用的正收入报价超过旧容量 64，既有报价来源的容量改为 512，保全原生观察结果。只修改 root 已授权的现有叶，注册和动作语义不变。
- Tenet：R8 暂停实机的第三个 selected-definition 等于原生 default singleton `5D1F6C0`，是合法空槽。新 reader 识别这个 exact singleton，保留空 key 为 JSON `null`，而不把整个候选查询判成读取失败。其余来源、stride 和 native gates 沿用原路径。
- Faction：真实 SDK 接口要求既有八个 envelope keys 与 `player_faction_alerts_ready`。中央通用只读 formatter 曾输出额外 private metadata 并漏掉 readiness，导致 actual packet 被拒绝。只有 Faction 分支恢复该既有 wire shape，其余 domain envelope 保持自己的合同。

三个修复都由实机结果或覆盖生产路径的确定性复现触发；各自原始 RED 与必要新 fixture 保留在领域 artifact 中。它们不新增 query、flag 或自动动作。

## 验证与交付边界

`ai-inputs-native-source-only12.json` 引用已经冻结的 schedule / context 来源与组合 caller。组合 generic caller 的一次 O2 `/W4 /WX` 场景读取 multiple controllers 与合法 no-AI 两个请求；原始完整 packet 已用于实际 Driver/cache/官方 MCP 的一次 SDK 验证。这些来源矩阵和 SDK 结果直接复用。

本批中央登记测试只执行新 AI callback 的 OFF/ON 两配置，旧 callback 的实际执行次数为零；router probe 只验证新 selector、原始 revision payload 与真实 owning handler 的转发。新 named caller 只复用同输入的一场 O2 场景，清空 generic 与其他许可，执行实际 submit → owner drain → provider → Finish → wait/reclaim → full formatter，并与冻结 generic 的 packet 比较。历史 generic/provider main 不重复运行。

双配置 DLL/injector 使用 `tools/run_native_msvc.py` 与 `--jobs64`。最终 `integration-build-manifest.json` 保留实际 configured flags、target source selection、binary SHA 和 build source HEAD；root 提交后按当前 compiler dependency graph 记录实际输入的 Git 状态，再作 metadata-only FINAL 冻结。纯汇总不会再次运行 EXE、旧矩阵或 CTest。

所有后台证据最多授予 `static-ready`。新的 AI 输入查询与受影响故障修复仍需 root 在独立冻结 runtime 中做 paused 实机观察；ACK、fixture 或输入完整性不替代实际改革结果，也不表示完整观察 → 决策 → 操作 → 验证循环已经完成。
