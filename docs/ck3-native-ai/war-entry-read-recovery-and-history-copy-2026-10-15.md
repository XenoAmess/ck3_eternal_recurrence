# War-entry read recovery and finite query snapshots (2026-10-15)

An exact Native typed war-entry query may return `application-main typed query failed or its snapshot changed` after its request is sent. The ordinary turn now classifies only the fully bound `typed_query_failure_v1` response as `readonly_rejected`. It preserves the request ID, step, source frame and failed native result, awards no gameplay or time credit, and never resends that request. Replanning waits for a fresh paused frame with the same actor, episode, bridge PID and connection generation. Only the failed target is suppressed for seven game days; other observed targets remain eligible for read-only assessment, while missing power never authorizes a declaration.

The pure war-entry and declarable-war queries now use the existing history-free snapshot reader for their pre/post frame checks and primitive submission. A normal war-entry read previously made five complete `command_history` deep copies; a declarable-war read made three, and collection of a retained declarable result made two. The snapshot still carries semantic state, rollback failures, public/native revisions, actor, episode, connection and target scope. The actual `declare-war` business branch retains its full-history snapshots and default primitive behavior.

P11 completed Auto receipts show 664 successful war-entry reads with a 5.86 s median and 211 declarable reads with a 12.38 s median. The closed P11 Driver state had 7,531 history rows occupying 79,604,097 of 79,606,746 JSON bytes. An older immutable 33.49 MB Driver fixture measured a 0.499 s median for one in-memory history deep copy across nine samples; this is component evidence, not a P13 live speedup claim. Full native-query wall time includes Native work and transport. The war-results-window and campaign-root query paths already use semantic or finite snapshots and need no matching history-copy change.

Focused tests cover exact and mutated typed failures, fresh-frame cooldown binding, alternative target selection, no history export during pure queries, unchanged public result/history, invalid frame rejection, late-result collection and the declaration branch's full-history read. The external P12-based patch and immutable benchmark are recorded in `D:/codex-ck3-demos/2026-10-14-robert-30year/p12-war-entry-history-free01/review-report.json` and `D:/codex-ck3-demos/2026-10-14-robert-30year/p11-performance-review01/immutable-history-copy-bench.json`. P13 live latency must be compared against the same query stages before claiming realized speedup.
