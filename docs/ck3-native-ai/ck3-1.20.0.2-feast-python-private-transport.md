# Feast private transport 的 1.20.0.2 绑定

2026-10-01 的后台迁移复用既有 Feast 的 private 请求、native DTO 和 envelope。Python 返回值新增 `exact_ck3_build`；1.20.0.2 同时返回 `exe_sha256`。两者取自发出请求前同一 semantic snapshot 的 `diagnostics.hello`，通过 `bridge/nonwar_private_build.py` 的既有 exact-build resolver 解析，不从 C++ namespace、旧文档文件名或成功 ACK 推断版本。

1.20.0.2 的绑定是 `AE1BA6FF060BA603842F6F4A2DED0AF4B7D3666B3DD271F75FB01B0DA8E81B2D`。无 hello 的历史输入沿用 1.19.0.6，不能被标成新版；带 hello 的输入必须能解析为已冻结的 exact build。这是同一 private transport 的版本迁移，默认开关与发布能力表保持既有行为。

本次覆盖 planner diagnostic、Stage-5 gold/full cost、Start inputs、hosted post，以及 guest candidate、guest opinion、guest target、guest route proof、guest invitation rule 与 rule provenance。Start 提交的返回值仍是 `submitted_pending`；新增 build metadata 不改变资源数值、CanStart、guest qualification 或已有 formal policy。

```mermaid
flowchart LR
    H[同帧 snapshot hello] --> I[既有 exact build resolver]
    I --> Q[旧 private request / envelope]
    Q --> P[既有 native payload parser]
    P --> R[readback 加 build metadata]
    R --> F[既有 Feast formal consumer]
    F --> S[Start pending / hosted identity]
    S --> T[独立读取 native completed / invalidated]
    T -. unknown .-> G[真实收益数值与归因]
```

hosted identity 和资源扣减可以验证 Start 的提交结果，不能证明宴会已完成。新版原生 `CActivity+0x421` 的完成标志在 phase `on_end` 与 type `on_complete` effects 返回后置位；`+0x422` 是独立 invalidated 标志。新版 hosted rows 在实际观察到标志时增加 `terminal_flags_observed`、`native_completed` 和 `native_invalidated`，旧三字段身份行继续可读。Python 的 `bridge/activity_feast_terminal_outcome_v1.py` 只对保存的 ActivityID、host 与 `activity_feast` 身份归一化这个真实结果；缺行、旧行无标志和身份不符均保持 unknown。两个标志可以同时为 true，本次不假定互斥。

terminal 标志证明原生生命周期结果，不直接给出收益数值或归因。资源与 guest opinion 仍需分别观察；本次没有把活动从 manager 中消失解释为完成。旧 guest route/target 中尚未取得规则归属资格的值继续保持其原生观测结果，不借迁移放宽 Start。

离线验证：`tests/unit/test_ck3_12002_feast_wire.py` 的 5 项测试通过，实际 C++ full-cost reader/serializer 输出保留 gold `18500000`、piety `-100000`、barter goods 资源槽 `8` 与 `CanStart=false`；实际 hosted serializer 输出的 ongoing、completed、invalidated 三帧进入 Python transport 和 normalizer。原生输入使用离线 fixture，不是实机快照。另验证活动消失、旧身份行与未证明互斥的两标志组合不造成错误完成判定。受影响的 36 个既有 private transport tests 也通过。

命令为 `python -m unittest discover -s tests/unit -p test_ck3_12002_feast_wire.py` 与 `python -m unittest discover -s tests/unit -p test_activity_*private_transport.py`（工作目录 `ck3_autonomous_player`）。实际 JSON 在 `native_bridge/research/fixtures/ck3_12002_feast_fullcost_wire.json` 与 `ck3_12002_feast_hosted_post_wire.json`，对应 `.provenance.json` 保存 C++ 来源和离线边界。hosted fixture 使用逐字节摘出的 production serializer 与 Append helper blocks，payload 不是手写 JSON；它验证 wire 兼容，不替代同版本原生 reader 的实机结果。本工作包已达到 Python transport/normalizer 的 `static-ready`，未访问 CK3 进程、pipe、桌面或 Steam，没有新的 live artifact。

结果与源清单在 `artifacts/g2-offline-2026-10-01/feast-python/transport-result.json`。完整实机 lifecycle、实际收益、natural Start 与新的 PID 下的续接仍需后续实机窗口。
