## 实际迁移缺口与改动

新版 FAMILY provider 保留旧 DTO 字段，但 `current_first_heir_relationship`、观察到的继承人合法候选、候选联盟投影、指定玩家子女的 subject/value 以及私有 submit/receipt 输出仍硬写 `1.19.0.6`。当前婚约履行和 first-heir formal submit 还直接比较这个旧字串，因而不能消费已绑定新版原生实现的数据。

指定玩家子女的 default/matrilineal 路径共用 `player_child_matrilineal_private_action_v1.py`；它的 submit、later/cold result 和 alliance result 三个输出也改从同一 hello 派生身份。其全部 final legality、selected option、冷恢复及 material receipt 条件保持原样，成功的 native 响应才会发布这个 DTO，不会因此启用尚未安装的原生动作。

`bridge/nonwar_private_build.py` 从既有 `take_snapshot()['diagnostics']['hello']` 读取 `expected_ck3_version` / `expected_ck3_sha256`（保留 `game_version` / `executable_sha256` 的既有 fallback），复用 `bridge/version_identity.py` 的冻结 version/SHA 对。新版 DTO 发布 `exact_ck3_build` 与 `exe_sha256`；新版相邻查询与 submit 消费同一冻结身份。旧 1.19 的 version-only DTO 与没有 hello 的历史消费夹具仍保留原有合同，后者不能标成 1.20。原生代码复用的 `ck3_11906` value-type 命名空间不再被误当成 ABI 构建身份。

新版冻结身份：`1.20.0.2` / `AE1BA6FF060BA603842F6F4A2DED0AF4B7D3666B3DD271F75FB01B0DA8E81B2D`。来源是已迁移的 exact native adapter 及实际 provider，见 [FAMILY](ck3-1.20.0.2-family.md)、[生活方式](ck3-1.20.0.2-lifestyle.md)、[建设](ck3-1.20.0.2-construction.md) 与 [建设 submit ABI](construction-submit-1.20.0.2.md)。这里只改 private 合同和三个 formal 身份表达式；formal 默认 OFF、policy、质量条件及 JOINT 行为保持原有语义。原生指针/RVA 的迁移由各 native provider 完成。

建设的 authored-income 表按 actual hello 身份选择已验证构建。新版脚本静态提取证明原有 **19 个保守 tier-one 正收益 key 及数值全部相同**，因此沿用这 19 项，未扩到额外 203 项正收益列表。新版 `00_standard_economy_buildings.txt` SHA 为 `33A6253E89ACD0DA1C0242BD441987817DC5386325694F92BBE635F657FBD0E8`，`00_building_values.txt` SHA 为 `F436F7D9D5AC5506B38D715F0CE02C4F4257EEF3ADDF56597C18A526A6F66825`。冻结提取在 `native_bridge/research/ck3_12002_construction_authored_income.json`。有效费用始终取当前 native `cost_raw_native`，没有把旧 R0406 的 180 gold 或新版 authored base 150 gold 当成游戏中有效费用。
