# Native normal-exit admission for the public continue launch

The production normal-exit source verifier now accepts the public launcher's exact `-continuelastsave` argument. It continues to reject duplicate modes, simultaneous `-loadsave` and continue modes in either order, unknown flags and invalid userdir/save-key forms. Argument count, executable identity, source inventory, GUI namespace and file census checks are unchanged. The change adds one local parser boolean; no header, ABI, MCP or action schema changes.

The trigger was the [independent MTS R22 report](https://github.com/XenoAmess/ck3_mod_more_tenant_slots/blob/9fb204154ffbbe40fdac1bdf290ab7764ec21038/docs/native-main-r22-2026-10-16.md), machine `bf-202609141645-5434332d4d`, exact CK3 1.20.0.4 / EXE `98702f88a547cde2eaf29a85f93b85f68ee4cf8148336a4f7afaeb75319dd518`. Its retained process had four actual arguments: executable, `-gdpr-compliant`, absolute `-userdir=...`, `-continuelastsave`. Native `query_context` returned `actual_launch_userdir_contract_unsupported` without consuming a claim or stage. The parser rejected that final unknown argument before any inventory check; this was not evidence of an invalid GUI source inventory. R20's explicit `-loadsave` native qualification retains its original scope.

The existing `normal_exit_map_launch_arguments_v1_test` now covers the continue mode's parsed values and real Win32 `CommandLineToArgvW` decoding, including the executable path with spaces. It also checks reordered/debug continue, duplicate continue, both mixed-mode orders and malformed attached/split values. Existing explicit-loadsave, no-save-key, executable identity and output-unchanged-on-reject cases remain.

[Actual offline qualification](qualification/native-normal-exit-continue-argv-20261016.json): **40 argument cases and 7 executable-identity cases PASS**. Two translation units compiled once, then one small fixture EXE linked and ran; all four actual process exits were 0. The build reused the previously qualified runtime archive and frozen headers. No DLL or whole native matrix was built, no game was started and immutable runtime007 was not modified. The fixture's owned output namespace was about 1.96 MB against a 64 MiB estimate. Win32 argument parsing has no CK3 script/finite-runtime semantics, so `open_kaishek` was not applicable.

Defender remains a separate **RED**: this new exact fixture EXE's administrative WMI `Add ExclusionPath` failed with COM general failure (`-2147217407`); `partial_mutation=false`, no successful registration/readback and no repeated Add. Its original receipt is pinned. Actual fixture execution returned 0; that does not turn the settings failure into success or qualify live native Quit.

This source package is reusable across products, while the private save, screenshots, allocation and detailed business evidence stay in the independent product. MTS R22 used the existing official GUI fallback after recording the native gap, then independently obtained retained OS0/native process_exit0/full cleanup. Its original host RED/exit1 from a different protected readonly-query failure remains separate from scoped business and normal-close PASS.

Deployment is deliberately separate: runtime007 still contains its old parser. The next MTS COLD uses that unchanged runtime's supported explicit `-loadsave` route. Future adoption needs an explicit narrow successor and actual native context/stage/OS0 qualification; the offline parser pass does not grant fresh-game native Quit or any product PASS.
