the intended launch path in source, **not that CK3 accepted the argument or
finished loading the save**. A bridge heartbeat with date zero and no paused
gameplay state is consistent with pregame/front-end operation, but does not
identify the page or the reason the map did not become available.

only a successful native route response may name `main_menu`, `bookmarks`, or
another page. This diagnostic is default off, does not submit any of the six
target queries after a readiness timeout, and never changes the RED result or
the date/action hold. `open_kaishek` cannot answer a pregame CK3 process/window
readiness question, so its deterministic subset is **not applicable** here.
