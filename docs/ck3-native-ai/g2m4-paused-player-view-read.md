# G2-M4 受控 paused 玩家建设视图读取

状态：**static-ready；尚无同版本真实 paused result；不注册、不广告建设。** 本包只给当前 CK3 操作负责人在现有 `NativeHeadlessGameplayDriver` Python 进程内读取一帧。DLL 是 named-pipe 单客户端，另开查询进程会争用当前 server；`native_session` 对外队列也没有私有 query 命令。读取函数在 `ck3_autonomous_player/native_bridge/research/run_g2m4_paused_player_view_read.py`，入口为 `run_owned_paused_player_view_read(existing_driver, frozen_manifest, artifact_path)`。它只发两次 `execute_step` 只读帧，先正式 `query-campaign-root-context-v1`，后私有 `g2_player_construction_view_probe_v1`；每次默认最多等 12 秒，超时保留 request ID 在 artifact，不重发。函数不构造 driver、不启动 CK3、不点击 GUI、不推进日期。

受控资格清单：

1. 当前负责人在持有 CK3 独占轮次时，用已冻结的普通 production 标准封建和平 source save/独立 seed；记录 `candidate_id`、`round_id`、seed、存档/CK3 EXE/DLL 实际路径与 SHA-256、agent commit、DLC/mod 加载顺序和配置。CK3 exact EXE SHA-256 必须为 `2D00FF3101EF70B566F2FCBAE292F09263199C80E9DC8F139B82D7D96F83DB86`。已构建、私有选项 ON 的 Debug DLL 是 `Z:\tmp\g2m4-private-view-probe-build\debug\xar_ck3_bridge.dll`（SHA-256 `83722F12D10FC77E1A4E6D99CF45633251F8EEFAC9E96E6A62530DAEE655AD0A`）；Release DLL 是同目录的 `release\xar_ck3_bridge.dll`（SHA-256 `501E73D697E4DB8151296BA75DE68788BA0C6A1A020B5F76EDD0D00C6BFCF8B6`）。这些二进制是受控查询候选，不是生产建设能力。
2. 起始 native snapshot 必须 `paused=true`、`map_ready=true`、played actor 为活人、没有 active war、没有残留玩家军队、没有 active event/pending interaction。R639/R694 的 WarID 16777290 场景不合格，不能因该场景查询失败而宣称标准封建和平建设已 RED。
3. 正式 campaign-root result 必须 `status=available`、同 `native_revision`/日期、`player_character_id` 等于 played actor、`government.key=feudal_government`、至少一项 held county title、capital province identity 非空，且 provenance EXE SHA 与冻结 EXE 一致。exact collector 在 [`campaign_root_context_v1.cpp`](../../ck3_autonomous_player/native_bridge/src/campaign_root_context_v1.cpp) 739–772 行逐项验证 held title holder = player 才输出可用 partition；这是所持 county 的 holder 证明。它没有输出 capital province 的独立 holder，因此该字段仍是**未观测**，不能被这次 read 冒充通过。
4. 两次只读结果前、中、后的 paused frame binding 必须一致。私有结果需要 `advertised=false`、`failure=none`、`view_present=true`、`executor_invocations=1`，cache count/status/capacity 一致。`view_candidate_cache_present` 可以进入 typed row、成本、原生最终 `CanConstruct` 读取；`view_candidate_cache_empty` 立即走已定位的 player model/holding definition enumerator 施工，**不是没有合法建设**。`unavailable`、native rejection、超时、未执行分别保留原始 frame 和分类。
5. CK3 1.19.0.6 原版 window_county_view.gui 的窗口运行名是 holding_view，HUD 与地图入口也以该名字打开视图。当前私有 query 在同一次 application-main mailbox 执行中通过 ResolveNamedGuiWidgetV1 固定解析这个名字，再通过 ReadGuiWidgetRuntimeV1 读 vtable、运行名与 effective-visible flags；只有解析到同名、可读的 widget 才输出 available 和 effective_visible=true/false。widget 未实例化、解析或读取失败均输出 unavailable，不能把空指针当成视图关闭。结果的 snapshot_revision/date_raw 必须与 owner 的 paused frame 一致；持久 paused-player-view-read.json 保存 typed receipt 和原始 command frame。只有同帧 available/false 可称 closed-view cache 分支；available/true 是 open-view scene，unavailable 保持 closed_view_evidence_insufficient。runner 的桌面截图只作诊断，不作可见性结论。旧 c31886f0 DLL/候选被冻结，仍没有这个新 receipt；新代码必须重建明确版本的新私有候选并实机验证，不能沿用旧 DLL SHA 声称已通过。

本读取只关玩家成本观测的下一分叉，**不**证明建设动作、物质建设后置结果、下一 turn 消费或 cold restore。预览/M4 治理闭环在这些实机证据前保持未通过。与原生建设决策树、exact ABI 和成本输入的关系见 [`domain-construction-ai.md`](domain-construction-ai.md)；不使用 AI-only construction 结果充当玩家合法性。
