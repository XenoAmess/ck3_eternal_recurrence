## 普通 Robert 入口与业务玩家必须分两层

Start 前仍只选普通 **1066-09-15 Robert**。必须保留实际原生 selected-model 读回：`bm_1066_rags_to_riches`、`bookmark_rags_to_riches_duke_robert`、`feudal_government`、原生 bookmark 起始日期，随后只提交一次 Start。GUI 重复控件名或 setter ACK 不能替代该读回。

Start 后夹具会合法切玩家：

- **RMTM**：初始 `random_player` 的 ROOT 是 Robert；`rqa_initialize_effect` 在 ROOT 写 `rqa_fixture_initialized`，预检 AI 宋帝 `character:han_8052` 后切到宋帝。public driver 再次 `random_player` 时已经进入宋帝业务身份。续跑时又先切到当时真实的 Later heir，再杀 predecessor，并在实际继承事务后检查相同 title/realm/ministry 对象。
- **Ox**：初始 Robert 只提供一次真正开局入口。`oxa_initialize_effect` 预检仍为 AI 的神罗皇帝 `character:1316`、配偶和 royal court/champion 条件；初始化及 decline phase 标记写入该目标，然后切为该皇帝。

这两个脚本 history reference 不能直接当作 bridge public CharacterID。地图后必须从新鲜 snapshot 和同 revision 的 campaign root 取得当前 player、date、government、primary title；RMTM 首个未推进日期的业务角色持 `h_china` 且为 celestial，Ox 持 `e_hre` 且为 feudal。RMTM 后续再切继承人时重新绑定实际 ID。没有把 AUB 的地图后 `player=29829` 条件用于这两个计划。

源码确认当前通用 selected-bookmark Start normalizer 的地图后条件是 **同帧玩家/日期和 feudal government**，并没有 numeric29829 或 Calabria 检查。它会拒绝合法切为 celestial 的 RMTM；Ox HRE 仍为 feudal，满足这一项也不能证明地图后还是 Robert。执行者需要把已经存在的 native model/select/Start 原语的 Start 前身份收据，与夹具后业务身份读回分别绑定。不能笼统关闭身份验证，也不能把地图后新玩家当作普通入口的反证。
