## 静态 ABI 与实现

[候选扫描器](../ck3_autonomous_player/native_bridge/research/compare_build_anchors.py)读取旧 manifest 的 163 个签名和 6 个主线程入口，屏蔽 RIP displacement / 直接跳转与 call 的相对立即数，保留字段偏移。结果为 **64 个唯一候选、105 个未闭合入口**；唯一匹配不自动变成 runtime binding。

人工审阅后冻结的 [新版基础 ABI](../ck3_autonomous_player/native_bridge/research/ck3_1_20_0_2_foundation.json)包含 **12 个精确唯一签名、6 个 RTTI/vtable 前缀、18 个指令语义检查**：

| 基础项 | 新 RVA / 布局 | 静态依据 |
|---|---|---|
| Jomini global / local player getter | `0x5C6A520` / `0x383E2B0` | pause UI 和命令路径；getter 使用 players `+0x18`、local ID `+0x1F0`、Player ID `+0x70`。 |
| 日期 / 速度 / 暂停字段 | GameState 低 int32 `+0x08` / int32 `+0x70`；Jomini byte `+0x20` | constructor/read、speed/pause setter 与 UI。公开速度仍为 native 0–4 加 1。 |
| pause vtable | primary `0x476C898`，secondary `0x476C868` | RTTI COL secondary object offset `0x18` 与 UI 写入一致。 |
| speed vtable | primary `0x476C708`，secondary `0x476C640` | RTTI 和 UI 构造一致。 |
| 时间命令 | size `0x28`；flags `+0x08`、secondary vptr `+0x18`、value `+0x20`、pause byte `+0x24` | pause flags=8，speed flags=0；pause/resume 为同对象的不同目标值。 |
| SDL pump / PeekMessageW | `0x40D93F0`；call `0x40D942C` / return `0x40D9432`；IAT `0x43DAE38` | 指令链与 USER32 import 双证据。 |
| 主线程 TLS | wrapper `0x3E14690`、flag `0x5CBE6BF`、getter `0x3F784C0`、marker `+0x20` | wrapper 先检查 flag/getter/marker，再进入事件 body；尚未接入新 runtime hook。 |

**提交入口发生实际变化。** 新 UI 以 `RCX=command`、`EDX=7` 调用 `0x9E16B0`，通过 vslot `+0x40` clone，再自行读取 manager `0x5CC1240`、调用队列 `0x37F06F0`。旧 `SubmitCommand(manager, command, flags)` 参数排列不适用于这个新 UI wrapper。它在 queue call 后继续销毁临时对象，没有旧 manifest 中显式保存并返回 queue bool 的模式；返回契约和失败语义仍待闭合，不能把 AL 当可靠成功结果。

CGameState constructor 新入口为 `0x229A5F0`，栈帧改变，并分配 **`0x36780` bytes** 的 game data。`+0xA0` 指针仍存在，内部 manager/storage 布局尚未迁移。

[ck3_12002.hpp](../ck3_autonomous_player/native_bridge/include/xar_bridge/ck3_12002.hpp) / [ck3_12002.cpp](../ck3_autonomous_player/native_bridge/src/ck3_12002.cpp)新增独立基础模块：解码调用方持有的 clock/PlayerID 字节副本，构造 pause/resume、set-speed 对象。没有旧版头文件依赖、进程读取或命令提交。CMake 仅增加离线测试 target，正式 DLL 与 registry 尚未启用新版 gameplay。
