## 初期冻结与基础 ABI

[候选扫描器](../ck3_autonomous_player/native_bridge/research/compare_build_anchors.py)读取旧 manifest 的 163 个签名和 6 个主线程入口，屏蔽 RIP displacement / 直接跳转与 call 的相对立即数，保留字段偏移。结果为 **64 个唯一候选、105 个未闭合入口**；唯一匹配不自动变成 runtime binding。

人工审阅后冻结的 [新版基础 ABI](../ck3_autonomous_player/native_bridge/research/ck3_1_20_0_2_foundation.json)当前包含 **17 个精确唯一签名、7 个 RTTI/vtable 前缀、34 个指令语义检查**（首批为 12/6/18；10 月 1 日追加角色绑定）：

| 基础项 | 新 RVA / 布局 | 静态依据 |
|---|---|---|
| Jomini global / local player getter | `0x5C6A520` / `0x383E2B0` | pause UI 和命令路径；getter 使用 players `+0x18`、local ID `+0x1F0`、Player ID `+0x70`。 |

**提交入口发生实际变化。** 新 UI 以 `RCX=command`、`EDX=7` 调用 `0x9E16B0`，通过 vslot `+0x40` clone，再使用嵌入式 manager `image_base+0x5CC1240`、调用队列 `0x37F06F0`。旧 `SubmitCommand(manager, command, flags)` 参数排列不适用于新 UI wrapper，wrapper 也没有保留 queue bool。迁移代码直接使用已闭合的 owning queue `bool(manager, void** owned, flags)`，接受和拒绝路径都交由原生消费 clone；原件按原生 deleting destructor 清理。详见 [命令迁移](ck3-native-ai/ck3-1.20.0.2-command-runtime.md)。

CGameState constructor 新入口为 `0x229A5F0`，栈帧改变，并分配 **`0x36780` bytes** 的 game data。`+0xA0` 指针仍存在；各 manager/storage 按领域重新定位，不复用旧版地址。

[ck3_12002.hpp](../ck3_autonomous_player/native_bridge/include/xar_bridge/ck3_12002.hpp) / [ck3_12002.cpp](../ck3_autonomous_player/native_bridge/src/ck3_12002.cpp)为基础模块：clock/PlayerID 解码、时间命令构造、exact-SHA `BindCoreImage` 和 `ReadCoreSnapshot`。它已作为完整 adapter 的输入编入生产 DLL；本轮执行仍仅使用 fixture 自有对象和磁盘地址计算。

`CoreSnapshotPrefix` 独立于完整公开 `Snapshot`。新版完整 adapter 合成角色关系、事件、战争、军队和结算；领域读取失败时不发布假空状态。地图尚未加载时可发布合法前缀。主线程采样、worker 缓存和命令分派已接入，真实 paused 帧仍待验收。
