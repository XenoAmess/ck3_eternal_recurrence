# CK3 1.20.0.2 后台启动准备

本工作包只读取安装文件并生成离线命令计划，没有启动 runner、准备游戏 profile、同步工坊缓存、访问游戏进程、注入 DLL 或发送输入。新版本路径与验收参数已准备好；实机结果仍待独立测试窗口取得。

## 已修复的迁移阻点

`tools/run_acceptance.py` 原先默认从仓库 `Crusader Kings III/` 启动 EXE，原版规则文件也固定取该旧目录，验收报告则默认写 `1.19.0.6`。这会让新版本验收启动旧安装，或者在 EXE override 指向新版时仍以旧版规则生成测试档。

现在 `tools/ck3_installation.py` 为 runner 与原生环境准备工具提供同一套磁盘路径选择：有明确 `XAR_CK3_GAME_DIR` 时遵循该路径；否则优先已存在的 `Z:\SteamLibrary\steamapps\common\Crusader Kings III`；没有该安装时仍允许仓库参考目录。runner 的 `XAR_CK3_EXE` 优先级最高，原版 `game_rules/00_game_rules.txt` 从所选 EXE 的安装根目录派生。

报告从同一安装的 `launcher/launcher-settings.json` 读取真实 `rawVersion`，并保留所用 EXE 路径。缺失或无法读取安装身份时记录错误，不再用历史版本号补成成功身份。白绮 runner 默认预期 `1.20.0.2`；显式旧版回放可同时指定 `XAR_CK3_GAME_DIR` 和 `XAR_CK3_EXPECTED_VERSION=1.19.0.6`。

可视 UI/OCR 校准仍保留原有 `1.19.0.6` 合同。`configs/default.toml` 与两份旧 UI JSON 没有改版号，也没有把旧坐标冒充新版实测。新增的 `ck3_autonomous_player/configs/ck3-1.20.0.2-native-candidate.json` 只表示原生候选启动配置，`visual_ui_contract=null`、`live_validated=false`。

## 已落盘的具体计划

运行以下命令只生成计划 JSON，不启动游戏，也不会创建候选 state/profile：

```powershell
py -3.13 tools/prepare_ck3_12002_offline_plan.py
```

输出位于 `artifacts/migrations/2026-09-30/post-update-1.20.0.2/offline-launch-plan.json`，包含磁盘核验过的 EXE SHA-256、原版规则路径，以及可直接交给后续实机窗口的 argv。候选 DLL/injector 默认引用协调者统一的 `build-migration-msvc/`；目录可以用 `--bridge-build-dir` 覆盖，不会触发编译或注入。

候选 state 是 `%LOCALAPPDATA%\XarAutoplayer-1.20.0.2-migration`，pipe 是 `\\.\pipe\xar_ck3_bridge_migration_12002`。这些值与旧默认 state/pipe 分开。计划生成时确认候选 state 尚不存在。

计划顺序为：新版本独立 profile 准备 → profile 核验 → 原生 session 的 owning-thread/paused snapshot/命令测试 → 单轮原生观察、决策、操作、验证。最后一项必须先在新 profile 内创建新版 `xar_checkpoint`，不能直接把旧 checkpoint 当作已迁移种子。

本次磁盘身份是 `1.20.0.2`，EXE SHA-256 为 `AE1BA6FF060BA603842F6F4A2DED0AF4B7D3666B3DD271F75FB01B0DA8E81B2D`。首次计划 JSON SHA-256 为 `7a9dd55dbe2e97bd7e22ebfc767f422797930a9ddfe3f85f7b80a0dfc696954e`；重新生成时生成时间会变化，以新文件自身的 SHA 为准。

## 离线验证与剩余实机边界

`py -3.13 tools/test_ck3_installation.py` 的 4 项 fixture 已通过，覆盖新版安装优先于旧参考、显式旧版路径与 EXE override、launcher/EXE 不匹配，以及计划生成不创建 state。另对共享模块、两 runner、环境模块和计划工具进行了语法编译检查，确认 runner 的原版规则路径实际绑定 `CK3_EXE.parent.parent`。

当前 readiness 是 `static-ready`。以上验证不导入或执行具有桌面/进程操作的 runner，不是 L1-L3 结果。剩余需要实机的内容是新版 UI/模组行为、原生 owning-thread 与完整观察口、实际命令副作用、checkpoint 可恢复性，以及完整原生循环。后续只在用户结束当前游戏并进入独立实机窗口后执行计划里的启动命令。
