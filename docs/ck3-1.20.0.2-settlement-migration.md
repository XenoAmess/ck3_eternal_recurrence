实现位于 `ck3_autonomous_player/native_bridge/include/xar_bridge/ck3_12002_settlement.hpp` 与对应 `.cpp`。`BindSettlementImage(base, sha)` 只计算地址；`ReadSettlement(settlement_bindings, core_bindings, snapshot)` 在 adapter 已有的 owning-thread snapshot 事务内调用，只填写 `has_one_life_settlement / one_life_settlement`。调用者必须保留以下结果的区别：

- `unavailable`：绑定、container accessor、registry 或必需 core binding 不可用。
- `not_published`：ready 尚未写入、仍为注册后的 `none`、等于 `0`，或读取结束时 publication gate 已撤回。
- `invalid_payload`：ready 已为 `1`，但必需字段缺失、类型不符、整数不能精确除以 `100000`、布尔不为 `0/1`，或死者完整 generation ID 不能在 storage 中解析。
- `published`：全部字段完整解码，结束时 ready 再读仍为 `1`。

source character 只要求稳定身份。fixture 中死亡组件非空、玩家时钟与其他 snapshot 字段均保持原值，仍能读取结算；若同一索引被另一 generation 复用则拒绝该 payload。两个 score 保留完整 raw numerator；其他整数只做精确除法。测试还覆盖 ready `0 / none / 2`、空 global array、fractional commit serial、缺字段、错误 source kind，以及第二次 ready 读取失效。没有把空对象或部分字段冒充完整结算。
