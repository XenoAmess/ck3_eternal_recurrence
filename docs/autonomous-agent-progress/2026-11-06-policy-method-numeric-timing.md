# Per-policy method wall-time candidate

The first actual P052 summary recorded 139.1979975 seconds in the own planning scope, with two work calls totaling 139.1941984 seconds. Those work calls include observation and planning; they do not identify one slow policy. Flush time is nested, and the separately observed 3.306-second HTTP request is one sample rather than all model cost. These times cannot be added into a CPU or end-to-end total.

This candidate changes only `OrdinaryPlanner`, `OrdinaryPlanCompletion`, and `RootReadPublicationCompletion`. It times the one actual `policy.evaluate(request, draft)` invocation whenever the existing completion is supplied. The current exclusive foreground and legal materialization behavior remains unchanged. The new default diagnostic callback carries only the existing stage ordinal, elapsed nanoseconds, and whether the raw method returned normally. A raw null return counts as returned; the original non-null result guard still rejects it afterwards. Original exceptions, realm cancellation and suppression, interrupt state, and call counts remain intact. The callback's own failure cannot replace a policy result or error. Planner paths without completion keep the original direct evaluation.

Root stores three numeric cells per current stage in the tail of its existing round array. The callback performs no I/O, downstream call, business guard or Session operation. The existing single `xar.java-planning-method-timing/v1` summary gains a `policy_evaluations` array. Each row contains `stage_ordinal`, `enter_count`, `return_count`, `failed_count`, and `elapsed_ns`; rows are present only for stages whose evaluation reached its finally callback. These counters describe calls that have exited, including exceptions, and do not reveal a currently hung invocation.

Emission retains the original proof: entry had no writer scope, and the actual own-scope Core call returned normally after physical lock close. Inherited scopes and Core or close failures emit no summary. No new per-policy output runs under the lock. Times are inclusive method wall durations, not CPU and not a sum to add to work, scope, outcome consumption, or total latency. The 34-stage ordinal mapping is frozen from the actual enum in the evidence index. All 34 rows with the widest signed-long values require 6211 bytes, within the unchanged local 8192-byte canonical limit.
