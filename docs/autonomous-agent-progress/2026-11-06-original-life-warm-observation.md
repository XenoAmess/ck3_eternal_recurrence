# Same-graph observation after an original Life negative READ

A Life resume can receive its original positive control ACK, then fail its fresh postcondition READ while an event blocks time. The ordinary worker previously destroyed its graph on that failure, so observing the same original after normal event handling required another cold bootstrap. This software candidate retains the same graph for a narrowly qualified, bounded read-only reconciliation.

The first candidate (commit68737f57e5) passed its production compilation and a small DATA/STOP case. That case did not exercise the private observation path: a fresh READ unavailable before a physical lease could still throw, and the actual coordinator reduces checked IO exceptions to a class-only Unknown. Thus the first candidate did not prove that it would wait through that event condition.

The final candidate closes that actual producer/consumer gap across three leaves. No physical lease, semantic completion, new action or authority is fabricated. Player-missing/dead/changed and all other failure paths retain their original guards.
