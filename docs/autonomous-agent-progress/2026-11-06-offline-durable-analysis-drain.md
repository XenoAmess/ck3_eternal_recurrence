# Durable offline originals participate in clean restart

A clean-restart attempt after batch20 failed because the actual offline-analysis drain rejected its report. Eight durable request originals were present, while the sixteen exact completion/failure terminal paths were missing. The original inner failure was not retained; a reported failed ID alone does not prove an exceptional future.

The Controller now retains a bounded diagnostic of the actual reap phase and Throwable cause/suppressed graph. It also asks the actual installed offline port for the complete fixed-binding durable request inventory before a clean capture. Each original is validated by its immutable bytes, filename/key and full binding, then obtains the producer's real ticket and is joined and reaped using the unchanged caller deadline. The current incident scan creates one current batch per episode and cannot substitute for this historical inventory.

The production Root wrapper implements the new compatibility-default port method directly and passes its genuine installed binding to the same worker. Existing jobs and futures are preserved. Conflicting originals and failed or invalid terminal evidence still reject; the four-part clean-drain condition, including the old report's failed IDs, is unchanged. No failure/report is cleared, no terminal is overwritten, and no game action is replayed.

The first strict four-source compile failed on the pre-existing exception field Optional<ExactRef>, which is not serializable. That RED and its unqualified partial outputs are preserved. The final source stores all three evidence fields as serializable strings/long and reconstructs an equal ExactRef. All actual constructor calls pass a nonnull Optional; empty and present evidence are preserved. A nonproduction null Optional argument now throws after super rather than storing a null container.
