# Preserve planning-state reuse without a new application holder type

The actual r47 normal reload failed during its first construction planning call with `NoClassDefFoundError: OrdinaryFinanceCollector$PlanningStateReuse`. No new ordinary control or SAVE followed. Runtime verified that both Top.class and the holder.class had been generated under the actual `application/classes` directory. This is a real loading failure; it is not evidence that javac omitted the holder, and this patch does not repair or qualify the application's general new-type reload contract.

Only OrdinaryFinanceCollector changes. The private application holder is replaced with a JDK AtomicReferenceArray containing nine private DATA slots and private static helpers. All public/package APIs remain. The first result still comes from the real complete producer; only its Known result can prime this one-call scope. Reuse still requires the identical request, owning thread, actual borrowed Session, head sequence/digest/persisted reference and snapshot frame. A successful take must win a single ACTIVE true-to-false CAS before returning its captured immutable DATA. Every query, view, explicit Session path, miss and finally boundary permanently disables the scope. Explicit Session/INTENT paths still use the original fresh producer. Eligibility failure does not grant a successful read, and first-producer failures still propagate. Native, source-pin, funding, quote, Guard and authority behavior remains unchanged; no loading Error is caught or swallowed.

ACTIVE is set true only by a new scope factory. A prime already past its active check can temporarily write references into inactive slots while another thread disables it. Those slots can never be reused; the owner's finally boundary clears them. This is a permanent-disable/single-hit guarantee, not a claim that all inactive slots are empty at every concurrent instant. The original Root/writer thread restrictions remain.

The first strict compile passed: one Finance translation unit, twelve classes, 4.7039368 seconds. The new application holder is absent; the eleven common nested class structures match and the non-private ABI is unchanged. The existing five DATA-test classes were reused without compilation. Only the affected package-level method ran once against this new Finance output: 1P/0E/0F/0skip in 3.3971976 seconds. It covers the single hit, no re-prime, fresh ROOT query, query/view/explicit-Session invalidation, escape/finally, identity/point/thread misses and metadata IO fallback. It remains DATA routing evidence, not a physical storage/Root or actual Runtime-hit proof. Both phases released their resources.

The runtime source is pinned from the adopted1842 Finance preimage; the formal file differs only by its existing Git LF projection. The other four planning candidates, P068 and warm06 remain unchanged. The formal construction planningView route is preserved. Runtime may take the exact one-leaf SourceReady at its real recovery boundary without waiting for this publication; actual loading and restored play require separate receipts.
