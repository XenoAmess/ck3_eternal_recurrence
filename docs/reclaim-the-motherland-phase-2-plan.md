# 《重整河山》二期版本计划

状态：**设计已通过，尚未实施**  
计划版本：`0.2.0`  
产品目录：`mod_reclaim_the_motherland/`  
Steam Workshop item：`3798404599`  
设计基线：CK3 `1.19.0.6`、《溥天之下》、本项目 `0.1.1`

## 1. 二期目标

二期只包含两个产品目标，按以下优先级交付：

1. **留朝忠臣不改名**：群雄割据后最终继续臣服后朝的忠臣，必须保留原有主头衔、国号和封臣树；不得因为中华霸权被销毁、弱势头衔裁剪或临时脱离再归附而改名。
2. **尊王派并非绝对忠诚**：尊王派是长期政治立场，不是不可撤销的效忠契约。群雄割据发生时，部分低好感、公开敌对、野心强或实力足以自立的尊王派直属封臣也可以叛离。

两个目标的关系是：目标 2 先决定最终留朝名单，目标 1 再成为这份名单的强制不变量。非尊王派与已经决定叛离的原尊王派继续走原版群雄割据流程。

## 2. 产品原则

- 只对旧天子在割据前的**直属、有地封臣**作留朝判定；下级封臣不单独掷骰。
- 每个直属封臣的整棵封臣树作为一个政治共同体处理：直属封臣留朝，树一起留下；直属封臣叛离，树一起进入原版重组。
- 旧天子继续保留个人领地、除中华霸权外的个人头衔，以及最终留朝封臣；现有后朝与复辟主循环不变。
- 不给留朝人数或领土设置隐藏硬上限。是否留下应由人物关系、性格和实力解释，不能为了凑比例强迫忠臣叛变。
- 所有随机结果在本次割据中只判定一次并保存；后续阶段不得因重复调用重新掷骰。
- AI 使用规则判定；玩家控制的候选封臣必须获得明确选择权，不由后台随机替玩家决定。
- 本期不修改非留朝势力的原版称号选择规则；若以后要限制割据国号的地理候选，应作为单独目标立项。

## 3. 目标 1：留朝忠臣不改名

### 3.1 玩家合同

对目标 2 产出的最终留朝直属封臣及其封臣树，群雄割据前后必须同时满足：

- 直属封臣仍以旧天子／后朝统治者为顶级领主；
- 原主头衔对象仍存在，title key 不变；
- 主头衔显示名及已有自定义名称不变；
- 原有下级封臣仍在同一直属封臣树内；
- 不触发独立势力的中国动态国号事件；
- 不因为原版“弱势 AI 王国／帝国头衔裁剪”而失去主头衔。

这项合同覆盖伯爵、公爵、国王和帝国级直属忠臣。最重要的回归场景是：一个运动力量不足、按原版本应被销毁王国头衔的尊王派国王，既然最终选择留朝，就必须保住其王国头衔和原名。

### 3.2 实现设计

当前 `rmtm_chaos_shattering_effect` 已从独立和后续层级重组中排除尊王派直属封臣树，但原版兼容段仍会对所有 `former_vassals` 执行弱势王国／帝国头衔裁剪。二期应把目标 2 生成的最终留朝列表同时排除在该裁剪段之外。

实现顺序：

1. 在销毁 `h_china` 之前冻结所有候选人物、主头衔、顶级领主与显示名称证据。
2. 运行目标 2，形成一次性的 `rmtm_final_loyal_direct_vassals` 与 `rmtm_defecting_direct_vassals`。
3. 创建后朝头衔并销毁 `h_china`。
4. 独立事务只处理非留朝直属封臣。
5. 弱势王国／帝国头衔裁剪明确排除 `rmtm_final_loyal_direct_vassals`。
6. 层级重组继续排除留朝直属封臣及其树。
7. 不采用“先独立、再重新附庸”的实现，以免触发独立国号事件。

原版延迟国号事件本身要求人物届时已经独立；真正留朝者不满足该条件。除非实机出现可复现的误触发，否则不增加全局事件覆写或额外名称重置。尤其不得用 `reset_title_name` 粗暴恢复名称，因为这会抹掉玩家原有的自定义国号。

### 3.3 明确非目标

- 叛离者允许按原版重新选择国号。
- 留朝者持有的无地官职仍可按原版在割据时清理；本目标保护的是有地政治实体的主头衔和名称。
- 不改变普通继承、征服、篡夺或玩家主动改名造成的后续名称变化。

## 4. 目标 2：尊王派的二次忠诚判定

### 4.1 候选范围与判定时点

候选人必须同时满足：

- 群雄割据前是旧天子的直属封臣；
- 有领地；
- 冻结的 `former_movement_member` 属于 `pro_hegemon_movement`。

所有关系、好感、合法性、实力和性格必须在 `h_china` 被销毁、领主关系发生变化之前读取并冻结。非尊王派不参与二次判定，始终按现有逻辑叛离。

### 4.2 三段式判定

#### A. 明确决裂：必定叛离

以下任一成立时，无视尊王派旧身份，加入叛离名单：

- 正在与旧天子交战；
- 是旧天子的仇敌或宿敌；
- 家族与皇室处于世仇；
- 拥有“不忠”特质；
- 对旧天子的好感不高于 `-75`；
- 正在参加针对旧天子的独立或宣称者派系。

#### B. 生死相托：必定留朝

没有命中“明确决裂”，且满足以下任一条件时，加入最终留朝名单：

- 与旧天子是至交或灵魂伴侣；
- 是尊王派领袖，且对旧天子好感至少 `+25`；
- 与旧天子同宗室、拥有“忠诚”特质，且好感至少为零；
- 旧天子持有其强牵制，且其好感不低于 `-25`。

同宗本身不能保证留朝；宗室成员仍可能因敌对、野心和实力而叛离。

#### C. 其余人物：一次性留朝概率

尊王派提供 `65` 点基础留朝概率，以下修正使用互斥档位时不得重复叠加：

| 因素 | 修正 |
| --- | ---: |
| 好感 `>= +75` | `+20` |
| 好感 `+50..+74` | `+15` |
| 好感 `+25..+49` | `+10` |
| 好感 `0..+24` | `0` |
| 好感 `-1..-24` | `-15` |
| 好感 `-25..-49` | `-30` |
| 好感 `-50..-74` | `-50` |
| 好友 | `+15` |
| 情人 | `+20` |
| 与旧天子存在师徒关系 | `+15` |
| “忠诚”特质 | `+20` |
| “知足”特质 | `+10` |
| “野心勃勃”特质 | `-15` |
| 强力封臣 | `-10` |
| 王国级直属封臣 | `-5` |
| 帝国级直属封臣 | `-15` |
| 军力超过旧天子的 `35%` | `-15` |
| 军力超过旧天子的 `60%` | `-30`，取代上一档 |
| 旧天子合法性 `<= 1` | `-20` |
| 旧天子合法性 `>= 4` | `+10` |
| 畏惧／恐惧旧天子 | `+5 / +10` |

最终概率钳制到 `5%..95%`。判定完成后立刻保存人物结果，不在名称处理、层级重组或延迟事件中再次判定。

### 4.3 玩家封臣

多人游戏或切换角色场景中，如果候选直属封臣由玩家控制，则暂停后台概率判定，通过事件让该玩家选择：

- **奉诏留朝**：保留原头衔、原国号和完整封臣树；
- **各自称雄**：进入与其他叛离者相同的原版群雄割据流程。

选择必须在旧天子的最终列表结算前完成；若引擎无法在同一阶段可靠等待多人选择，则二期首版应明确不支持该交互分支，并保留当前角色的确定性规则结果，不能默认为某一选项。

### 4.4 结果反馈

割据完成后，旧天子收到一次汇总事件：

- “奉诏留朝”列出留朝的主要直属诸侯；
- “各自称雄”列出叛离的主要直属诸侯；
- 人物提示显示最主要的正面或负面原因，例如“素有嫌隙”“兵强势重”“宗室同心”“受恩于朝”。

玩家无需看到内部随机数，但必须能够理解结果。汇总事件不得使用验收专用 UI，也不得把后台术语暴露到正式文案。

## 5. 游戏规则与兼容

新增独立游戏规则“尊王派的抉择”，与现有 `rmtm_hegemon_fate` 正交：

- **人心离散（推荐）**：启用目标 2 的动态忠诚判定。
- **誓死尊王**：保持 `0.1.1` 行为，所有符合条件的尊王派直属封臣留朝；仍受目标 1 的不改名保护。

现有“原版群雄割据”选项必须完全绕过二期两项目标，保持原版行为。规则默认值、旧存档缺少新规则时的实际语义，需要在实现前用静态解析和一次受控存档加载验证后冻结；未验证前不得声称旧存档兼容。

## 6. 平衡目标

二期不承诺一个固定的尊王派领土比例，而采用以下调参目标：

- 普通局势下，后朝控制中华法理领土的目标区间为 `15%..40%`；
- 多数未经刻意经营的局势在割据后不应立即达到 `51%` 的复辟门槛；
- 玩家长期经营友谊、宗室、忠诚和牵制必须获得明显收益；
- 强大、野心勃勃或与旧君关系恶劣的王国级尊王派成员应有可信的叛离机会；
- 不以隐藏硬上限保证上述区间，极端经营局允许突破，但必须作为独立的高位样本记录。

`0.1.1` 的现有实机验收人为设置了一个尊王派直属封臣，割据前后 HUD 兵力由约 `9021` 降至 `1647`，约保留 `18%`。这只能作为单忠臣受控基线，不能冒充自然局平均值。二期验收必须新增自然样本与极端经营样本。

如果自然样本频繁在割据后立即满足 `51%`，先调整忠诚权重；是否给复辟增加“割据后实际收复”条件属于另一项产品决策，不在本计划中静默加入。

## 8. MCP 优先验收方案

当前仅批准设计，不启动 CK3。进入实现和验收阶段后仍遵循以下顺序：

### L0：离线与静态

- 先判断 `open_kaishek` 是否能覆盖新增 trigger、effect、变量列表和随机权重语义；能覆盖的确定性子集先离线预验。
- 校验括号、作用域、未定义 key、本地化占位符、规则默认值与 release staging 纯净性。
- 对好感档位、互斥军力档位、概率钳制和硬规则优先级建立表驱动测试。

### L1/L2：受控机制验收

通过项目既有 CK3 槽位取得排他控制权后，使用 MCP 原生状态与命令优先；只有 MCP 不支持的最小步骤才允许降级，并记录边界。

至少覆盖：

1. 普通尊王派忠臣留朝且名称不变；
2. 低运动力量的王国级忠臣仍保留原王国和原名；
3. 有自定义国号的忠臣不被 `reset_title_name`；
4. 忠臣完整封臣树不拆分；
5. 仇敌、交战者、极低好感者必叛；
6. 至交、灵魂伴侣等硬留条件必留；
7. 摇摆人物只结算一次；
8. 原尊王派叛离者与普通非尊王派走相同的原版重组；
9. “誓死尊王”保持 `0.1.1` 兼容行为；
10. “原版群雄割据”完全不受二期逻辑影响。

### L3：玩家可见验收

- 游戏规则名称、说明和默认项正确；
- 群雄割据结果事件能区分留朝与叛离者；
- 角色、主头衔、顶级领主与地图名称和底层状态一致；
- 记录后朝割据后的直属封臣数、中华法理郡县控制比例、总兵力及复辟决议是否立即可用；
- 真实地图证据仍以大宋首都开封为中心，不得使用错误地域镜头；
- 自动报告、截图和日志不等于人工完整审阅，正式发布前仍需单独签核。

## 9. 发布退出标准

二期只有同时满足以下条件才能标记完成：

- 两个目标的 L0–L3 必需用例均为 GREEN；
- 留朝忠臣的主头衔、国号和封臣树有实机前后对照证据；
- 动态忠诚的硬规则、概率边界和一次性结算有可复查证据；
- 后朝强度报告同时包含自然、刻意经营和极端三个样本类别，不用单个 fixture 推断平均值；
- 正式 staging、manifest、ZIP、Steam 上传、订阅缓存复核全部完成；
- Workshop BBCode、相关艺术资产和 `0.2.0` changelog 已提交并推送到 `master`。
