# 产品与技术路线图

本文是《琉焰卿的永恒轮回》下一阶段产品、机制、工程与发布工作的权威计划。
评审基线为 2026-08-18 的 `master`：核心循环已闭环，完整 acceptance 为 GREEN，
但纪录语义、首局体验、长期挑战和发布工程仍需补全。

## 1. 产品判断

项目的核心定位是：

> 一位统治者、一条命、一次结算，以跨存档余烬位阶驱动下一世强化的 CK3 New Game+ / roguelite 挑战模式。

现有优势：

- 跨存档纪录、死亡结算和下一局预算已形成完整循环。
- 祝福三选一、诅咒二选一和成长特质提供局内变化。
- 100+100 奖池、九语言、生成 parity 和实机验收已具备成熟基础。
- 琉焰卿的人格、视觉和交易主题统一，具有工坊辨识度。

当前瓶颈：

- 持久层保存的是量化阈值，产品却按精确最高分表达和比较。
- 非零纪录导入缺少显式 request/ready 协议。
- 首局没有可消费纪录，商店价值和下一目标不清楚。
- 当前分数、历史位阶和下一位阶缺少整局可见的信息入口。
- 全额继承与绝对状态计分会形成滚雪球，不同开局缺少可比较赛道。
- 垂青会交互偏密，奖池缺少状态过滤和构筑协同。
- 死亡与 hover 计分、结算文案和文档仍有多处同步成本。
- 静态校验和实机 runner 很强，但 CI、生产场景覆盖和可复现发布不足。

## 2. 投资原则

1. 先保证纪录可信，再扩展内容。
2. 先让玩家看见目标，再增加目标数量。
3. 保留当前全额继承模式，同时增加公平挑战赛道，不强行替换现有玩法。
4. 优先提高每次选择的有效性，不继续单纯扩大数值奖池。
5. 保留 tutorial lesson 持久化介质和现有 lesson ID，避免破坏旧纪录。
6. 生成器负责重复结构，手写代码只保留引擎语义无法统一的适配层。
7. 测试调用生产 effect，不维护一套相似但独立的测试实现。
8. Steam 与 GitHub 应发布同一份可追溯 staging 产物。

## 3. 阶段路线

### Phase 0：核心可信化

目标：让跨存档纪录、破纪录判定和开局导入具备明确且可验证的语义。

工作项：

- 将真实本局分数、量化候选位阶和历史位阶分开存储。
- 只有候选位阶高于历史位阶时才写入并显示新纪录。
- 定义达到持久层上限后的反馈。
- 建立 `import_requested -> import_ready -> consumed` 导入协议。
- importer 幂等汇总候选位，商店只在 ready 后获得点数。
- 增加非零纪录、同阈值区间、上限和重启导入验收。
- 修正文档中“精确最高分”和 tutorial 禁用行为的表述。

退出标准：

- 同一阈值区间内不会重复宣布新纪录。
- 预置非零位后重启 CK3，历史位阶和商店点数均准确。
- GUI 与 on_action 的先后顺序不影响导入结果。
- 达到上限后不会反复触发无效写入。

### Phase 1：首局与信息层

目标：玩家不依赖 README，也能理解第一世、当前进度和下一目标。

工作项：

- 纪录为 0 时进入首局专用说明，跳过无意义空商店或提供教学流程。
- 增加“琉焰账簿”，展示当前分数、历史位阶、下一位阶和差值。
- 展示主要分项、本局交易、拒绝次数和下次垂青时间。
- 结算突出扣分前小计、最终分数、是否升阶和下一世预算。
- 增加无继承人结算兜底。
- 商店价格采用明确整数策略，显示、购买条件和扣款完全一致。
- 在规则、契约和首次结算中提示 tutorial 前置条件。
- 正式发布内容隐藏 selftest 规则和 acceptance-only GUI。

退出标准：

- 新玩家能在第一世明确知道“当前无前世余烬”和本世目标。
- 任意时刻可在两次交互内查看当前、历史和下一位阶。
- 有无继承人都能看到完整结算。
- 商店不再出现显示价格够但选项不可用的情况。

实施状态（2026-08-18，本轮范围）：

- 已完成两个核心信息层功能：0 历史位阶的首世专用说明/直达祝福流程，以及玩家专属、可重复打开的「琉焰账簿」。
- 账簿当前覆盖只读分数、历史/候选/下一位阶、差值、完成对数和拒绝次数；下一位阶与 cap 语义由 highscore generator 的 `THRESHOLDS` 统一生成。
- 已补齐商店 12 项价格的统一向上取整、九语言 tutorial 写入前置提示，以及无继承人的同步结算 fallback；实机已证明 fallback 完成计分/写位，但原生 Game Over 确认遮住结算窗，玩家可见承载仍待解决。
- selftest 已通过 release 投影隔离；开发树保留完整自动验收，正式 staging 排除整文件测试定义并剥离混合分支。

### Phase 2：工程基础与单一权威源

目标：降低新增计分项、机制和发布版本的同步与回归成本。

工作项：

- 建立 `tools/scoring_data.py`，统一系数、档位、世代深度和拒绝倍率。
- 由 schema 生成死亡计分机械部分、hover、文档和离线参考模型。
- 后代遍历保留 effect/value 两个适配器，但共享规则参数和测试向量。
- 抽取运行、商店、垂青会初始化及购买生产 effects。
- selftest 和生产事件调用同一 effects。
- 静态校验自动发现事件、on_action、decision 和 interaction 入口。
- 建立 L0 静态、L1 解析、L2 机制矩阵、L3 UI/OCR 四层测试。
- GitHub Actions 自动运行 L0；Windows 自托管环境运行 L1-L3。
- 构建纯净 release staging、manifest、SHA-256 和 deterministic zip。
- runner 输出 run ID、git SHA、mod hash、环境信息和 JSON/JUnit 报告。

实施状态（2026-08-18，计分单一权威源子范围）：

- 已建立 `tools/scoring_data.py`，统一六维、血脉、资源、头衔、后代深度、`log2` 上限、领地与拒绝倍率参数。
- 死亡计分机械核心、`log2` 阶梯和五代展开由 `gen_scoring.py` 生成到独立 effect 文件；手写文件仅保留后代身份/宗族/家族/最高头衔的引擎适配器。
- hover 与 `docs/scoring-rules.md` 读取同一 schema；文档全文生成并纳入 parity。
- 已增加纯 Python reference model，以及 `log2` 0/1/2/3/4、两套头衔系数和拒绝 0/1/100 次边界断言；静态校验同时限制 `xar_compute_score_effect` 只能有一个生成定义。
- 本子范围不包含 CI、release staging、分层测试扩建或 Phase 3 平衡功能，这些仍为待办。

实施状态（2026-08-18，生产逻辑复用子范围）：

- 已将玩家契约启用与运行/商店状态初始化抽为生产 scripted effects；契约接受 option 与 selftest 调用同一组 effects，自测不再复制价格及垂青会 session 初始化。
- 已将 12 个会整数涨价的商品抽为具名生产购买 effects；事件 options 只保留购买条件、测试 marker 与 UI 跳转，外交 `25 -> 30`/扣款样例直接调用生产 effect。一次性信仰改革保持简单事件逻辑，不引入商品 DSL。
- 已将余分转金币、余额清零和垂青会 session 初始化抽为生产 effect；首世继续跳过商店兑换，完整 UI 自测继续在 effect 返回后把 session 覆盖为 3，原流程不变。
- 静态校验会解析上述 effect bodies，证明生产事件与 selftest 共用入口，并禁止契约/selftest 重新出现初始化赋值或外交购买复制片段。

实施状态（2026-08-18，静态 CI 与 release staging 子范围）：

- 已新增 hosted Windows GitHub Actions L0：安装固定的最小静态依赖，依次运行 `validate_static.py`、计分 reference vectors 和 `build_release.py --check`，不启动 CK3。
- 已建立 byte-preserving release allowlist，只从 mod 源目录复制正式 CK3 根文件与核心目录；mod 内 `tools/`、Python cache、未知根内容、仓库文档和源素材不会进入 staging，意外 cache/非 allowlist 文件会令静态校验失败。
- 默认生成 `dist/XenoAmess_s_Eternal_Recurrence/`、旁置 manifest JSON（相对路径、大小、SHA-256、可用时的 git SHA）和 deterministic ZIP；`--check` 在临时目录双构建并比较 manifest 与 ZIP。
- acceptance 与 static requirements 已拆分并按当前可用环境固定版本。runner 已输出 JUnit 和环境指纹；L1-L3 自托管 CI 仍待后续实施。
- production-only 投影已实现：整文件排除 acceptance 定义，混合运行文件用严格 marker 渲染生产分支，构建扫描禁止测试标识残留；生产 smoke 直接加载投影实测。
- acceptance runner 已增加 `selftest/on-first-life/on-recorded/on-high-budget/off` 场景并完成实机 GREEN；四个生产场景均加载 release 投影，每场输出 JSON/JUnit、run ID、git/mod/environment 指纹与阶段耗时，且现场备份不进入 artifacts。

退出标准：

- 修改计分系数只需编辑一个机器权威源。
- 测试不再复制生产初始化和购买逻辑。（已完成）
- 每次 push 自动阻止 stale generation、loc、BOM、资源和入口 guard 回归。
- GitHub 与 Steam 候选包可追溯到同一 commit 和 manifest。

### Phase 3：平衡 Beta

目标：控制继承滚雪球，减少无效选择和长局交互疲劳。

工作项：

- 增加 0%、25%、50%、100% 继承比例，不另设预算上限；用成长口径控制直接买分。
- 增加纯净计分与相对开局增长赛道。
- 不同赛道使用独立位阶或明确的记录标识。
- 奖池条目增加稳定 ID、标签、适用条件和重复策略。
- 已有 trait、同名 modifier 和无关状态使用替代效果或排除抽取。
- 选项显示普通、稀有、传说及构筑标签。
- 按角色状态动态调整相关条目权重。
- 将每场最多六个模态窗口压缩为一至两个交互，或改为每场一对。
- 建立伯爵、国王、皇帝、自建角色的平衡矩阵。

退出标准：

- 不同开局和继承强度有清晰赛道，不共享模糊纪录。
- 抽到完全无效祝福/诅咒的概率显著下降。
- 30-50 年人生的模态打断明显减少。
- 高纪录不会在少数轮回后完全消除挑战。

实施状态（2026-08-18）：

- 已增加绝对/本世成长两种计分口径，以及 0%/25%/50%/100% 继承；25%/50% 预算向下取整，所有比例均不另设预算上限，推荐默认是本世成长 + 100%。八种组合在账簿与结算中显示 `v2` 赛道标识。
- 旧 `xar_hs_ge_*` 保持为兼容的全局余烬进度，不复制 5600 个额外 lesson；因此不同赛道以明确标识区分，但仍共享进度位阶，此差异列入 1.0 known limitation。
- 产品决策已确认：1.0 接受八赛道共享余烬进度，以及当前 166,600 持久化位阶上限；二者不再作为 1.0 发布阻断项。
- 无封顶继承新增三种一次性高价批量典当：10,000 分万国贡火、50,000 分借来一代、100,000 分六维登神；与 1,133 分宗教改革合计后，166,600 预算仍可在少量点击内完成构筑。
- 奖池保留 0-99 wire id，并导出 `bless.000`/`curse.000` 稳定 ID、稀有度与类别；已持有同级/更高 trait、同名 modifier、无宗族、零压力减压会被过滤，状态与契约匹配项动态加权。
- 垂青会已压缩为每三年一对，最多两个模态窗口；重抽和封印由特质里程碑提供。
- 继承公式已有生产 effect 与 0/25/50/100 实机脚本断言；100% 以 1200 位阶验证不封顶并覆盖 1133 分宗教改革价格。完整伯爵/国王/皇帝/自建角色 30-50 年人工矩阵仍属于发布后的平衡采样，而非阻断结构正确性的验收。

### Phase 4：CK3 原生契约内容

目标：从附着于 CK3 的高分层，升级为能驱动不同 CK3 战略的 roguelite 模式。

工作项：

- 增加征服者、织网者、圣徒、家主、贤王、享乐者等契约原型。
- 每类契约提供本世增量目标，而不是只看死亡时绝对状态。
- 为战争、计谋、信仰、家族、治理、活动建立行为计分和事件反馈。
- 祝福/诅咒按标签形成协同与冲突。
- 特质每 10 级解锁信息、重抽、封印、事件或外观，不只增加压力。
- 增加成绩等级、分项个人最佳、图鉴和首次目标永久解锁。
- 增加 20-40 个围绕契约和交易的叙事事件。

退出标准：

- 连续两局能主动引导玩家采用不同 CK3 策略。
- 特质升级产生期待和新选择，而非只有惩罚。
- 未破纪录的长局仍能推进至少一种长期目标。

实施状态（2026-08-18）：

- 已生成征服者、织网者、圣徒、家主、贤王、享乐者六类本世契约；玩家从决议选择，不额外插入强制开局窗口。
- 战争胜利、使用牵制、伯爵领改宗、子嗣出生、建设完成及低压力生日通过原生 on_action 进入共享玩家/AI 闸门；每点进度计 10 分。
- 3/6/10 进度生成 18 个契约反馈事件、18 个跨存档 PB lesson 与 6 个图鉴完成位；账簿显示当前 D/C/A/S、该契约 PB 和全部已完成契约。
- 【琉焰之视】生成 10 个里程碑事件；每级在压力代价之外提供累积原生属性成长，交易奖励从早期单枚代币逐步升级为中后期重抽与封印组合。池权重按契约标签形成祝福协同和诅咒冲突。
- 本轮内容事件采用 18 个契约里程碑加 10 个特质交易事件，共 28 个；后续扩写可只改 `contracts_data.py`/`gen_contracts.py`。

### Phase 5：1.0 发布闭环

目标：形成明确品牌、稳定版本和可持续更新模板。

工作项：

- 使用正式语义版本号和 changelog。
- 工坊标题明确表达 CK3 Roguelite / New Game+。
- 重制缩略图和中英双语干净截图。
- 首屏先表达一条命、跨存档和下一世强化，再说明 tutorial 要求。
- 增加兼容性、FAQ、局长预期、死亡后行为和挑战模板。
- tag 构建 release staging，通过 L0-L3 后生成 GitHub Release。
- Steam 上传同一 staging，并记录 item ID、commit 和 manifest hash。
- 日常只维护简中与英文；收到明确发布指令后，再按 `docs/localization-workflow.md` 补齐其余七语言并进行九语言结构、术语、人格和截断 QA。

退出标准：

- 每个 Steam 版本都能追溯到 Git tag、manifest 和验收报告。
- 工坊访客能在十秒内理解核心循环。
- README、工坊描述和游戏内术语保持一致。

实施状态（2026-08-18，本地自动化范围）：

- descriptor 已升至 1.0.0，新增 changelog、发布 QA 表、资产来源待签表，并统一 README/工坊源文案中的 CK3 Roguelite / New Game+、版本、FAQ、局长和挑战模板。
- release manifest v2 记录版本、tag、commit、工坊 ID 与逐文件 SHA-256；`--release` 要求 clean worktree 与 `v<version>` tag，`--verify` 可核对下载后的工坊缓存。
- acceptance JSON/JUnit 记录 run ID、UTC、版本、git SHA、mod tree hash、游戏/环境及结果；用户现场备份已移出公开 artifacts 并在恢复后删除。
- Steam 实际上传、GitHub Release、干净中英截图、缩略图人工审美确认和资产许可确认需要外部账号或人工判断。其余七语言翻译及九语言人工人格 QA 按用户要求推迟到明确发布指令之后；状态见 `docs/release-qa-v1.0.0.md`，不得伪报为自动完成。

## 4. 测试矩阵

优先补齐以下场景：

- 正常 `xar_on`、`xar_off`、首局 0 纪录、已有纪录和高预算 release projection 均已由 runner 实机 GREEN。
- 非零纪录导入、两进程重启导入和 request/state 防抢跑均已有自动验收。
- 同阈值区间、跨阈值、最高阈值和超过上限。
- 商店三页代表商品、整数涨价、余额不足和余分兑换。
- 真实拒绝、重抽与封印已纳入 selftest UI；仍需补第一至第三对、满三对结束和正常三年重开。
- 祝福/诅咒稳定 ID 到 effect 的代表性语义映射。
- AI 实际死亡负例已自动验证。
- 无继承人脚本链与原生 Game Over、正常继承人观察者切换已验证；无继承人可见结算仍待新承载层。
- log2 的 0/1/2/3/4、幂前后边界。
- 后代 1-5 代、近亲重复路径、死亡中间节点和多头衔。
- 发布模式、非 debug 模式和 staging 内容实测。

## 5. 不做事项

以下重构当前投入产出比低，除非新需求改变前提，不进入近期范围：

- 替换 tutorial lesson 跨存档介质。
- 将单调位改成需要清零进位的普通二进制编码。
- 手写替换生成的 100 分支 dispatcher。
- 全面将 global variable 迁移为 character variable。
- 为代码美观取消五代展开。
- 在选择质量未提升前继续扩大 100+100 奖池。
- 优先微优化只在玩家死亡时运行一次的计算。
- 为少量 custom entry 建立复杂通用 DSL。
