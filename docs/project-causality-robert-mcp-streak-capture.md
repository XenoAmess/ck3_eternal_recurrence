# 罗贝尔 MCP 连胜实机录制契约

这条实机不是“为巴勒莫准备的一段脚本”，而是 Project 因果律对 CK3 自动游玩能力的一次公开验收：纯原版 CK3、从主菜单和选人流程开始、全程由 MCP 读取状态并执行语义动作。录像只负责留下连续证据，不参与控制或判定。

## 展示目标

1. MCP 从主菜单进入 1066 书签，用原生角色 key 选择罗贝尔并开始游戏。
2. 智能体处理开局事件、婚姻、宫廷与领地等当前策略认为必要的治理动作。
3. 智能体查询当前合法宣战集合，以实时合法性、双方军力、外部支援依赖、距离、宣战理由和目标价值排序，选择当前策略下最合适的目标。这里的“最好”是可审计的保守策略结论，不宣称数学意义上的全局最优。
4. 智能体完成宣战、集结、行军、围城、战斗、事件恢复、战争结算、解散军队和战后检查点。
5. 每次进攻胜利后重新读取世界状态、重新评估目标，再发动下一场战争。不得把上一场的目标硬编码到下一场。
6. 录制持续到第一次战争级失败。单场战斗失利不等于战争失败，不触发停止；白和平记入战争账本，但不伪装成胜利。

## 动态选敌策略

通用自动玩家在资料不完整时允许保守地选择 `NO_DECLARE`；宣传实机需要展示完整战争 OODA，因此录制器在这一阶段启用显式的 show-off campaign policy，但不硬编码目标，也不绕过 MCP：

1. 调用 `ck3_query_declarable_wars` 获取这一帧中 CK3 原生判定为合法的全部宣战项；
2. 对每个不同目标逐一调用 `ck3_query_war_entry_assessments`，保留同帧回执；
3. 以 `max(目标基础兵力, 目标网络合计, 目标修正后合计)` 作为保守目标兵力，避免不透明的负修正把强敌显示成零兵力；
4. 优先选择罗贝尔基础兵力达到目标保守兵力 1.5 倍的宣战项，再按目标/己方兵力比、目标兵力、距离、宣战理由、目标头衔价值和稳定 ID 排序；
5. 若当前没有 1.5 倍优势目标，仍选择风险最低的合法目标，并明确标记为 `least_risk_until_failure`。这是“持续进攻直到失败”展示契约的一部分，不把它包装成稳胜预测；
6. 调用 `ck3_declare_war` 提交排名第一的原生 declaration ID。战争结束后废弃旧排名，从新世界状态重新查询。

因此，“最好”表示当前 MCP 可观测数据和上述公开规则下的确定性最优项，不表示全知全局最优，也不预设必须攻打谁。

## 控制与观测边界

- 控制面：官方 MCP Python Client 加项目 MCP Server。
- 观测面：native bridge 发布的语义快照和只读查询。
- 证据面：FFmpeg 对同一桌面的连续录制、MCP JSONL 日志、WarID 战争账本和最终报告。
- 模组：`enabled_mods=[]`，不加载“琉焰卿的永恒轮回”。MOD 展示与 CK3 自动玩家展示是两项能力，不能相互污染。
- 固定版本：CK3 1.19.0.6；EXE、bridge DLL、injector 全部记录 SHA-256。

以下任一情况均视为验收不合格，不能拿录像剪辑掩盖：

- OCR、鼠标、键盘、窗口坐标或图像模板进入控制/判定链；
- 命中旧 `war-declare-palermo` / `war-siege-palermo` 路径；
- 仅凭命令 ACK 声称选中了罗贝尔、宣战成功或赢得战争；
- 跳过母带中的失败、阻塞或不利结果；
- 固定要求必须攻击某个预先指定的领主。

## 连续母带与剪辑

正式母带从 CK3 启动前开始，到首次战争级失败、角色/战役终止或明确的操作员上限为止，中间不停止录制。宣传片允许按时间顺序改变播放速度和做蒙太奇压缩，但源时间不得倒退、跳过或重排。所有胜利应按真实发生顺序展示，第一次失败作为当前版本能力边界保留。

母带之外必须保留：

- `report.json`：环境、哈希、停止原因、累计胜负与清理证明；
- `mcp-calls.jsonl`：每次 MCP 调用及返回；
- `war-ledger.jsonl`：每个 WarID 的开始、目标状态和结算结果；
- `target-evaluations.jsonl`：每轮全部合法目标的原生军力回执、排序、风险分类与最终 declaration ID；
- `ffmpeg-recorder.log`：编码日志。

执行器为 `tools/run_project_causality_robert_mcp_streak.py`。只有“至少一场进攻胜利 + 后续首次战争级失败或自然战役终止 + 连续母带完成 + CK3 进程树回收”同时成立，报告才可标记为 GREEN。若达到显式时长/回合上限仍未失败，素材仍可作为连胜证据，但该次报告保持非 GREEN，并诚实标为有界停止。

## 录制历史现场收口（2026-09-20）

R30 完成后，工作区还遗留两类未提交现场。评审结论如下：

- `opening_smoke.py` 与 `run_project_causality_robert_benchmark.py` 的未提交修改属于已经被 R30 取代的固定巴勒莫旧基准。它们同时保留 OCR、鼠标和固定路线行为，与最终公开的 MCP-only、动态择敌能力不是同一条实现路径，因此还原到已提交版本，不作为正式能力提交。
- 根目录 `nb1/`、`nb2/`、`nb2vs/`、`nb2w/`、`nb3vs/`、`nb4vs/`、`nb5vs/` 均为可重建的 CMake/Ninja 临时目录。除 `nb5vs` 外，其余目录只属于编译候选或工具链试验；七个目录在证据冻结后全部删除，共释放约 214 MB。
