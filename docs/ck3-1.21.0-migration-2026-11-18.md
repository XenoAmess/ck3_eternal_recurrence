## 实际验收顺序

先运行隔离 profile 的原版/最小模组加载，取得真实新版错误日志；并行完成 Native 新 DLL 和 Java 接收合同。R1 验收核对地图、玩家、日期、暂停与稳定接收来源，再验证时间控制、保存和冷恢复。随后迁移原已验证业务族并运行有界 OODA；每个动作都保留真实后态，UNKNOWN 不重放。

跨版本继续同一 campaign 使用现有 `prepareReadOnlySavedSource` → `RootJavaSavedBootstrap.admitLoaded` 链：新游戏加载、新 custody、独立 writer、两次稳定接收与演员/日期/暂停/地图等条件全部实际成立后才能导入。旧 continuation 的同 EXE 守卫保持严格，不把旧 head2003 writer 原地认作新版 writer。
