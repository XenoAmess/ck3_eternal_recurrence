# 《汉晋春秋》董卓篇：拍摄复盘与用户要求

记录日期：2026-11-01。实拍及剪辑机器：`machine_id: 4-8e1c2f1861`。范围为本轮导演稿、实际游玩、几次审片返工、Edge TTS、成片与Bilibili封面；本机路径、版本和运行结果不外推到其它机器。

这说明“时长够了”与“故事拍完了”要分别判断。最后一版比前一版短，是删减重复后的实际结果；不能据此推导用户喜欢越短越好，也不能替用户宣布整片已经满意。

本局的收尾是董卓的人物结局，不要求把整个三国世界玩完，也不是今后每一集都必须拍到角色死亡。选题时应先明确本集要回答什么，再选一个观众看得见的结果来结束。

## 三、先把一集拍完整

开拍前把本集的核心问题说清楚。本期是董卓手握天子和强兵，能否守住权力与性命；市丘赢一场只能回答眼前的小战，不能回答这个问题。未央仍未出现时，应继续正常推进，记录中间真正影响处境的变化。

录制开着不代表拍摄有推进。长时间暂停、反复读面板和工程等待都不能当成新内容；遇到阻碍先解决实际游玩问题，继续往下玩，剪辑只留下能推动这集的部分。

拍到结果后还要录后态：人物是否死亡、谁接手、头衔与兵力怎样、战争是否还在。本轮补拍到死亡后继续、国贼伏诛和董璜页面，才让观众知道这一局落在哪里。不能死亡窗一出就关录制，也不能用未来会怎样的口播替代后态。

导演稿里设想过的分支应随实际结果改写。本轮早期设想称病，真正录制选了照常入朝，就按入朝后的结果讲；不能把另一分支、熟悉的演义故事或源码后续混进这局。

## 四、玩家口吻来自判断，不靠口头禅

本轮“AI味”的具体来源包括：逐段报日期、读标题和按钮；评论“事件怎么写”；不断说“局面变了”“还得接着打”；在死亡、家族、领地和回顾四段反复感慨同一件事。这些句子占时间，又没有增加玩法或故事信息。

修改时先决定哪些话值得说，再调整说法。日期能由场标题交代，就不用每次重读；按钮能看懂，就不逐字念；一句结论已经落下，就不要换三个比喻再说一遍。“我看到什么、准备怎么做、结果如何”可以帮助审稿，但不必机械套成每段四句话。

本轮实际重写例子：

| 出戏的表达 | 实际采用的方向 |
| --- | --- |
| “事件把迁都写得很直接” | “才到二月，洛阳就烧了。带上天子，搬去长安……”接自己的防守打算。 |
| “事件里还给拆开了” | “千里草，是董；十日卜，是卓。合着这句不得生，说的就是我。”直接回应童谣。 |
| 多次总结三万兵仍在、董卓却死了 | 死亡处给反应，继承处交代处境，最后落一句，不再另设回顾重复感慨。 |

不要靠密集添加“行”“好家伙”“咱们”伪造口语，也不要给角色编没拍到的内心戏或动作。已定片头可以保留戏剧化独白，正文仍应像玩家在讲这局。

“我可没把联军打服”与“我可没被联军打服”改变了主语承担的意思：前者强调没能征服对手，后者保留董卓不服输的语气。用户指定后应精确采用，不能再用自己的措辞覆盖。当前完整台词以[最新旁白](../promo/hanjin_spring_autumn/research/filming-05/narration.txt)为准。

两份本地模型改稿候选曾分别缺场、输出摘要腔或弄错语义，均整份拒绝。HTTP完成、JSON能解析并不能证明台词自然；[审阅记录](../promo/hanjin_spring_autumn/research/filming-04/model-review.json)保留了具体原因，正文由我重写。

## 五、已有录像，优先用录像

本轮最大的一项剪辑失误，是已经有原片，却为了选取方便大量使用截图。按实际剪辑时间线统计：

| 素材来源 | 约8分25秒版 | 约6分04秒实录版 |
| --- | --- | --- |
| 原始游戏录像 | 51.207秒 | 312.433秒，占时间线85.841% |
| 游戏截图 | 418.437秒 | 15.5秒 |
| 原创标题、说明、对照、宣传卡 | 34.989秒 | 36.033秒 |

来源见[返修记录](../promo/hanjin_spring_autumn/research/filming-04/README.md)及[最终交付](../promo/hanjin_spring_autumn/research/filming-05/delivery-snapshot.json)。这是本次改进的实测数，不设成未来每片必须达到的比例。

原片替换应寻找完整的小过程：事件出现、正文和选项、真实点击、窗口消失、地图或人物状态改变。迁都、童谣、入朝、死亡继续和死讯关闭都找到了这样的片段。截图推近、平移或循环同一段视频，不能冒充新增游戏动作；暂停界面的录像也不等于连续游戏推进。

真正缺录的地方要承认。本次关东举兵弹窗落在两个录制段之间，保留3秒弹窗及3.5秒总览截图，再接战争地图。董璜终态原片只有约8.7秒，给人物动画使用后，统计段另保留9秒真实截图。具体原因见[静图清单](../promo/hanjin_spring_autumn/research/filming-04/still-retention-reasons.json)。

下次录制要接好分段，避免恰好漏掉重要弹窗；结局后给继承人物、领地、军队和战争页面留够干净素材。保留时间标记和可用片段范围，剪辑时就不必重新从长原片里盲找。

## 六、台词、画面和数字要落在同一时刻

原片可用，不代表随便取一段就能配台词。先按新配音确定句子的时间，再选内容相符的镜头，并限制在实际画面边界和文件结尾之前。

本轮具体修过三处：承载4,680的说明卡提前到该句出现；说“赢了”时立即给伊阙胜利；说五金岁禄时切到通知，而不是让画面晚好几秒。家族段前半说董璜，就必须显示董璜，后半说回看董卓才换死者页面。

事实也要讲准：

- 伊阙不是潼关。素材旧文件名曾有误猜，不能把文件名当成地名依据。
- 袁术是敌方主参战者，不等于他亲自担任本场指挥官。
- 承载4,680和补给存量300不是同一个指标，也不能拿另一队五千人来解释两万主力。
- 伊阙赢了是单战胜利；讨董战争随董卓死亡退出列表，不是联军认输。
- 董璜页面五百兵是他个人名下兵力，不能解说成旧三万军队全灭。
- 刘协来信说明王弘已获命援助，确认通知不是点击后再派一次兵。

以上边界来自[真实续拍记录](../promo/hanjin_spring_autumn/research/filming-03/README.md)。+19%用了战后稍晚查看的真实盾牌，不应说成胜利窗口当时已经显示；画面日期、原生读取时间和录像秒数分别记录。

战斗的正常剪法是交代目标和一项判断，给短交锋或日期跳切，再交代结果。本次市丘约18秒、伊阙约23秒只是实际选择，不是通用秒数。没有连续录下的伤亡推进，不能把暂停面板加速伪装成全过程。

### 汉晋春秋的称号按模组实际展示核对（2026-11-01补记）

用户明确纠正：董卓的称号为**相国、假黄钺、都督中外诸军事、录尚书事、郿侯、董公**。可以使用“郿侯”，不能使用“郿国王”，也不能把他称作国王。

这条要求适用于汉晋春秋中的所有人物。模组对官职、爵位与称呼有特殊处理，不能把原版CK3的国王、皇帝、公爵等称呼直接套进来。地图上出现“郿国”，或源码使用某级领地容器，都不能据此把董卓改称“郿国王”；内部等级只用于解释实现，不作为人物称号的依据。

写导演稿、旁白、字幕、封面和简介时，先核对对应人物在对应时点的模组实际显示，再统一用词。未核实就先用人物姓名，不猜称号；身份发生变化时重新核对，也不能把一时的称号套给所有时期。

## 七、宣传和封面是交付的一部分

本期片名已定为《洛阳炙手，公卿憎我，天下讨我》，用户问起时直接准确回答。已定标题和开场独白不要在不同稿件中悄悄改写。

结尾要明说Mod《汉晋春秋》与Steam创意工坊搜索；既然口播说链接放简介，就实际提供带三个工坊链接的简介。启用了议和扩展，不等于本片演示了完整议和。尾卡之后结束，不再补下一期或未拍机制预告。

封面应兼顾缩小后的文字、人物和品牌辨认，两种比例分别排版。本次[封面记录](../promo/hanjin_spring_autumn/images/bilibili-20261101/README.md)保留了提示词和实际文件。生成器宽版是1672×941，仅接近严格16:9；另一版1448×1086为4:3。生成请求写了比例，不足以证明实际像素精确符合规格，交付时应读回宽高，不能把近似画布追认为指定的精确尺寸。

## 八、修改要快，记录要服务交付

先改当前台词源，再同步Edge TTS、字幕、相应编码段及成片；同时更新当前入口，保留旧版的历史记录。本轮改一字，复用18个已编码段，只重做目标场，并在音频实际能装下的前提下保持原23.4秒；不能为了保时长截掉尾音。

检查聚焦本次变化：配音是否读对，字幕是否一致，改句对应的画面和前后切点是否正常，旧段是否按原样复用。不能因为改一字就重拍整局或重编码全部素材，也不应把整理大量过程材料放在用户取得可看片子之前。

本轮已证明：首版即使plan/build和解码通过，仍然会因为内容不完整、台词出戏而被用户否定。解码通过证明文件能读；抽帧证明抽到的画面；两者都不能替代完整观看、听感或用户认可。当前记录的人工签核仍为null，不补写“用户审核通过”。

原片、TTS、段视频和旧版按[通用存储策略](storage-retention-policy.md)复用与限期保留；不无限复制大文件，也不在返工时覆盖旧版制造混淆。本机按[既有本地交付偏好](maintenance/machine-preferences/4-8e1c2f1861.video-delivery.json)交付；本轮没有Bilibili投稿，不把文件生成或Git推送写成已经发布。

## 九、下一次按这个顺序做

1. 用一句话确定本集问题和可见的收尾点，保留用户已经选定的片名与台词。
2. 实际玩到结果，连续录下关键事件的出现、选择和后态；没有拍到的内容先从本期口播删掉。
3. 从原片选过程，压缩战斗、行军和等待，真实缺录才用短截图；结果之后补齐人物、家族与局势收尾。
4. 按玩家视角重写正文，删读界面、制作说明、空泛感慨和重复总结，朗读检查句子是否值得占用时间。
5. 核对人物在模组当时实际展示的称号，不能套用原版CK3称号；配音后按句子对齐画面，核人物、地名、数字及各自统计范围，重做相符字幕。
6. 收尾给模组名、工坊搜索和真实简介链接；按所需画幅准备并核对封面文件。
7. 围绕这次改动完成必要检查，交付明确的新版本链接；有用户修订就局部落实到声音、字幕和成片。

后续收到具体修订，直接更新对应素材并交付；新的审片意见继续追加到本页或相关版本记录。
