## Player-visible changes

- Stop the idle map from repeatedly traversing the 701-state cross-save high-score importer. All 700 persisted tutorial-bit thresholds remain intact, but the importer now becomes active only while game start explicitly requests the record.
- Reject irrelevant birthday pulses before entering the contract effect chain: only the player, with the mod active and birthday contract selected below completion, proceeds to the existing progress logic.
- Publish the complete death-settlement snapshot synchronously and idempotently before the tutorial record writer. Slow persistence can no longer delay the result/terminal consumers or expose a partial settlement.
- Add dedicated finale artwork to the end-of-life settlement.
- Preserve the full game feature set: tutorial-backed import/write, all 700 record thresholds, reincarnation shop, blessing/curse pools, rerolls and seals, all six contracts and PBs, scoring, inheritance settings, ledger, courtier creator, and both heir/no-heir terminal paths remain present.

## Compatibility and migration

Target game version: CK3 `1.19.0.6 (Scribe)`. Existing saves and tutorial-backed records require no migration. The release changes when expensive import work is requested, not the record representation or thresholds. Tutorial mode must remain `Full` or `Warnings` for new persistent records, contract PBs, and collection entries to be written; existing records remain readable.

A new single-player game remains recommended. Do not combine this mod with another mod that replaces the same succession window, same-key `on_action`, GUI, or asset definitions without a compatibility patch.

## Known limitations

- Disabling CK3 tutorials still prevents new tutorial-backed persistence; this is an engine storage requirement and is unchanged from 1.0.0.
- The no-heir settlement projects `window_succession_event.gui` and therefore conflicts with another mod replacing that file.
- Multiplayer and arbitrary same-key mod combinations are not claimed as supported.
- The release acceptance proves correct load, workflow, persistence, settlement, and terminal behavior. It does not claim a controlled years-per-minute benchmark because machine load, game speed, realm size, and simulation state were not held constant for a reproducible A/B measurement.
- The optional Open Kaishek validator had no CK3 fixture and reported unsupported-opcode diagnostics after its parser passed; it was not used as a release gate. The project-owned static validator and real CK3 acceptance are the applicable gates.
