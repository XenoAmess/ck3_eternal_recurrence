## Player-visible changes

- Fix automation being silently disabled when the player character dies and play continues as the player heir.
- Transfer the enabled state and the selected funding policy—treasury only, personal gold only, or treasury first—to the player heir.
- Transfer the selected pause/continue-above-domain-limit policy and reseed one unique 15-day scan loop, so the enable decision does not need to be taken again.
- Confirm in the production scan that all three Mandala Shrine Citadel minor-building chains—`mandala_citadel_shrine`, `mandala_sacred_pool`, and `mandala_vihara_halls`—upgrade normally.
- Keep the Mandala capital Great Project excluded by design; this release does not expand the mod into that separate system.
- Keep the Phase 2 coverage graph at 165 building chains and 605 applicable upgrade edges.

## Root cause

The enable and policy flags were stored on the current player character. CK3's succession replaced that character, while the existing recurring scan still belonged to the dead ruler; no on-death handoff copied the state or started the heir's loop. The production Mandala minor-building edges were already present and valid, so the reported Mandala symptom was the succession shutdown rather than missing building definitions.

Version 4.0.1 adds an `on_death` handoff that applies only to an enabled player ruler with a valid `player_heir`, copies every automation policy flag, and starts the heir through the existing unique-loop guard. This preserves one scan loop instead of stacking duplicate timers.

## Compatibility and migration

Target game version: CK3 `1.19.0.6 (Scribe)`. Existing saves require no conversion. An enabled ruler running 4.0.1 transfers the settings beginning with the next death and player-heir succession. A campaign that already changed ruler while using an older release may need to enable automation once on the current ruler; later successions retain it automatically. Keep a save backup before changing the active mod set. Do not enable this edition alongside the original or another mod replacing the same `auto_build` events, `enable_auto_build` flag or building scripts.

## Known limitations

- The mod upgrades existing eligible buildings immediately; it does not construct empty slots or use the vanilla construction queue/progress bar.
- Domiciles, nomad/herder N/A objects, the Mandala capital Great Project, terminal tiers, leased holdings and holdings with active construction remain excluded.
- Funding/domain policy changes require disabling and enabling automation again; there is no separate live-switch decision.
- Succession state is handed to CK3's `player_heir` during the enabled player ruler's death. It is not an AI-wide inheritance system and does not attempt to preserve state across unrelated character switches.
- All 605 production edges are statically exhaustive; real CK3 acceptance directly exercised the three reported Mandala chains and succession behavior rather than launching once per edge.
