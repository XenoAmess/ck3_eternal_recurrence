# 被动长期平衡矩阵协议

本文定义 1.0 发布前的简单 30–40 年工程平衡样本。它验证长期交易节奏、计分可观测性和明显的数值可达性问题，不模拟会玩 CK3 的玩家，也不替代 `docs/autonomous-player-agent.md`。

## 当前状态（2026-08-19）

- 四夹具、规则重建、34 字段 bit-wire、30/40 年 checkpoint、kind 4 死亡终点和串行聚合器均已写入源码。
- 现有历史 GREEN 只覆盖 `synthetic --balance-smoke-pairs 2`；它不能证明 30 年、自然死亡、pair 10、40 年右删失或完整矩阵。
- 当前 runner 要求自然死亡的 kind 4 terminal wire 先于可交互继承窗到达；如果先看见「继续扮演」，场景立即 RED 并保存诊断，不再点击后等待 wire。
- 因此完整四格执行仍是 1.0 最终发布决策前的待办工程证据。机械路径 GREEN 之后，是否因样本分数调整价格、拒绝惩罚或健康收益，属于独立产品判断，并需重跑矩阵。

## 证据边界

- 场景使用开发树、`-debug_mode` 和 acceptance-only 插桩，因此不是合法排行榜局。
- GREEN 只表示夹具、固定规则、被动策略、1095 日节奏、采样、现场恢复和零 `xar` 错误全部成立；不表示数值天然平衡。
- 四个史实开局的属性、家庭、资源、额外头衔、领地、战争和随机事件都不同，不能把分数差异单独归因于爵位等级。
- 合成测试体是脚本创建并接过奥塔两个伯爵领的标准化替身，不是原生统治者设计器，也不得写成自建角色兼容性实测。
- 单局样本可否定机制节奏和发现量级异常，不能证明奖池分布、寿命因果效果或策略最优性。

## 固定夹具

四局都从 `1066.9.15` 的原版罗贝尔书签进入，再于 `on_game_start_after_lobby`、生产初始化之前切换玩家：

| Cell | 角色 | 定义 |
|---|---|---|
| `count` | 奥塔 `212892` | 原版史实状态；持有 `c_olomouc` 与 `c_prerov`，是双伯爵领开局 |
| `king` | 腓力一世 `214` | 原版史实状态；持有 `k_france` |
| `emperor` | 亨利四世 `1316` | 原版史实状态；持有 `e_hre` |
| `synthetic` | 脚本标准化替身 | 21 岁、健康 5、六维创建基础值各 5、无随机特质、新宗族；接过奥塔两个伯爵领。运行期总值仍可受引擎上下文修正，逐项记录而不强制等于基础值 |

每个夹具都由脚本断言当前玩家、预期最高爵位和关键头衔；失败立即 RED。四局必须串行运行，因为它们共享工坊缓存、用户目录、日志、规则预设和桌面。runner 会备份 `dlc_load.json` 并把运行期播放集收敛为仅启用本工坊项，结束或被强杀后由主流程/watchdog 恢复原文件。

## 固定规则

`tools/run_acceptance.py` 在每局启动前解析本地 CK3 `common/game_rules/00_game_rules.txt`，从每个顶层规则读取其 `default`。CK3 1.19.0.6 当前得到 81 项；runner 完全重建 `LastAppliedRules`，而不是继承用户上次使用的规则，再追加：

```text
xar_on
xar_inherit_100
xar_score_growth
xar_balance_<fixture>
```

完整 `rule -> setting` 列表及规范 JSON 的 SHA-256 写入每局 `report.json`。游戏版本、DLC 和播放集变化仍会改变可比性；本矩阵只冻结已安装版本声明的规则默认值。

## 被动策略

- 纪录预置为 0，走生产首世契约和成长赛道；不进入当铺。
- 每场固定选择第一个可用祝福和第一个可用咒痕。
- 不拒绝、不重抽、不封印、不购买寿命、不选择本世契约。
- 不主动发动战争、婚姻、计谋、建设、活动、议会、生活方式或普通决议。
- 无关阻塞事件由 OCR 选项恢复器选择可点击项，只为继续日期，不按结果优化。
- 30 年为最低有效观察点；达到后若自然死亡则结束，否则继续到 40 年并右删失。30 年前自然死亡保留为 early-death 样本，不伪造死亡或回档。
- 自然死亡必须由生产死亡链先交付 kind 4 terminal wire。继承窗先出现代表提交顺序或稳定玩家 scope 回归，不能通过点击「继续扮演」改变控制权后继续采样。

## 采样与门禁

首对交易结束后、每一对交易结束后、每次生产重开、30 年、40 年和自然死亡时，插桩跨生产计分的提交边界输出 `XAR: BALANCE SAMPLE BEGIN/END` 帧。帧内由生成的 script values 直接对生产 globals 做 `abs/floor/divide/modulo 2`，再用静态 bit marker 编码；runner 按 `tools/balance_wire_data.py` 还原结构化值。该通道不依赖 hidden event 中不可用的动态 localization 上下文：

- 成长分、绝对分和成长基线。
- 交易对数、拒绝、祝福/咒痕 wire ID 与稀有度。
- 重抽、封印、寿命层数和契约状态。
- 六维、四类资源、各级直辖头衔、领地规模、宗族/家族后代。
- 引擎日期、距首对的日数和终止原因。

机制 GREEN 要求：

- 对数从 1 连续递增；生产 `xar.0006` 的重开 wire 必须严格落在 `n×1095` 日。可见窗口打开到自动化点击可能再跨一个 UI 日，成交点击间隔只报告、不冒充 timer 语义。
- 固定策略下拒绝始终为 0，寿命层数和契约 ID 始终为 0。
- 第 10 对后恰有 1 次重抽、0 枚封印。
- 活到 40 年时恰完成 14 对并产生一个 40 年 checkpoint。
- `error.log` 中任何包含 `xar` 的新增行均为 RED。

## 运行

单格摇测：

```powershell
& "tools\.venv\Scripts\python.exe" "tools\run_acceptance.py" --scenario balance-long --balance-fixture count
```

完整串行矩阵：

```powershell
& "tools\.venv\Scripts\python.exe" "tools\run_balance_matrix.py"
```

每格都有独立 JSON/JUnit、截图、OCR、增量日志和现场恢复；聚合器另写 `balance-matrix.json` 与 `balance-matrix.md`。

## 发布前静态审阅信号

以下是公式审阅，不是长期实机结论：

- 开局首对后每 1095 日一对；30/40/50 年约为 11/14/17 对。
- 【琉焰之视】20 XP 约需 57 年，100 XP 约需 297 年；普通 30–50 年人生通常只能触及 10 XP。
- 全拒绝 30/40/50 年只损失约 11%/14%/17%，需要结合实机分量判断是否过于便宜。
- 每场都购买封印的理论累计成本约为 9,669/17,813/31,891；相对 166,600 顶层位阶偏低。
- “借来一代”加后续寿命层可在约 97,591 分附近形成 `+50 Health`；健康改变死亡概率，不能直接换算为固定寿命年数，但量级需要发布前决策。
