# Normal GUI prefunded redemption observations

`financial-markets/redemption-gui` is a saved-campaign case in the existing
GenericAdapter. It retains three independently reviewed local cells:
`prefunded_publish`, `independent_ai_redemption`, and `expired_remainder_return`.
It adds no financial script, observer ARM, timer, artificial holder, balance,
price, AI decision, Host, SDK, parser, or execution runner. Existing lifecycle,
delisting, derivatives, market-evolution and continuous14 contracts remain intact.

Registration and software tests are preparation credit only. A completed local
case can retain honest `NOT_OBSERVED` cells. Its broad business/product release,
financial-clock and toast-delivery flags stay false. The shared postclose
verifier still independently requires actual original normal exits and its
180-second reserve. No deadline is extended for missing liquidity or AI luck.

   graph with that source. Retain the source archive receipt and new baseline

   `xfm_redemption_publish_gui_button`, query the current `xfm_redemption.1`
   context, confirm its actual current option through the public event route,
   fresh-read the outcome, then SAVE and independently reconcile. Publication
   must actually succeed before the adapter dispatches a natural day.
3. `natural-redemption-and-expired-remainder`, calendar D35: the unchanged public
   one-day route handles real event/inbox boundaries through Root. It never
   forces a holder to watch, trade or redeem. At the terminal boundary read the

   expired with a positive escrow remainder may Root use the normal reclaim

   An empty escrow or delayed finance day makes the return cell `NOT_OBSERVED`.

## Phase evidence contract

All phases use the existing Root checkpoint API: current `run_id`, reviewer
`/root`, each declared assertion literally true, and original byte/SHA FilePins
in `evidence`. These assertions are independent Root review obligations; the
adapter does not pretend to decode the financial graph. No ACK proves business.

Baseline adds `source_archive`, `baseline_archive`, `baseline_audit`,
`baseline_raw`, `baseline_whole_graph`. The source receipt's archived bytes/SHA
and native date must equal the real prepared saved input. Each new receipt's
local source must be inside this run's actual prepared profile.

Publication adds `redemption_publication`. Its exact fields are:
`status`, `assertions`, `before_archive`, `after_archive`, `gui_actions`,
`confirmation`, `audit`, `raw`, `whole_graph`, `window`.
Status must be `OBSERVED`. Each `gui_actions` element contains its own original
`query` and `activation` pins. `confirmation` contains `context`, `selection`,
`after_snapshot` pins. These bind the real event and revision; no historical
instance ID, hardcoded option index or cached activation is authorized.

`window` contains exact non-boolean integers for native and permanent
`coin`, `window`, `issuer`, `escrow` identities (the suffixes are `_native_id`
and `_id`), plus `publisher_id`, `controller_id`, `price_cents`,
`initial_budget_cents`, `remaining_cents`, `paid_cents`, `paid_units`,
`reclaimed_cents`, `created_financial_day`, `expiry_financial_day`,
`duration_days`, `status`. The new actual window must start with
initial=remaining=1000, paid/units/reclaimed=0, status1. Issuer and escrow must
be distinct, publisher/controller must equal the prepared player, and
expiry=created+duration. Root reconciles issuer debit=dedicated escrow credit,
unchanged reservations/private wallet/holdings/supply/global cash, proper legal
entity/beneficiary, and absence of this new window before publication.

Terminal adds `redemption_gui_cells`, `physical_archives`, `terminal_audit`,
`terminal_raw`, `terminal_whole_graph`. The archive list order is cold,
published, terminal. The publication cell is repeated exactly, never rewritten.
Each other cell is either `NOT_OBSERVED` with exact `reason` and `evidence`, or
`OBSERVED` with assertions, published/terminal archive endpoints and audit/raw/
whole-graph pins. `REDEMPTION_GUI_COMMON_ASSERTIONS` and the exact per-cell
assertion exported by the adapter must all be true for observed credit.

The AI cell adds one actual new immutable `receipt` witness: native/permanent
receipt, coin, window, payer, payee identities; holder, beneficiary, controller;
paid units/cents, price, financial day, status. It must be a successful natural
one-lot100-unit redemption of this window, price/payment exact, independently
owned private recipient, not player/controller/issuer/escrow self-redemption,
within the financial window. Root separately proves actual AI status/attention,
maker-beneficiary exclusion, receipt absence before, all aggregate window and
cash/coin/utility/project-spend changes, and unchanged unrelated assets. A sampled
receipt does not replace reconciliation of all actual intervening transactions.
The unchanged-assets assertions concern the local operation being reviewed.
Across the natural 35-day interval, list and reconcile actual AI, trading and
daily settlement flows separately; do not require global balances to remain
stationary or treat their total endpoint difference as a redemption payment.
Units transfer to escrow holdings; redemption does not burn supply.

The return cell adds normal `gui_actions`/`confirmation` and `reclaim` containing
window native/permanent IDs, actual `financial_day`, `remaining_before_cents`,
`reclaimed_delta_cents`, `remaining_after_cents`, `escrow_after_cents`, `status`.
Positive remainder must return exactly once to the same legitimate issuer,
after actual financial expiry, leaving remaining/escrow0 and status4. Root must
reconcile an intervening AI redemption and the final reclaim separately even
when both share the terminal SAVE endpoint. No extra SAVE is required to prove
software idempotence; no historical event or action is replayed.

Optional original typed `ck3_query_current_interface_toast_v1` reports can be
retained in ordinary phase evidence, with source/window/news/recipient and actual
UI delivery reviewed independently. No query is automatically dispatched here.
Queue/news creation is not display, unavailability is not empty, and none of
these artifacts changes the three mandatory cell names or creates delivery PASS.
