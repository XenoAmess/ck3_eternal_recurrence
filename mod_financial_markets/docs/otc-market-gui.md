# 市场内双边场外出售

当前为独立源码候选，未采用、未在 CK3 实机验收或发布。运行入口不依赖 Java 服务、Native 特例或验收 fixture。

玩家选择一个真实币，在右侧现货票据下点击“刷新此币持有人”。列表只读该币已有 `xfm_holders`，按永久主账户 ID 排序，每页最多16个持仓。合资格买方必须活着成年、不是本人，且这笔持仓属于其可用的私人法律主账户；项目、做市、创始锁仓、冻结账户和继承副账户不进入本列表。

列表显示姓名与币持仓数量，明确持仓不是现金。不因列出持有人假定对方有钱或愿意买入。选中后用上方原票据调整手数与每手分价，点击“向此人出售”，发送你的币的双边出售报价。本功能不提供向卖方发起买入邀约。原角色右键互动完整保留，仍可向不在本持有人列表的任意合资格买方报价。

新市场按钮与原右键互动调用同一个 `xfm_market_ui_otc_propose_effect`。原互动的四项 validity 条件原样抽成 `xfm_market_otc_can_send_trigger`，显示条件、发送、取消及 AI 自行发起权重不变。新 GUI 额外验证所选币、实际 holders 成员、持仓、法律主账户及持有人均未换人；换币后必须刷新，不会沿旧页向错误的买方报价。

该生产函数固定双方主账户、币、手数、价格、nonce、币价版本和到期金融日，向真实买方发既有 `xfm_market.120` 邀请。对方仍可同意或拒绝；7个金融日后失效，替换或撤回报价使旧邀请无效。点击撤回使用原取消效果并增加 nonce。没有直接触发替代事件、自动接受、虚构买家或写入验收生产变量。

同意后仍由原 `xfm_market_ui_otc_accept_effect` → `xfm_listing_accept_otc_effect` → `xfm_finance_otc_effect` 校验和原子交割。可用币必须真实存在，已被别处冻结的币不能交付；资金来自买方主账户及本人真实金币补差。当前 OTC 没有额外交易费，原规则保持；不借用现货0.3%手续费、价格撮合或成交统计冒充 OTC 成交。

控件位于既有 `xfm_market_window`，新增稳定 runtime_name：

| 控件 | 用途 |
| --- | --- |
| `xfm_market_otc_refresh` | 从所选币持有人刷新第一页 |
| `xfm_market_otc_buyers` | 16行列表容器 |
| `xfm_market_otc_buyer_row` | 选中该实际持仓的法律主账户持有人；按本次 child_path 区分重复行 |
| `xfm_market_otc_previous` / `xfm_market_otc_next` | 翻页 |
| `xfm_market_otc_send` | 向所选买方发送出售报价 |
| `xfm_market_otc_cancel_offer` | 撤回本人未决报价 |

本次只新增用户刷新/翻页时的列表投影，不新增每日处理、全角色扫描或独立市场账户。现有 Native 查询仍会计入隐藏子树；16行约束不能替代真实控件数与 query complete 验收。

离线回归使用原 `ContentValidator` 合并实际运行文件核对 BOM、脚本引用和中英键；对照保留的原生产互动/票据，验证共享资格抽取前后等价、正常按钮仍走原发送/取消生产路径。它们不执行 CK3、不模拟买方同意或交割，不赋予自然 OTC 成交、存档或 UI 渲染资格。AI 接价政策另由独立候选负责，本 UI 不改事件 AI 条件。
