# 每日回调缺口诊断

原始定时器入口与每日处理入口分别保存最近一次实际观察到的向前日期缺口，使用现有单一交易所记录，固定增加13个变量，不创建逐日记录、额外定时器或人口扫描。结算顺序、日期准入、历史未定价保护、资金与交易权限均保持。

两个前缀分别为 `xfm_daily_raw_` 和 `xfm_daily_attempt_`：

| 后缀 | 含义 |
| --- | --- |
| `gap_count` | 新字段启用后观察到的缺口次数；只在首次实际日期差大于1时初始化为1 |
| `gap_count_saturated` | 次数到达十亿后，再出现缺口时标记1，计数保持上限 |
| `last_gap_prev_date` / `last_gap_date` | 该入口相邻两次实际调用的脚本日期 |
| `last_gap_missing_dates` | 两日期差减1，不等于累计缺失天数 |
| `last_gap_attempt_count` | 观察该缺口时、包含本次调用的原入口累计序号 |

每日处理入口另保存 `xfm_daily_attempt_script_date_delta`。原始入口沿已有对应日期差字段。脚本日期为 `current_date` 日序数，不把它直接当作原生 `date_raw` 或按其单位换算；首次无历史、连续日期、同日重复和逆向日期不创建缺口历史。缺少计数表示未知，不能补0。计数饱和后仍更新最近缺口；原入口累计序号若已饱和，最近缺口的序号只能作为下界。

原始 `first_gap_*` 块原文保持，先前首次缺口不覆写、不用最近缺口修正历史。两个入口独立计算：仅每日处理入口缺少调用时，不能伪造原始定时器也跳过日期。新字段只记录观察结果，不触发补结算或重放交易。
