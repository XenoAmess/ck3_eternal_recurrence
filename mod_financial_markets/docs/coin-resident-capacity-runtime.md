# 可回收登记容量与永久币身份

`xfm_registered_coin_count`、旧 `xfm_coin_count` 与 `xfm_next_coin_id` 保留实际累计身份，不递减、不复用。新登记上限改查 `xfm_resident_coin_count`，仍受当前4×市场容量、pending240、每日上市8、成本和冷却限制。币有任何资产或外部权利时继续占用 resident slot；“退市”不等于释放容量。

`xfm_coin_registry` 现在明确为运营索引。只有严格无币、无现金、无未结债/承诺/赎回、无认购残款、无冻结遗产或期货结算/挂单的 state7，才能移至 `xfm_archived_coin_registry` 并释放一次 resident slot。实际 story、永久ID、全部旧收据与引用保持，oracle授权显式归零，历史价格/时间不改。归档并不删除存档对象。

老存档 O(1) 从真实旧 registered counter 取得保守 resident 基线；不重数或凭空改账。已有 issuer 日循环每游戏日最多复核64个旧终态/失败AI申请，删除在循环结束的最多64项队列执行并再次核权利，避免迭代中改源列表。相同游戏日再次调用不重置预算。

每币持久轮次标记保证整轮覆盖前不重审受保护的表头；预算用完后遇到本轮未审候选仅置轻量remaining标记，整次遍历没有剩余候选才前进轮次，且每天最多前进一次。当天一轮已经完成后，同日重入也不开始下一轮复核，次日才可继续。这个保证不依赖global list的排列顺序；固定候选集合C在最多ceil(C/64)个服务日覆盖，有新增/状态变化时不把这个固定集合期限冒称为全R期限。旧state7若携带此前遗漏的赎回/其他权利，恢复state6残权服务并保持关闭交易；不会冷藏该权利。原01的30日回审会让1920个受保护前缀饿死尾项，已由02轮次机制代替；03另封同日完成轮次后不能消费新轮的边界，原01/02均保留。

AI仅自动放弃从未上市、真实认购退款都成功且只剩发行金库/创始人未分配库存的空项目。沿用当前政治控制者授权、真实库存 burn 和原archive入口；玩家项目、外部持有人、退款失败、部分closing、已上市项目都不自动注销。自动流程保存并恢复AI原selected coin，币和宗族/政治实体旧引用不清除。

历史查询：正常市场ID过滤器设为该永久ID、第一页、关闭“仅持有”，再点击正常“刷新”。当前热页为空时只做该ID的冷表查询，可正常选择档案阅读；所有原交易/增发/赎回/复牌状态守卫继续拒绝state7。默认ID0浏览、每日服务和AI不会重新合并历史。该显式单ID冷查询可能扫描冷表；不声称历史lookup为常数复杂度。

边界：本包保留全部 story/账户/零持仓/认购/新闻/收据历史，无存档体积压缩或历史GC，也没有重写全市场日循环。老运营表迁移期间既有日循环仍访问其当前所有元素；64是每日日权利复核/退役预算，不是总扫描上限。清洁历史移出后，四个币日循环和AI候选池会缩小；实际加载、旧档迁移、save/reload与性能计时仍须另行实机验证。

软件候选 `CoinResidentCapacityScriptTest` 的16方法执行真实新脚本及既有退款/库存burn；仅账户选择、历史初始化和无关模块明确作为测试端口。包含1920个保护前缀+干净尾申请跨31日、同日重入和列表重排，以及单个受保护项目完成一轮后同日预算/标记不变、次日可重审。未执行CK3、不授实机成功。CI沿现有完整Maven verify自动发现该新增Test；必要增量入口：`mvn -f mod_financial_markets/tools/pom.xml -Dtest=CoinResidentCapacityScriptTest test`。先执行16个定向用例，再由唯一构建owner执行完整验收，保留实际失败。
