# 实现计划

日期：2026-11-18。需求基线：[综合设计第 3 版](../../docs/design/futures-and-virtual-currency-markets.md)、[发行与退市](../../docs/design/futures-and-virtual-currency-listing-lifecycle.md)、[债务剧情](../../docs/design/futures-and-virtual-currency-debt-events.md)。本文中的阶段完成须有对应证据，代码存在不等于游戏验收通过。

## 1. 产品与维护边界

做成**一个 Mod、一个 Workshop 条目**。内部拆成共同金融底座、币现货、期货、主体与宣传、债务与新闻六个模块。两个市场共享同一账户可用资金、冻结资产、币身份、债务、继承和数据版本，避免分成两个 Mod 后出现抵押重复使用、载入次序和两套迁移问题。

现货与期货可在游戏规则中分别开关。关闭只阻止新增风险，仍继续撤单、减仓、到期、债务及赎回；有义务的模块不能直接卸载。只有运行时功能都完成且组合验收通过，才向玩家开放相应开关。

游戏运行时使用 CK3 脚本、GUI、本地化；不要求 Java、服务器或 DLL。Java 21 / Maven / Quarkus 用于参考结算、生成、静态校验、fixture 和打包。开发中的参考引擎不会被宣称为 CK3 已采用的运行时。

## 2. 模块与存储合同

| 模块 | 职责 | 依赖与边界 |
| --- | --- | --- |
| finance | 主体/账户/资产唯一 ID、资金冻结、手续费、事务检查、日序、存档版本 | 唯一可更改公共资金与所有权的底座 |
| spot | 发行、上市、有限报价、价格时间优先限价簿、持仓/撤单 | 只用真实币和真实金币，不无限兑付 |
| futures | 合约、多空、杠杆、标记、逐日结算、强平、到期 | 同一钱包、独立保证金；穿仓转债务 |
| identity | 个人、家族、宗族、政权、教团等主体、控制者变更、章程 | 主体 ID 不等于当任角色；继承不复制财产 |
| influence | 宣传、绑定概念、背书/担保、增发与操盘 | 宣传改变信息和真实订单，不直接制造价格收益 |
| consequences | 债务、援助、重整、追责、20 个离世叙事、全球新闻 | 死亡不消债；广播有队列及去重 |

生产对象分开存放：币、发行主体、场所交易对、账户持仓、委托、合约仓位、债权债务、公告。发行人死亡不销毁币；资产退市不销毁持有人。故事/变量表等 CK3 具体载体须先完成身份、精度和保存原型，再扩容，不能用成千上万虚构角色冒充交易对象。

金额为整数分，100 枚币为一手，价格为分/手。每次成交计算一份本金，双方使用同一结果。现货双边费率 0.3%，按原始订单累计成交额计费；部分成交不重复收最低费用。公共可用余额不能同时承诺给多个币、挂单和保证金。

每个 effect 文件按用途拆分，目标 1–10 个顶层 effect，最多 20 个。使用 xfm_ 前缀，原版 on_action 只追加自有钩子，不覆写原版市场规则。

## 3. 阶段、顺序与退出标准

| 阶段 | 实现工作 | 完成标准 |
| --- | --- | --- |
| A0：本轮开工包 | 独立产品骨架；真实金币/币库存的个人币发行与双向报价原型；玩家入口；低阶/无地 AI 资格与付费冷却；Java 整数账本、限价撮合及性质测试；显式打包清单 | 软件验证有真实结果，运行脚本和未验证边界明确；**不授完整 A 阶段资格** |
| A1：存储与日历证明 | 账户/币/订单实体载体；多人持有不同币；日序幂等；死亡与继承；保存/重载；分精度；后台操作入口 | CK3 1.21 同一存档热/冷读取一致，原型与参考算例一致；没有自成交获利、资金/币复制 |
| A2：完整每日现货 | 将价格时间优先委托簿落到脚本；限价/市价保护/部分成交/撤单/手续费；全市场列表、搜索和分页；AI 轮转买卖；至少百币与基本宣传 | 玩家发行并连续买卖多个 AI 币；正常冷币当天可交易；真实对手资金；AI 含低阶和无地者；无月度交易窗口 |
| B：发行主体和操盘 | 两档发行成本、认购退款、锁仓解锁、增发/销毁、家族/宗族/政权绑定、宣传受众、控筹/拉升/出货、调查和政治追责 | 完成融资→宣传→真实买盘→用途兑现或违约；身份更替与资产责任正确；微型 20 金和标准 200 金算例一致 |
| C：期货核心 | 真实匹配多空、1/2/3/5/10 倍、独立保证金、日盯市、止盈止损、减仓、强平、到期；防对倒标记；缺口债务和有限基金 | 20% 杠杆损失及跳空穿仓算例、基金不足、赢家未付债权、重载不重复清算均通过；不能拿自发币无限抵押 |
| D：退出与世界后果 | 30 日退市流程、迁移/终结合约、无价格待结算、OTC 和残余索偿；重整援助；20 种非细节离世剧情；全球气泡和新闻簿 | 每条权利追踪到实际收款或未付债权；远方 AI 的严重事件也能查到；重复事件零二次死亡/扣款；不自动杀玩家 |
| E：规模与扩展 | 2048/4096/8192 活跃档压测，16384 存量上限另测；永续资金费实际转移；合格市场 20 倍；商品指数；多人同步；开关/迁移 | 在实际 CK3 场景测量后才开放相应档位；性能不过先优化或降新增风险，不跳过存量清算 |
| Release | 简中/英语、教程、兼容、干净升级、canonical staging、公共验收、永久 changelog | 完整选定范围业务及正常退出通过，明确未开放功能；Workshop 首发另记真实结果 |

先实现 A0–A2，再接 B/C；身份/债务接口提前保留，避免期货另造一套钱包。发行、宣传、退市和全球后果都在正式范围内，不因第一包只做个人币而删需求。

## 4. 性能预算及发行约束

最终标准容量目标 4096，2048 为保守档，8192 为扩展档；16384 是标准活跃4096的四倍存量记录上限，不是第五个活跃档。原型允许较小容量以查清存储和日历，但不把原型上限当最终设计，也不预生成 4096 个无买家的币。

所有成年 AI 包括无地和低阶角色都有发行资格。真实费用、个人一个活跃发行加一个筹备项目、24 个月发行冷却、认购需求和每日最多 8 个新上市限制频率；担保必须有真实付款人，不能靠身份绕过成本。

生产调度使用增量候选和稀疏持仓索引。目标每日最多 512 次 AI 主动决策、每人 6 个关注币、64 个详细热点簿；所有正常币当天可提交委托，所有未平杠杆仓位每日风险检查。不得每个 AI 扫描所有币，也不能把冷币的交易推迟到月末。

标准场测 4096 币、64 簿、512 次决策/日、4000 仓位：新增日处理 P95≤100 ms、P99≤300 ms，详情刷新≤16 ms，状态预算 16 MiB。这些是**待验证目标**，Java 测时不能代替游戏脚本测时。过载先缩减新搜索、宣传扇出、历史和新上市/开仓，保护存量义务。

## 5. 工程交付

1. 每个工作包同步代码、必要测试和实际状态，正常 commit/push；不等待全部功能写完才集成。
2. 修改模块使用增量 Maven 验证，不反复构建未变的大型智能体工程。静态工具检查 BOM、定义、引用、清单和本地化，明确不证明引擎语义。
3. 游戏验收只走仓库公共入口，产品提供数据与 fixture，不复制 host / DLL。共享后台能力和 1.21 资格未齐时，保留真实阻塞，继续不依赖它的软件实现。
4. 本轮不恢复旧自动游玩。CK3 实测保持最小化、不抢焦点；先核本机身份、EXE、离线凭据与现场归属。
