# 期货撤单记录

新版本在首次取消开放期货委托时记录原因、金融日、是否处于历史补期，以及实际释放金额。活动委托、历史委托和共用行模板保持一致；开放委托不显示取消说明。旧已取消委托继续显示原因或退款金额未记录，不按事后余额补写历史。

原因码是版本1的稳定存档字段：

| 码 | 原入口 |
| --- | --- |
| 1 | 未指定原因的原直接取消调用 |
| 2 | 持有人主动取消 |
| 3 | 关闭期货新风险 |
| 4 | 账户冻结 |
| 5 | 缺少当日可靠报价，含历史补期的未定价保护 |
| 6 | 标的仅允许减仓 |
| 7 | 原杠杆超过当前上限 |
| 8 / 9 | 委托价低于 / 高于当前价格带 |
| 10 | 定期合约到期 |
| 11 | 减仓目标缺失或关闭 |
| 12 | 来源仓位结束，撤销关联减仓单 |
| 13 | 新强制退出单替换旧退出单 |
| 14 | 强制退出即时单的未成交余量 |
| 15 | 仅减仓切换撤销开仓单 |
| 16 | 未成交余量不能进入委托簿 |

同一风险检查同时命中多个条件时，沿表中3至10的固定顺序记录首因；原风险OR、资金释放、状态及归档顺序保持。记录不授予交易权限，也不触发额外付款。

`xfm_cancel_receipt_version=1` 最后写入。调用前捕获同一真实账户和预留，调用后重新确认身份，并检查：

- 释放额 = 预留原余额 − 预留后余额；
- 可用资金后值 = 原值 + 释放额；
- 冻结资金后值 = 原值 − 释放额。

正余额释放还须本次确实调用资金API、返回成功且预留归零。原余额为零时，可核实零释放，但不引用上一次API结果。缺少字段、身份变化、拒绝或三项现金关系不成立时，`xfm_cancel_release_verified=0`，释放金额字段缺失；不将请求额、旧结果或缺失值填成实际付款。

记录持久化原因、日、补期标记、本次API调用及结果、核实标记和实际前后现金值。再次取消已关闭订单不覆写初次记录、不再释放资金。通用存档投影只增加新 `cancel_*` 可选字段；旧记录缺失字段时不改变其数字投影。

AI开仓同时增加最小预算预检：选择原杠杆后，先按现有上沿价格及向上取整的保证金、手续费计算一手成本，预算不足则不创建空合约。原尺寸计算、实际扣款、风险、容量和所有角色资格检查继续执行。该优化不保证市场随时有对手或成交。
