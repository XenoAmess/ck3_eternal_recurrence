# IndexTTS 正式片的局部重复检查

第 1 集 R7F 正式片交付后，用户在 21 分钟附近听到“折合六十二点七七……”重复。冻结的 C10 中文稿和对应字幕只含一次；原始 IndexTTS WAV 的独立 Whisper-base 短片段识别在相邻两段各记录一次 `62.775`。第一次整段 ASR 虽然也记录了两次，但当时的门禁只查音频长度、首尾覆盖和粗略字符比例，因此误报为“粗筛通过”。**粗筛通过不能解释为没有局部口吃、复读或错词。**

本次修正保留原 WAV、原 ASR、剪切前后的字节身份与编辑清单。在原 C10 的 `87.154694–89.943855` 秒两个零幅值点之间，精确剪去多说的一次，其他 22 段 WAV 不变；剪切外的 PCM16 逐样本与原文件相同。修正后的 C10 短片段和整段独立 ASR 均只识别一次同一数字短语；全 23 段的相邻数字短语筛查从旧版仅 C10 命中，变为修正后零命中。这些是机器筛查，不能取代人耳听审；ASR 对数字、专名和音色的判断尤其有限。

后续使用 IndexTTS 制作长片时，逐段配音完成后先做局部复读筛查，至少比较 ASR 中相邻重复的长数字、短语与冻结句稿；命中项必须回听或用独立短片段识别核实。不能只看整段转写相似度和时长比例。修复任何音轨后须建新 attempt，记录原音频、剪切/重生成方法、新音频及复核证据；重新驱动字幕和章节时间轴。最终 MP4 先上传到既定 OneDrive 文件夹，确认客户端“已上传”，再对该**上传副本**做完整解码、音频目标片段转写和声画抽查。旧版媒体不覆盖，旧审核也不能借给新文件。

现有辅助命令 `python -m war_ai_promo.audit_index_local_repetition --source-asr-dir <逐段 ASR 目录> --output <新报告路径>` 读取 23 份已生成的转写 JSON，标记六秒内相邻重复的五位以上数字短语。报告只是候选清单，不能把“零候选”当成没有所有语言层面的复读；对确切问题仍需逐段声源和最终片段双重核验。
