# 战争系列制作复盘：第 1 集 R7D → R7E

2026-09-26。本文记录第 1 集墨西拿同场计算片的可复用制作规则。R7D 的[全量文案审计](../episode-01-battle-win-probability/r7d-brown-gold/full-copy-audit.md)、[开场设计](../episode-01-battle-win-probability/r7d-brown-gold/opening-recut.md)是发现问题与编辑意图；[R7E 构建记录](../build-records/episode1-r7e-opening-recut-20260926.json)是本次实际成片、上传和检查的字节证据。两版成片及其 attempt 都保留历史身份。

## 这次真正改变了什么

R7D 的前两分钟先交代选题、编号、预测和方法，观众还没看到本集最有张力的战况。R7E 改为从同一场墨西拿战斗原片 275 秒和 280 秒的战斗窗开始：罗贝尔守方 `1,222 → 1,156`。先让观众看到战线人数变化并提出“这笔账从哪一步开始”，随后才讲战斗身份、战宽与算式。标题和计算卡不能抢在问题之前；事实悬念比抽象口号更能承载一部长篇机制片。

设计稿设想前 6 秒让实机占满画面，实际 R7E 首 cue 用棕金版式把两张真实帧并列，后一帧先暗后亮。这个差异应保留在记录里：机器抽帧和人工查看关键帧确认了数字、字幕及配色位置，但没有用户 1× 完整审片反馈，不能把“设计稿全部实现”或“审美已获认可”写成事实。下一集开头先做有声音和字幕的 30–60 秒可观看段，核对节奏，再批量渲染整片；不能只审台词或静态分镜。

## 后续每集的制作规则

1. **先定同场问题，再排计算顺序。** 每段按“此刻玩家看见什么 → 要解释哪个变化 → 输入与每一步整数运算 → 算出什么 → 下一帧是否验证”组织。R7E 把第 5 日主战、森林 `floor(1,645×90,000/100,000)=1,480` 放在宽度份额和出伤之前，避免先使用一个尚未解释的 `1,480`。
2. **把四层数字逐项对齐。** 口播、同秒原片、屏幕计算卡、原生回执必须说同一战斗、同一日边界和同一对象。原片 275→280 秒能支持守方 `1,222→1,156`；250→260 秒显示的是增援过程，不能借其画面讲前一个变化。每个 cue 保留原片秒点与帧哈希；片子渲染后按最终 MP4 再核一次，不能只看素材账。
3. **先说玩家名词，再给研究编号。** `side 0/1` 要映射到攻方与罗贝尔守方；`#50/#51/#65` 要映射到罗贝尔征召兵、长枪兵和骑士图尔吉塞的一人战斗条目。明确区分玩家界面能直接看到的兵力、战宽、阶段、溃逃/战死显示，和研究回执里的逐团 raw、有效坚韧及截断步骤。
4. **显示值、原始整数和机制名不能互换。** `1,222→1,156` 是界面整数，底层 `122,225,074→115,629,874 raw` 除 `100,000` 后精确少 `65.952` 人当量；“少 66 名现役”不能直接说成“阵亡 66 人”。主战 `36%` 是硬伤拆分比例，追击软伤转硬伤属于另一条机制。顶部“现役 0”与原片 420 秒下方红字“败退 761”可以同屏存在，必须分别标注。
5. **让图、字幕、音乐组成同一个系列。** 包装色引用第 0 集深棕、金、米白系统，检查左上来源卡、底部字幕带和计算卡，不能只检查主背景；游戏原版 UI 保持原色。沿用唯一主题曲与固定音乐增益，不做旁白驱动压低。中文字幕按能读完的语义段展示，并检查安全区与卡片重叠。
6. **证据范围跟结论走。** 同日两侧出伤与部分兵团损失的整数对拍，只支持已展示的局部计算；不能外推成完整战斗胜率。智能体用途应列出真实输入（当日人数、战宽、优势、固定缩放、反制后有效攻击等）和当前可用范围，不把“研究内核可复算”说成“已能自主决定宣战”。下一期要研究的追击深层抽签、骑士人物伤死、增援撤退与终局，仍按[系列规划](../series-roadmap.md)另列，不在本片口播中解释缺片清单。
7. **交付按新文件字节重新审。** 每次改稿建独立 run，保留旧 TTS、片段、失败 attempt、配置快照和回执。新片只复制允许的 MP4 到固定 OneDrive 选择性同步目录，读回客户端“已上传”，然后检查该目录中精确文件的 SHA、完整解码、章节、开场关键秒帧、字幕与配色。R7E 自动检查了 23 章、23/23 章配色、23/23 cue、26 项数字及 122 份引用素材；这些是机器门禁与抽查，仍不等于用户 1× 完整观看和签核。

新集开工前，先为开头挑出确切原片前后帧，并把问题写成一句能由画面回答的话；冻结句稿前做逐 cue 的四层数字核对；成片上传后再对用户实际收到的文件审片。任何一步发现声画错位，都建立新 attempt 修正，不覆盖旧交付物或借旧版审阅状态。
