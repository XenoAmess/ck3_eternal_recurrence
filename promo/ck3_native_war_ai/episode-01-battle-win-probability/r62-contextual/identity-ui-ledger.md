# 第 1 集人物、兵种与游戏界面名称对照

本表供 R6.2 文案和数字卡使用，限定 CK3 1.19.0.6。研究编号、定点原始整数和公式仍保留；首次口播与每张相关卡必须同时给出观众在游戏中能识别的对象。**没有独立 UI 字段的中间量，必须直接标为内部计算量，不得给它虚构一个面板名称。**

证据分三组，严禁串成同一战斗：

- 墨西拿：`ck3_autonomous_player/tests/fixtures/combat/episode01_messina_paired_day05_r14.json` 绑定第 5 日、战斗省份 2633、守方 Army 18、owner/commander Character 29829、RegimentID 50/51/65；原始 `episode01-paired-counter-trace-attempt-010/d05-immutable.ck3` SHA-256 `695f1fde17457004eb8d060c1f21146c3605374806dabacf6fb5fab386882885`。用 Rakaly 0.8.19 只读解码出的 `episode01-identity-labels-001/d05-melted.ck3` SHA-256 `3ea734aeca5992ca8ddad87564c1b7090a7ac677df23c1069764a5c93f42c4ca`；其中 `armies.regiments.51.type="pikemen_unit"/army=18`、`.65.knight=33437/army=18`，人物 29829 `first_name="Robert"`、33437 `"Turgise"`。原生产期 v3 `maa_type.key=null` **不能**当作存档里没有兵种类型；对 65 号，它是骑士的一人战斗 entry，不能口播为普通兵士。同一存档中 RegimentID 115 `knight=34120/army=16777231`，该敌军 owner/commander 32725；人物 34120 `first_name="Amr"`、32725 `"Tamim"`。冻结第 26 日战报的 `killer=34120` 与此人物 ID 相同，故可称“塔米姆军骑士阿姆鲁”，但第 26 日击杀仍属于独立回放，不能并入第 5 日伤亡公式。
- R0217：[`battle-simulation.md`](../../../../docs/ck3-native-ai/battle-simulation.md) 与 [`actual-contact-scope.md`](../../../../docs/ck3-native-ai/actual-contact-scope.md) 绑定 CombatID 738197508：side 0 是敌军 Army 50331863、commander Character 31797；side 1 是玩家军 Army 83886367、commander Character 29829。墨西拿同源角色存档中的 31797 名为 Nikephoros，但敌军**持有者**没有从 R0217 冻结回执得到名字，故只称“尼基弗鲁斯率领的敌军”，不称其拥有的军队。R0217 数字不是墨西拿画面当日的数值。
- 游戏名称取自本机原版 `C:/SteamLibrary/steamapps/common/Crusader Kings III/game/localization/simp_chinese/` 的 `combat_l_simp_chinese.yml`、`gui/combat_window_l_simp_chinese.yml`、`game_concepts_l_simp_chinese.yml`、`regiment_l_simp_chinese.yml`、`names/character_names_l_simp_chinese.yml`。`Robert=罗贝尔`、`Turgise=图尔吉塞`、`Nikephoros=尼基弗鲁斯`、`Ashraf=阿什拉夫`、`Ramadan=拉马丹`、`Amr=阿姆鲁`、`Tamim=塔米姆`、`pikemen_unit=长枪兵` 均按该原版简中键。
