# 《食人赋能》Mod 静态分析报告

## 1. 报告结论

《食人赋能》是一个围绕“吞食囚犯并永久强化角色”设计的 CK3 Mod。它扩展了原版食人处决选项，并在宫廷囚犯界面加入批量吞食和食人记录功能。

吞食角色可以获得随机基础属性、遗传特质、将领特质、虔诚和遗骨宝物；累计吞食人数还会提升“食人魔王”成长特质。其数值强度很高，尤其是高阶遗骨和 100 人成长奖励。

本 Mod 同时存在明确的兼容性和实现风险：它完整覆写两个大型原版文件；批量吞食绕过了大部分原版处决脚本；宫廷 GUI 副本删除了当前原版的角色筛选窗口定义；部分脚本还保留了当前游戏版本不存在的旧特质 ID。

本报告基于 CK3 1.19.0.6 游戏文件与 Mod 源码的静态对比，没有进行游戏内加载或行为验收。因此，本文将“源码明确实现的行为”与“需要实机确认的风险”分开描述。

## 4. 玩家可见流程

### 4.1 单独吞食

Mod 保留原版处决互动，并强化其中的“砍头……然后吃掉”选项。该选项仍只在以下任一条件成立时显示：

- 角色信仰允许食人；
- 角色拥有食人者特质；
- 角色拥有食人秘密。

确认后，Mod 会先执行新增的属性、特质、遗骨和记录结算，然后继续执行原版的处决流程。

如果信仰允许食人且执行者尚无食人者特质，单独吞食会为执行者添加该特质。

### 4.2 批量吞食

宫廷囚犯页面新增“批量吃掉”按钮。按钮仅在玩家拥有食人者特质或信仰允许食人时显示，点击后弹出二次确认框。

确认后，脚本遍历所有囚犯，并跳过带有以下任一锁定标记的角色：

- `mass_action_locked`
- `is_mass_action_locked`

其余囚犯全部调用统一的单体吞食效果。

批量模式和单独模式并不完全等价。批量模式直接调用 `death = { death_reason = death_execution }`，没有逐个执行原版 `execute_prisoner_effect` 以及完整的互动合法性检查。批量模式也不会像单独模式那样，在信仰允许食人时自动添加食人者特质。

### 4.3 食人记录

囚犯页面新增“食人记录”按钮。打开时，脚本重新统计记录列表中的受害者，并按生前最高头衔分为：

- 普通人；
- 伯爵；
- 公爵；
- 国王；
- 皇帝。

记录窗口逐条显示受害者姓名、该次吞食对应的基础属性档位、成功掠夺的特质和食用日期。姓名可以点击并打开对应角色页面。

Mod 将受害者加入玩家的 `devoured_ledger_list` 变量列表，并在死者身上设置 `do_not_prune` 变量，意图让已死亡角色继续保留在记录中。

## 5. 吞食收益

### 5.1 基础属性

吞食收益取决于受害者当时持有的最高头衔。每一点属性都在外交、军事、管理、谋略、学识和勇武六项中等概率独立抽取，因此同一项属性可以在一次吞食中被重复抽中。

| 受害者最高头衔 | 随机属性点 | 死者记录特质 |
| --- | ---: | --- |
| 帝国级 | 5 | `devour_stat_5` |
| 王国级 | 4 | `devour_stat_4` |
| 公爵级 | 3 | `devour_stat_3` |
| 伯爵级 | 2 | `devour_stat_2` |
| 其他 | 1 | `devour_stat_1` |

这里的 5 点并不是六项属性各加 5，而是独立进行五次“随机属性 +1”。

### 5.2 神职人员奖励

受害者符合以下任一条件时，吞食者获得 200 虔诚：

- 是神职人员；
- 拥有 `devoted` 特质；
- 担任宫廷祭司；
- 是其信仰的宗教领袖。

单独吞食还会在死者身上记录 `record_is_clergy` 变量，但当前 GUI 和其他脚本没有读取它。批量吞食不会设置该变量。

### 5.3 压力与疾病

每次吞食都会执行一次以 `medium_stress_impact_loss` 为基础的压力影响，即设计意图是降低中等程度压力。

相较于原版食人处决，Mod 删除了：

- 慈悲和宽容人格对应的额外压力调整；
- 20% 获得疾病并触发健康事件的风险。

因此，源码层面上吞食被改造成稳定减压且没有原版疾病风险的正收益行为。

## 6. 特质掠夺

### 6.1 智力、体质和美貌

以下三个遗传特质系列使用相同的升级算法：

- 智力：`intellect_good_1/2/3`；
- 体质：`physique_good_1/2/3`；
- 美貌：`beauty_good_1/2/3`。

每次吞食在每个系列中最多提升一级：

| 受害者等级 | 吞食者当前等级 | 成功结果 | 成功率 |
| ---: | ---: | --- | ---: |
| 3 | 2 | 吞食者升至 3 | 20% |
| 3 | 1 | 吞食者升至 2 | 40% |
| 3 | 无 | 吞食者获得 1 | 80% |
| 2 | 1 | 吞食者升至 2 | 30% |
| 2 | 无 | 吞食者获得 1 | 60% |
| 1 | 无 | 吞食者获得 1 | 40% |

如果吞食者已经拥有同系列的相同或更高等级，则不会继续提升。

脚本会同时删除或降低死者对应特质，把死者身上最终保留的特质当作“本次成功获得内容”的记录标记。食人记录窗口读取的正是这些死者特质，而不是单独保存的一份结果数据。

### 6.2 纯血和多产

如果受害者拥有而吞食者没有，则以下特质分别独立进行一次 20% 成功率判定：

- `pure_blooded`；
- `fecund`。

### 6.3 将领特质

以下 17 个将领特质分别独立进行一次 20% 成功率判定：

1. `military_engineer`
2. `organizer`
3. `logistician`
4. `flexible_leader`
5. `aggressive_attacker`
6. `unyielding_defender`
7. `cautious_leader`
8. `reckless`
9. `holy_warrior`
10. `forder`
11. `open_terrain_expert`
12. `rough_terrain_expert`
13. `forest_fighter`
14. `desert_warrior`
15. `jungle_stalker`
16. `winter_soldier`
17. `reaver`

如果吞食者已经拥有相同特质，则不会重复获得。脚本还把进攻者/防御者、谨慎/鲁莽视为互斥组合，拥有组合中的任一项都会阻止获得另一项。

由于各特质独立判定，一个拥有多种优秀特质的受害者可能在一次吞食中提供多项能力。

## 7. 遗骨宝物

每次吞食都会以受害者为制作者创建一件“某某之骨”宝物。宝物类型为 `miscellaneous`，使用 `artifact_bone.dds` 视觉。

| 受害者最高头衔 | 稀有度 | 敌对计谋防御 | 恐怖值基准 | 其他 |
| --- | --- | ---: | ---: | --- |
| 帝国级 | Illustrious | 敌人的敌对计谋成功率 −40 | +40 | 直辖上限 +1 |
| 王国级 | Famed | −20 | +20 | — |
| 公爵级 | Masterwork | −10 | +10 | — |
| 伯爵及以下 | Common | −5 | +5 | — |

修正是否生效仍取决于 CK3 对该宝物类型的装备或展示规则；源码只保证创建宝物并附加修正。

## 8. “食人魔王”成长特质

第一次吞食时，执行者获得 `devour_master`，中文名为“食人魔王”。每名受害者提供 1 点 `cannibal_track` 经验。

| 累计吞食人数 | 新增奖励 |
| ---: | --- |
| 10 | 敌对计谋阶段时长 −20；敌对计谋成功率上限 +10；成功率 +10 |
| 30 | 敌对计谋阶段时长再 −40；成功率上限再 +20；成功率再 +10 |
| 50 | 压力增长 −50%；健康 +0.5 |
| 80 | 绑架计谋阶段时长 −20；健康 +0.75 |
| 100 | 最大敌对计谋数 +1；计谋隐秘度 +40；恐怖值基准 +999 |

按照文件内注释，轨道奖励按阶段累加。达到 100 人后，`dread_baseline_add = 999` 在正常恐怖值上限下等效于长期维持极高恐怖值。

## 9. 单独吞食与批量吞食的实现差异

| 行为 | 单独吞食 | 批量吞食 |
| --- | --- | --- |
| 基础属性奖励 | 有 | 有 |
| 特质掠夺 | 有 | 有 |
| 遗骨宝物 | 有 | 有 |
| 食人记录 | 有 | 有 |
| 食人魔王 XP | 有 | 有 |
| 神职人员 +200 虔诚 | 有 | 有 |
| 合法信仰自动给予食人者特质 | 有 | 无 |
| `record_is_clergy` 标记 | 有 | 无 |
| 原版处决互动合法性与费用 | 保留 | 大部分绕过 |
| 原版 `execute_prisoner_effect` | 执行 | 不执行 |
| 死亡方式 | 后续由原版处决流程处理 | 直接调用 `death_execution` |

这两条路径复制了部分相同逻辑，而不是让单独吞食也调用 `devour_single_character_effect`，因此已经出现行为漂移。

## 10. 已确认的问题与风险

### 10.1 大型原版文件覆写

Mod 直接提供与原版同路径、同文件名的：

- `common/character_interactions/00_prison_interactions.txt`；
- `gui/window_court.gui`。

它没有使用小型独立文件或更窄的注入入口。这意味着：

- 与任何修改监狱互动或宫廷窗口的 Mod 存在明显加载顺序冲突；
- CK3 更新这些原版文件后，本 Mod 会继续提供旧副本，遮蔽上游修复和新增功能；
- 即使 `supported_version` 没有变，另一个 Mod 也可能使其中一份完整覆写失效。

### 10.2 宫廷筛选窗口缺失

与本仓库中 CK3 1.19.0.6 的原版 `window_court.gui` 对比，本 Mod 副本删除了两段 `window_character_filter` 定义，其中包括名为 `court_character_filter_window` 的宫廷筛选窗口和囚犯筛选配置。

这不是增加吞食 UI 所必需的改动，可能造成宫廷或囚犯角色筛选窗口缺失、功能不完整或依赖其他文件中的偶然定义。具体表现需要实机确认。

### 10.3 批量吞食绕过原版处决链

批量吞食的有效性检查只要求“至少存在一名囚犯”，随后直接遍历并杀死所有未锁定囚犯。它没有逐名检查原版处决互动中的：

- 当前斗争阶段限制；
- 特殊囚犯状态；
- 共治、摄政和政治处理；
- 处决费用；
- 原版处决效果及相关回调；
- 原版通知、事件和部分宗教或合法性后果。

引擎自身仍可能根据角色死亡产生通用后果，但源码明确没有调用原版的完整脚本管线。因此，“批量吃掉”不能视为“自动逐个点击原版食人处决”。

### 10.4 锁定检查与按钮有效性不一致

批量按钮的 `is_valid` 只检查是否存在囚犯，没有检查是否存在未锁定囚犯。当地牢里只有已锁定角色时，按钮仍可能保持可用，确认后不吞食任何人但仍发送完成提示。

### 10.5 旧智力特质 ID

`devour_steal_genes_effect` 在正确的 `intellect_good_1/2/3` 分支之后，还保留了对以下 ID 的检查：

- `genius`；
- `intelligent`；
- `quick`。

本仓库的 CK3 1.19.0.6 原版 trait 定义使用 `intellect_good_1/2/3`，没有定义上述三个脚本 ID。这些分支是旧版本残留，至少属于无效死代码，并可能在错误日志中产生未知 trait 报错。前面的当前版本分支仍然能够处理正常智力遗传特质。

### 10.6 本地化范围有限

Mod 只有简体中文本地化。其他语言下没有英文回退文件，界面可能显示本地化 key。

此外，宫廷 GUI 将“天才”“海格力斯”等特质名称直接写成中文字符串，没有走本地化 key；脚本效果中的完成提示也有硬编码中文。即使以后增加其他语言文件，这些内容也不会自动翻译。

### 10.7 编码不符合本项目规范

本 Mod 的多数 `.txt`、`descriptor.mod` 和 `devour_formatting.gui` 文件是无 BOM UTF-8，只有 `window_court.gui` 和简体中文 YML 带 UTF-8 BOM。

无 BOM 文件中包含中文 descriptor 名称、注释和硬编码提示。依据本项目既有的 CK3 编码经验，这可能造成启动器名称或脚本文字乱码；是否在当前游戏环境实际发生需要加载验证。

### 10.8 非玩家专用边界

批量吞食 UI 通过 `GetPlayer` 调用，实际面向玩家。普通吞食则被写入全局 `execute_prisoner_interaction`，没有添加 `is_ai = no` 或等价闸门。

因此，该 Mod 不满足本仓库主 Mod 的“所有新增内容只对玩家生效”要求。AI 是否会实际选择新增的食人处决方式仍需实机或 AI 行为验证，但源码没有主动排除 AI。

### 10.9 冗余和未使用定义

- `open_devour_ledger_sgui` 和 `close_devour_ledger_sgui` 操作角色变量 `devour_ledger_open`，但实际窗口使用 GUI 变量 `devour_ledger_window_open`，且没有其他调用点。
- `record_is_clergy` 被设置但没有读取。
- `common/text_formatting/devour_text_formatting.txt` 位于当前原版不存在的 `common/text_formatting` 数据目录，而且只定义部分颜色；实际 GUI 颜色由 `gui/devour_formatting.gui` 再定义一次。
- `events/` 为空，descriptor 的 `Events` 标签不能反映真实实现方式。

这些项目大多不会阻止核心吞食功能，但表明代码仍有未完成的重构或遗留实现。

## 11. 平衡性评价

该 Mod 的设计目标显然不是原版尺度的平衡，而是提供快速、永久且可重复叠加的角色成长体验。主要强度来源包括：

- 任意普通囚犯都能永久增加一点随机属性；
- 一次吞食可以同时掠夺多个不同类别特质；
- 吞食没有原版疾病风险且能够减压；
- 每名受害者都会生成一件遗骨；
- 批量模式可以一次处理整个地牢；
- 100 人奖励提供 +999 恐怖值基准；
- 帝国级遗骨附带直辖上限 +1。

如果遗骨修正可以通过展示或装备大量叠加，数值膨胀会进一步加速。即使遗骨不能全部同时生效，永久属性、特质和成长轨道已经足以显著降低游戏难度。

## 12. 总体评价

从功能设计看，这是一套完整度较高的“吞食成长循环”：

1. 通过战争、绑架或其他方式获得囚犯；
2. 单独或批量吞食；
3. 获得即时属性、特质、虔诚和宝物；
4. 在食人记录中收集受害者；
5. 通过累计人数解锁更强的计谋、健康和恐怖值奖励。

其核心玩法目标清晰，奖励反馈也覆盖属性、特质、宝物、成长条和收藏界面多个层面。但实现方式依赖大型原版文件覆写，批量路径与单独路径已经分叉，并带有当前版本不匹配的 GUI 和 trait 残留。

因此，可以把它概括为：**功能丰富、数值极强、收藏反馈明确，但兼容性较差且需要一次针对 CK3 1.19.0.6 的实机加载与脚本错误日志验收。**
