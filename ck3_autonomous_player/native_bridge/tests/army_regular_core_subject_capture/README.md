# Regular-core explicit subject capture fixture

This narrow fixture calls the actual production candidate capture, scoped enable
setter, owned journal and serializer over owned mock memory. It also links the
actual natural phase TLS/clock and natural JSON implementation. It never starts
or connects to CK3 and never reads a game executable.

The six political predicate definitions in `position_stubs.cpp` are abort-only
fixture link boundaries. Mock chunks resolve to an invalid ArRg, so none of these
predicates may execute. Capture, full-generation resolution, sampling policy,
natural clock/TLS and serialization are not stubbed. Do not use these definitions
in a production DLL.

Compile and link exactly these six translation units with the project's MSVC
environment (C++20, `/EHsc /W4 /WX /O2 /MD /Gy /utf-8`, `NOMINMAX` and
`WIN32_LEAN_AND_MEAN`, native `include/` on the include path):

1. `src/army_regular_core_passive_12004.cpp`
2. `src/army_natural_phase_scope_12004.cpp`
3. `src/army_natural_phase_json_12004.cpp`
4. `src/person_natural_lineage_clock_12004.cpp`
5. `tests/army_regular_core_subject_capture/scoped_capture_focus.cpp`
6. `tests/army_regular_core_subject_capture/position_stubs.cpp`

Link their objects with `/INCREMENTAL:NO /OPT:REF /OPT:ICF`, `kernel32.lib` and
`user32.lib`. Pass one writable output filename to the fixture executable. It
writes the actual serialized Core-family JSON there. Project-built executable
registration must use the existing standard build producer and verified exact
SYSTEM receipt before execution on this machine; do not infer a new output path
is registered from an older fixture path.

The external qualification runner records the exact compiler/link argv, all
frozen header/source hashes, stdio and the broker result. On
`desktop-3fevhd2-1c74096080`, 2026-10-15, actual run `build-a02` passed **36 native
checks**. Its immutable result SHA-256 is
`44e1e6f160de7a7ecea4dbd810da1f84119bf46e1418700dba745d244d92421b`.
This is mock-memory qualification; it is not a live refill, applied inline ADD,
q/cause decomposition, complete monthly result or full-manager readiness claim.

Cases include 4097 unique global receivers versus a small subject closure, every
original manager row and duplicate ordinal, whole seven-slot cross-owner
receivers, ArRg/DATA aliases, shared cap reservation, changed owner/GameState/
generation/backreference, unknown nonselected occurrence, absent subject,
invalid DATA, unreadable slots, read budget, strict fallback refusal with raw
bytes retained, enable refusal, natural original-once, opaque return, actual
sampling epoch, owned readback and disable/clear.

The default collector retains its old global semantics. Explicit subject frames
always have global `capture_complete=false`; independent `subject_coverage_v1`
only describes raw physical closure. The old global ordered mapper remains
strict. Compare entry and returned physical tokens and full generations before
reporting raw net changes. Do not multiply a physical delta by DATA aliases or
manager occurrences.
