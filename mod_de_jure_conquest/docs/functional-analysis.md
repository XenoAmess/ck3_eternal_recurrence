# 功能分析

日期：2026-10-03。阶段：**公开页面与冻结源码已审阅，尚未执行实机。**

## 玩家功能

[上游页面](https://steamcommunity.com/sharedfiles/filedetails/?id=3600021457) 描述三种玩家专属宣战借口。冻结源码实际基础费用如下；页面资源列顺序与源码相反，维护版保留实际源码经济规则。

| 区域 | 上游解锁等级 | 威望 | 虔诚 |
| --- | --- | ---: | ---: |
| 公国 | 闻名遐迩（等级 2） | 100 | 200 |
| 王国 | 赫赫有名（等级 3） | 500 | 1000 |
| 帝国 | 高贵之人（等级 4） | 2500 | 5000 |

威望仍乘 `common_cb_prestige_cost_multiplier`，虔诚仍加 `common_cb_impious_piety_cost`；最终 UI 费用会随原版修正变化。

宣战会扩大防守方集合；胜利应转移目标法理内的伯爵领。对区域内弱小领主宣战仍可能把强大领主加入防守方，玩家须在确认前理解实际参与方。AI 没有此类进攻入口。

## 需核实的边界

源码适配见 [implementation.md](implementation.md)。以下问题仍需实机互证，不能把静态修改认定为已验证玩法：

1. 是对独立领主、顶级领主还是所有法理内持地人物收集参战者；原攻击者自己的附庸、朝贡关系、共同主君和停战如何处理。
2. 多防守方是通过原生战争参与方 API 加入同一战争，还是用大圣战标记与脚本补充；主防守方弱小时，战分能否过早达到胜利。
3. 结算只接管伯爵领还是也改动王国／公国；法理外土地、男爵与租赁、原附庸和异教领主的处理。
4. 白和平、战败、死亡继承、目标转移和战争无效化是否仍有可达且一致的终结路径。
5. 旧 CB key、事件 ID、flag 和存档变量是否需保留；同时加载上游与维护版时的重复键冲突。

## 页面反馈与待复现问题

2026-10-03 匿名页面可读到新版 DLC 后功能失效、自动军队停留于集结，以及其他并发战争在法理征服胜利后无法结束的用户反馈。[来源：上游评论](https://steamcommunity.com/sharedfiles/filedetails/?id=3600021457)。这些是测试输入，**不是已复现缺陷或引擎根因**。

并发战争案例必须优先形成最小夹具：防守方在目标帝国外仍有土地，同时对法理内伯爵领进行另一场征服。完成本 CB 后观察另一场战争的主参与方、CB、目标、胜利／白和／投降资格；不能只确认本场战争结束。

## 当前版本合同依据

已读取本机 CK3 `1.20.0.3` 的 `common/casus_belli_types/_casus_belli.info`：普通 effect／trigger 默认处于 CB scope；`allowed_for_character` 的 ROOT 是攻击者；`target_titles` 可选 `de_jure`／`all`，`target_de_jure_regions_above` 与 `use_de_jure_wargoal_only` 为不同合同；`is_holy_war`、`is_great_holy_war`、`defender_faith_can_join` 是不同开关。页面称其基于圣战，不能据此把这些开关当成等价项。

仓库 [grammar/pitfalls.md](../../docs/grammar/pitfalls.md) 已记录 1.20 CB 描述在战前预求值时 `root.war` 可能未设置。取得源码后先核对，必要时只在外层存在性分支内读取战争，避免在战前描述里执行不存在的战争结算。

## 系统富化判断

可复用成果是 CB 默认作用域、战前描述求值、目标集合和并发战争结算合同；已复用既有 parser 与公共 `tools/independent_mod_release.py`，没有复制产品 builder。产品文案、机制、源码及具体证据留在本目录；目前没有足以新增通用结论的实机事实。
