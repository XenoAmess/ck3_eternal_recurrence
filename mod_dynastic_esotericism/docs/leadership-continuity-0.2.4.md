# 0.2.4 双职位连续跟随候选

用户要求产品新建的宗族化绑定中，宗家家主和宗族族长都跟随实际 `head_of_rite`。这是对0.2.3只证明宗家家主的后继修复，不倒改原版本的有限通过或失败。

保留实际互惠绑定、稳定原宗家、`new_dynasty`来源、活着且确属该Rite／Faith的实际领袖守卫。复用的原生宗族及无法证明来源的旧绑定不被冒认为新建；原生建族／编辑pending、外礼仪共享教宗、旧backlink、死者与不完整scope均保守处理。

先按原产品规则加入实际同礼仪领袖，再使用真实 `set_house_head`。不存在已证明的直接 `set_dynast`脚本接口，也不能重复给同一House head赋相同值假称刷新成功。只有实际家主和实际Dynast均等于当前礼仪领袖才清pending。若真实Dynast错位并且存在在世支系成员，才对该单一绑定Dynasty做原有all-living快照归并，包含玩家与跨Rite成员；不全世界扫描、不扩大到其它宗族、不改死者历史谱系。

已初始化世界有独立0.2.4一次加载兼容门，不重跑世界初始化。领袖相关头衔、死亡与旧Rite离开等生命周期只安排一次有界重读，回调不自续；年度兜底保持，已对齐局部路径不枚举1216人或其它人口。普通头衔／继承副作用须由实际存档另验，软件模型不授引擎资格。

当前真实软件为a02的19项与a04必要7项分别通过（含一次必要重复覆盖），不是宣称最终24项wholeclass重跑。AUB六叶语法及未改AST守恒通过。工具Java源与71库存不变，产品版本从descriptor动态读取；复用已限定CodeSource的工具做一次候选build／verify，不重Maven，也不创建正式tag。
