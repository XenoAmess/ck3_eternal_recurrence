# 宗族化密教：需求文档

版本：1；制定日期：2026-10-24；目标产品版本：0.1.0，首次发布基线。用户已授权依次完成需求、测试方案、编码、验收和发布；本文件先于功能代码落盘。技术依据见[可行性分析](feasibility-2026-10-24.md)。

## 产品与适用对象

产品目录 `mod_dynastic_esotericism/`，英文名 Dynastic Esotericism，产品 key `dynastic-esotericism`，脚本前缀 `des_`。游戏对象严格区分 Rite（礼仪）、Faith（信仰）、Dynasty（宗族）、House（家族）。玩家、AI、有地／无地、成年人／儿童都适用，这是用户“任何信了这个礼仪的人”的明确范围。

第一版针对实际验收的 CK3 1.20 架构，正式 descriptor 的兼容版本按项目单一 registry 渲染。实际版本、机器身份和 EXE 由每次验收回执记录，不把版本标签当作其他 build 已实测的证明。

## 功能合同

| ID | 要求 |
| --- | --- |
| REQ-01 | 原版礼仪面板显示“宗族化”组与已提交选项；创建、改革和编辑礼仪的原生草案可以选择“宗族化”或“无”。未配置礼仪首次初始化为“无”；从已配置礼仪派生的草案沿用原版教义继承，仍可手选两项。不要求先知技能，不额外占用核心信条槽。 |
| REQ-02 | 选择只修改原生草案。玩家取消、关闭窗口或原生最终校验失败时，不创建宗族、不迁移人物；沿用原版提交、费用与可编辑资格。两个选项自身不额外添加费用或分歧值。 |
| REQ-03 | 首次实际启用时，该 Rite 创建一个新的真实 Dynasty 和初始 House；Rite 与 Dynasty 双向绑定实际对象。同名不同 Rite 不共用宗族。重复初始化、编辑或读档不重复建族。 |
| REQ-04 | 创建者和该 Rite 的全部存活信徒加入绑定 Dynasty；新加入者进入其默认 House，已处于该 Dynasty 的合法旁支保留 House。未改信的旧后代不因创建者建族而被顺带迁移。 |
| REQ-05 | 普通改 Rite／Faith 路径在同次同步中处理；出生、生成在原版人物与 House 初始化完成后同步，最迟下一游戏日。对其他脚本直接改 House 等没有通用原生钩子的路径提供明确周期校正，具体时限写入实现与实测记录。 |
| REQ-06 | 属于绑定 Dynasty 而当前 Rite 不等于绑定 Rite 的存活角色属于“背离宗族礼仪”。同一 Faith 的其他 Rite 和其他 Faith 均算背离。保留背离者 Dynasty，不自动改信或逐出。 |
| REQ-07 | 绑定 Rite 的其他信徒对背离者增加一项固定 `-100` 好感修正。该来源不叠加、不自然衰减；总好感仍叠加原版其他来源。其他 Rite、其他 Dynasty 不获得这一修正。 |
| REQ-08 | REQ-07 同一方向的观察者／目标关系具有实际监禁、放逐、处决理由，采用原版对应旗标。界面描述必须能说明来源。不给全世界通用罪行，不额外授予剥夺头衔或离婚理由。 |
| REQ-09 | 普通监禁管辖、交互资格、目标需先被囚禁才可处决等原版规则继续生效。模组提供犯罪理由，不自动逮捕、处决、改金币或代替玩家作惩罚决定。 |
| REQ-10 | 背离者重新采用绑定 Rite、实际离开该 Dynasty 或该 Rite 关闭宗族化时，仅撤销本产品的背离状态与关系来源。其他罪行和意见保留，已经发生的囚禁、处决和血缘记录不回滚。 |
| REQ-11 | 持续背离时，修正程序不反复移除／重加同一状态，不重置原版已赦免、已消耗的犯罪理由。悔改后再次背离是新的背离阶段；其实际犯罪消费行为须验收，不承诺无限重复处罚。 |
| REQ-12 | 从“宗族化”改回“无”时停止入族与背离惩罚，保留已创建的 Dynasty、House 与人物当前身份。再次开启同一 Rite 时复用原绑定；原绑定损坏时保存诊断并修复，不能静默关联其他礼仪。 |
| REQ-13 | 角色采用另一个宗族化 Rite 时进入新绑定 Dynasty，原宗族的背离处罚不再适用。两个宗族化 Rite 之间不得因共用布尔教义参数而互相授予错误好感或罪行理由。 |
| REQ-14 | 创建者死亡、族长更替、原生旁支、存档保存／冷重载、Rite 的 Faith 归属变化后，绑定继续基于实际 Rite，不按名字、创建者存活与否或 Faith ID 另建一族。死亡角色的历史宗族不追溯改写。 |
| REQ-15 | 玩家文案明确：入教会取代人物原来的宗族／家族归属，可能影响姓氏、继承、族长和宗族声望。“背离”显示为本产品的宗教罪行，不能为了展示普通 sin 图标而给不相关礼仪额外施加原版罪恶惩罚。 |
| REQ-16 | 新局自动初始化缺省教义，并为符合原版 `is_playable_character` 资格的存活角色初始化两个选项的知识；旧档若没有原生加载初始化钩子，提供仅尚未初始化时显示的正常“启用宗族化密教”决议，点击后完成同一初始化。知识资格不限制 REQ-04–14 的全员宗族及罪行规则。初始化不自动宗族化原版已有礼仪。正式包排除验收事件、诊断决议、测试角色和调试捷径；该旧档兼容入口属于正式功能。 |

宗族及家族初名沿用原版动态创建机制，保留原版重命名能力；对应关系由持久对象引用与界面文案表达，不依赖名称唯一性。第一版不额外设计秘密组织、入教收费、主动传教、自动惩罚或特殊婚姻／继承规则。

## 编码与发布合同

CK3 游戏脚本和 GUI 使用游戏原生格式，UTF-8 BOM；先完成简体中文与英文。其他语言的正式翻译按仓库翻译流程，在正式发布阶段办理。新增构建、校验和宿主模块使用 Java + Maven + Quarkus；默认 `mvn` 必须符合仓库最低版本，不新增 Python 产品业务模块或私有验收 runner。

正式上传只使用显式 allowlist 生成的 staging，附逐文件 SHA-256 manifest。内部 descriptor 不含 `remote_file_id`，首次真实发布前不填写 Workshop ID。实机经公共验收入口选择统一 runtime 和本机映射；现有工具不足时修复共享入口，明确来源与资格边界。

完整发布须同时完成：源码／正式 staging 业务验收、正式构建与版本提交、真实 Workshop 首发、公开描述和完整 Change Notes 精确回读、兼容标签回读、Steam 实际下载缓存与正式构建一致、CK3 实际加载该缓存、永久 initial-baseline changelog 提交推送。缓存阶段只核文件和加载，不重复业务验收。必要联网完成后恢复 Steam 离线。
