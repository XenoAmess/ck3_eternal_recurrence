# 宗族化密教：需求文档

版本：2；初定日期：2026-10-24；2026-10-25 根据用户追加要求修订；下一产品版本：0.2.0 候选。0.1.0 已首发，完整业务验收仍未完成。用户已授权依次完成需求、测试方案、编码、验收和发布；本次增量同样先修订需求与测试，再编码。技术依据见[可行性分析](feasibility-2026-10-24.md)。

## 产品与适用对象

产品目录 `mod_dynastic_esotericism/`，英文名 Dynastic Esotericism，产品 key `dynastic-esotericism`，脚本前缀 `des_`。游戏对象严格区分 Rite（礼仪）、Faith（信仰）、Dynasty（宗族）、House（家族）。玩家、AI、有地／无地、成年人／儿童都适用，这是用户“任何信了这个礼仪的人”的明确范围。

第一版针对实际验收的 CK3 1.20 架构，正式 descriptor 的兼容版本按项目单一 registry 渲染。实际版本、机器身份和 EXE 由每次验收回执记录，不把版本标签当作其他 build 已实测的证明。

2026-10-26 用户追加合同（优先于上表 REQ-03、05、06、17、18 的一般路径）：真实原生创建／改革者在产品迁族前已为 Dynast 时，不新建 Dynasty、House 或 NPC，直接复用其原 Dynasty 与实际 House，按新 Rite 改名、保留两者原纹章及其他合法旁支。必须在任何产品迁族前固定真实操作者及原 Dynast／Dynasty／House 来源；普通改信或首次采用预置 Rite 不能据此接管原宗族。启动时已宗族化并登记的 Rite 的普通采用保留即时同步；新出现或首次从无启用且来源未明的 Rite 先固定首次真实采用者、排一次次日初始化，不能在原生创建／改革回调前抢先建族或迁族。

若复用的原 Dynasty 已绑定另一 Rite，绑定转给新 Rite；旧 Rite 的宗族化教义实际改为 `des_doctrine_none`，解除旧双向引用与本产品背离关系／犯罪来源。保留原 Dynasty、House、纹章、实际成员和历史 Faith／Rite，旧 Rite 不由维护自动重建或抢回。复用旧宗族时，只有曾实际采用新绑定 Rite 的成员后来离开才构成该 Rite 的背离；从未入教的原成员不因同宗族而成为背离者。后续自然继承不由维护重抢。

2026-10-25 的追加要求覆盖旧版“宗族及家族初名沿用原版动态创建机制”。保留原版后续重命名能力；对应关系仍由持久对象引用表达，不依赖名称唯一性。第一版不额外设计秘密组织、入教收费、主动传教、自动惩罚或特殊婚姻／继承规则。

2026-10-25 后续澄清：用户允许“任意自创礼仪的图标复制，如果确定无法使用原宗教的图标，允许实现为按照游戏机制随机新的宗族图标”。该回退不改变两项预置礼仪精确使用上传图标的要求，也不允许每次同步／重开随机重置已有纹章。

2026-10-25 用户明确的原版建族边界处理：优先让原请求者把家族族长交给另一真实存活同House成员，确认原人物不再担任House head及Dynast后自行建族。原请求者仍不合法时，再选择其他合法真实信徒；仍无合法创始者时，按用户选择生成一名真实同礼仪成年人，再走同一真实建族和绑定路径。该人物留在世界中，重复初始化不反复生成；不追改旧后代、不切换玩家、不收额外费用。原版家族专属头衔如随族长交接，文案须披露。实际覆盖仍以[交接研究与验收](2026-10-25-house-head-handover.md)为准，不以授权或静态结果代替实机。

## 编码与发布合同

CK3 游戏脚本和 GUI 使用游戏原生格式，UTF-8 BOM；先完成简体中文与英文。其他语言的正式翻译按仓库翻译流程，在正式发布阶段办理。新增构建、校验和宿主模块使用 Java + Maven + Quarkus；默认 `mvn` 必须符合仓库最低版本，不新增 Python 产品业务模块或私有验收 runner。

正式上传只使用显式 allowlist 生成的 staging，附逐文件 SHA-256 manifest。内部 descriptor 不含 `remote_file_id`，首次真实发布前不填写 Workshop ID。实机经公共验收入口选择统一 runtime 和本机映射；现有工具不足时修复共享入口，明确来源与资格边界。

完整发布须同时完成：源码／正式 staging 业务验收、正式构建与版本提交、真实 Workshop 首发、公开描述和完整 Change Notes 精确回读、兼容标签回读、Steam 实际下载缓存与正式构建一致、CK3 实际加载该缓存、永久 initial-baseline changelog 提交推送。缓存阶段只核文件和加载，不重复业务验收。必要联网完成后恢复 Steam 离线。
