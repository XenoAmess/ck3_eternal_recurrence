# I3b checkpoint observation adapter

This external export adds a standalone read-only checkpoint adapter and typed input/output contracts for frozen source `632f0a57a07aa6299052004589ed6f7632e7d8f7`. It has never opened an actual checkpoint body. It calls no game, MCP, provider, registry or Git API, and changes no mod source. ROOT may integrate the reviewed new files only after the current game/client/lease is closed.

`reader/i3b_checkpoint_reader.py` is the single future entry. `CHECKPOINT-REQUEST.template.json` supplies the precise 0240 protection baseline, with every future live identity, serial/nonce/phase, PID, revision and save descriptor left `null`. The reader rejects this pending request before opening a body. ROOT must create a new filled request and fresh output directory after obtaining actual live/checkpoint evidence. The adapter has no decoder or compressed-save fallback.

The historical expected branch is actor **31254**, Faith **107**, main Rite **169**, actual native HoR **31254**. Old Faith **106** / main Rite **187** and the receiving Faith/Rite are protected through their complete saved ASTs. These are historical expectations, not new live observations. The old cancel82 Faith106/main169 identity cannot be substituted.

For G2 the adapter scans every numeric living record with the exact validated save framing, and classifies each through the complete Rite→Faith registry. Unmapped living records prevent a complete classification result. It retains every current Faith member, compares exact captured typed members/rites, and reads owner, serial, nonce, phase, vote, was_elector, was_player and separate `player_yes` stamps. Each active Rite gets an independent positive-elector-count check, full-roster counter reconstruction, actual representative check and integer `3*yes >= 2*total` quorum. All alive captured humans need their separate 412 consent for a signed-precommit result. A dormant Rite requires zero counties and zero members, no representative or signature.

Saved `currently_played_characters` is retained as a separate observation. It is not proof of native `is_ai`. Mod `was_elector` / `was_player` stamps likewise cannot independently prove current eligibility. `NATIVE-PREDICATES.template.json` requires a fresh complete native witness bound to the exact checkpoint/session/revision: alive/adult/imprisoned/incapable/effective learning/is_ai for the whole Faith roster and native county counts for every Rite. The adapter validates the closed payload and its internal binding, but does **not authenticate** a caller's native receipt. Actual-mode output explicitly labels this input `CALLER_SUPPLIED_NOT_NATIVE_AUTHENTICATED`; a hash-shaped string supplies no native proof. Existing saved numeric skill and trait IDs provide no implicit mapping.

For G3 the only discovery source for future T is the actor's actual saved `lyd_i3b_result_head_title` typed row. The adapter crosschecks T against the actual Faith `religious_head_title`, reads the full actual Title AST/holder/LYD owned marker/typed ownerFaith, and checks Faith religious head, recognized leader, office Faith and all captured Rite temporal doctrine projections. It preserves every tenet/status row and checks that success changes only `doctrine_no_head` to `doctrine_temporal_head`. All seven political titles retain their complete ASTs and holders. A partial result preserves a Faith-referenced factory title separately, without a fabricated success receipt or handoff.

The saved native Title type discriminator and the serialization of its succession law/four properties have **not been established** by 0240 evidence. `TITLE-REFERENCE-BINDING.template.json` and `TITLE-FIELDS-BINDING.template.json` deliberately leave their mapping `null`. An actual binding requires a reviewed native typed reference/Title record/getter observation. The adapter accepts only explicit unique field paths and supported declared shapes; missing fields and unknown tokens fail closed. The `synthetic_*` fields and `synthetic_native_title_reference` in tiny tests are fixture vocabulary, never actual CK3 mappings. Factory setter execution is not readback.

`formal_mandate_credit`, `actual_pass`, and `actual_native_runtime_pass` always remain `null`. A saved-state consistency result cannot establish that formal 410/411/412/413/430 callbacks ran with the current actor/serial/nonce/phase. Keep independent receipts described by `FORMAL-EVENT-CONTEXT.template.json` and retain the full signed-precommit checkpoint before cleanup. The existing primitive-charter fixture bypasses formal ballots and grants no mandate credit.

Only the new tiny fixtures are tested in this export. They cover two active schools plus a dormant school, all human412 stamps, cross-school counter/quorum errors, zero scholars, stale nonce/owner/witness, uncaptured/unclassified members, missing qualification, dynamic title discovery, wrong Title holder/owner/law/property, unknown real mapping, full political/tenet protection and preserved partial factory state. No old source/static/build suite is rerun.

Shared C3 handoff rows are defined in `OUTPUT.schema.json`: `native_title` includes `title_id`, `holder`, full `entries`, `AST_sha256`, typed `variables`/`lists`, and `qualification`; `protected_titles` is a complete array of the seven corresponding rows plus baseline hashes/holders. `null` native-title qualification remains a gap, not an empty positive proof. C3 can consume this exact row and preserve the same AST/identity binding without selecting a fictional title ID.

`NATIVE-ADDON-CONTRACT.json` isolates the minimal additional read-only native observations required for real G2/G3 credit. It is a proposed source contract, not an available tool or implemented patch. The copied phase-character source explicitly gates its bindings to the 1.20.0.2 executable hash; its human/effective-learning/incapable primitives cannot be extrapolated to the current executable. The existing 1.20.0.3 Title-holder interface supplies a holder read only, without succession-law/four-property getters. No native addresses, provider code or formal 21-tool registry are changed here.
