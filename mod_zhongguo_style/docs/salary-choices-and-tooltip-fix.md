# 薪酬案卷：选择含义与界面修复

2026-10-25 修复。这里的薪酬是本模组另加的年度发放，不替代原版薪俸。案卷把冻结考绩转为一笔实际欠款，再让管理者选择付款时间和是否承认补发。付款会从案主国库、案主个人金币转入受款封臣个人金币；绩效档不会因此改变。

| AE2 选择 | 当下收益与支出 | 后续负担 | 当前实际代价 |
|---|---|---|---|
| 立即付清并补发 | 立即支付原欠款加 4，结清这笔欠款 | 无这笔延期债 | 两库立即支出；没有额外好感或忠诚奖励 |
| 延期支付并承认补发 | 今日支付 0，暂留资金周转 | 90 日后尝试支付原欠款加 4 | 兑现信用记录 -15；尚未接入好感、忠诚或留任效果 |
| 延期支付并驳回补发 | 今日支付 0；相比上一项多周转 90 日，并少付补发 4 | 180 日后尝试支付原欠款 | 同样兑现信用记录 -15；尚未接入好感、忠诚或留任效果 |

国库通常承担约 70%，个人约 30%，整数按实际冻结口径取整。立即补发 4 拆成国库 3、个人 1；延期承认补发时先合并总债，再拆分。各选项 hover 从实际应付账计算两库金额，不能用固定示例充当报价。

到期付款要求两库及其预算同时足额。任一不足，两边都不扣款，欠款保留；当前到期处理会结束，不会自动反复尝试。延期不产生利息，也没有直接的好感、忠诚或叛乱惩罚。因而当前设计主要提供现金周转，约束偏弱：180 日方案与 90 日方案的信用代价相同，却更晚付款且少付 4。这是现有平衡边界，本次没有擅自增加新的惩罚体系。

三个选项的 hover 明确列出：实际欠款、补发、两库支出、到期天数、资金不足结果、信用变化，以及当前没有直接好感/忠诚效果。复杂案卷 effect 放入 `hidden_effect`，由独立 `custom_tooltip` 负责解释，避免说明求值遍历整个内部状态机。原先已有 tooltip key，不能把缺失 hover 简单归因为“没有写本地化”。原版 `game/events/accolade_events.txt` 同样支持选项级 `custom_tooltip`；`game/gui/shared/event_windows.gui` 只在 `EventOption.GetTooltip` 非空时显示。

同时修正生产链上的三个问题：最后一个 AE1 消费者先标记完成、再初始化账单，防止 AE2 时账单尚未就绪；立即付款先整体预检原欠款和补发，防止半笔付款；延期结算只冲销冻结债，不清空后来 AE3 新增的债。期限事件以受款人为 root 时，刷新正确写回管理者阶段。

“提前启动本年度考核”的共享业务条件改用四条可读说明，覆盖正在考核、当年考核、前轮案卷和合格官员。实际条件、150 威望费用及冷却未改变；不再让 `zg361_b1_cycle_active` 等内部 flag 和嵌套占位条件成为玩家说明。

回归执行真实生成脚本的有限子集，覆盖 AE1→AE2、完整付款、资金不足、90/180 日期限、AE3 后增债与重复提交。它不等同于 CK3 引擎执行或实际 hover；实机结果须单独记录。
