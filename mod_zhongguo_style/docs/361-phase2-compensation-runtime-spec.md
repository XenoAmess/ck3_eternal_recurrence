## 一、范围与对象

本内核精确覆盖三组共 33 个 phase=2 机制：

- L `082–091`：`compensation_award`，公式锁定 → 资金预留 → 授予 →
  递延/暂扣 → 支付/追索；
- AE `278–289`：`pay_statement`，应付生成 → 到期 → 支付/延期 →
  补发/纠错 → 薪酬申诉；
- AF `290–300`：`lti_grant`，提名 → 授予 → Cliff → 归属 →
  离任分类 → 回购。

模型刻意不把三者合并成一个“金币加减器”。奖金、工资应付与长期份额分别有自己的状态与守恒式，
但所有真实金币流动共用同一份 receipt journal。

33 个编号另有统一的 `CompensationRouteLedger`：99 条 A/B/C 路线逐条冻结
`owner + subject + cycle + case + expected_state`、数值资源载荷和可见结果；明确拒绝的 C 路线只记录
`no-object`，不伪造业务对象。相同 operation key 重放、旧 serial、换路重放分别走 idempotent、stale 和
typed RED。该路线账不是字符串 registry：现金路线会真实调用双付款 journal，欠付/延期路线冻结两边份额并可
随后结算，非现金路线也必须写入至少一个可执行数值资源。

## 二、金币合同：国库与负责人个人金币双扣

每笔真实制度成本使用显式 `FundingSplit`。默认地方/组织国库承担 70%，负责该案的领主个人金币承担
30%；两边比例可配置，但必须合计 100%，且任何一边都不能配置为零。金额按整数最小单位结算，极小到
无法让双方至少各付 1 的付款会 typed RED，而不是暗中退化成单边付款。

事务顺序固定为：

1. 根据冻结比例计算两边应扣额；
2. 同时预检国库和个人金币余额；
3. 两边都足够才原子写入余额与 receipt；
4. 任一边不足则 `INSUFFICIENT_FUNDS_RED`，两边余额和 receipt 表均不改变。

支持五类 receipt：`reserve`、`settlement`、`payment`、`refund`、`return`。
奖金先 reserve 后 settlement；工资、专项奖和长期份额回购可直接 payment。未使用预留只能退回原始
reserve 的剩余额，已支付追索只能退回原 payment/settlement 尚未追索的额度，任何超额均为
`RECEIPT_LIMIT_RED`。退款/追索按原 receipt 的国库与个人出资份额原路返回，不能借冲正制造金币。

## 三、三条守恒式

### 奖金

公式锁定后才允许预留，预留后才允许授予。授予额拆成即时应付、递延应付和审计暂扣；支付、没收、
退款和追索后必须满足：

```text
授予总额 = 即时未付 + 递延未付 + 暂扣 + 实付净额 + 没收
实付净额 = 历史实付 − 已追索
```

### 薪酬单

工资、津贴、绩效奖、专项奖、已归属长期奖等组成可见应付项。补发增加应付与欠付；退回一笔历史实付
会重新打开等额欠付，直到纠错正式改变合同额。始终满足：

```text
payable = paid + owed − returned
```

薪酬申诉只改钱账和规则执行，不能改冻结绩效档位；绩效申诉保留为另一条案轨。

### 长期份额

长期份额不是授予时立即产生的金币。授予批次始终满足：

```text
授予份额 = 未归属服务份额 + 未归属绩效份额 + 已归属 + 没收 + 已回购
```

实际回购时才从国库和负责人个人金币双扣，并向持有人支付金币。回购队列固定 FIFO，禁止暗箱插队。

路线账中的欠付和延期付款也遵守同一原则：创建债务时不冒充现金已动；真正调用 settlement consumer 时才同时
预检、扣减国库与负责人个人金币并给受款人入账。任一付款方不足时，债务、钱包和 journal 保持原样。

## 五、期限、幂等与 typed RED

所有状态写操作要求 `case_serial` 与活动案一致，并带稳定 `operation_key`：

- 相同 key、相同输入重放为 `idempotent-noop`，不二次扣钱、不二次归属；
- 新 key 携带旧 serial 为 `stale-noop`，不改状态；
- 同 key 改输入为 `IDEMPOTENCY_CONFLICT_RED`；
- 未开放的未来 serial 为 `FUTURE_SERIAL_RED`；
- 余额不足、状态次序错误、收据超限、申诉串轨、回购插队和守恒漂移均有独立 typed RED。
