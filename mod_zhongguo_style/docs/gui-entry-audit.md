# 361 GUI 入口与按钮布局审计

日期：2026-08-29（Asia/Shanghai）

目标版本：CK3 1.19.0.6

状态：考核榜位置、页签、关闭控件与代表性人物行均有实机证据；人物侧栏清理修复后等待整批 GREEN

## 1. “考核榜”为什么会出现在奇怪的位置

旧投影把 `180×44` 的常驻按钮直接挂在全屏顶层窗口上：

```text
parentanchor = top|right
position = { -205 165 }
```

这个坐标既不属于原版顶部资源栏，也没有贴住右侧 `50` GUI 单位宽的主功能栏；它会悬在地图右上方。更重要的是，旧按钮的可见性只检查有没有榜单数据，不检查原版右侧窗口是否打开。

已有 2560×1440 实机证据确认了两个问题：

- `cell/04_gameplay_hud.png`：按钮脱离原版 HUD 控件组，独自悬在右上地图区。
- `cell/07_scoreboard_button.png`：原版“决议和大型工程”抽屉打开时，按钮仍盖在抽屉的标题/内容区域上，视觉上像是决议列表的一部分，也会争抢该区域鼠标输入。

证据根目录为：

```text
Z:\ck3_mod_rewrite_process_assets\zg361\runs\zga_20260829_061314_ea5f04ad
```

原版 CK3 1.19.0.6 的相关 HUD 契约是：

- outliner 按钮：`parentanchor = top|right`、`position = { -5 55 }`；
- 主功能栏：`parentanchor = top|right`、`position = { 0 90 }`、宽 `50`；
- 相邻原版控件会在 `IsRightWindowOpen`、暂停菜单、非默认 GUI 模式等状态下隐藏。

## 2. 最小布局修复

权威修改点是 `tools/gen_scoreboard_snapshot.py`，不能手改生成的 `gui/zg361_scoreboard.gui`。

新按钮保持完整的 `180×44` 多语言文本空间，但改为：

```text
parentanchor = top|right
position = { -60 90 }
```

它的右边缘离屏幕右侧 `60` GUI 单位，正好留出原版 `50` 单位主功能栏和 `10` 单位间隙；顶部与原版主功能栏的 `y = 90` 对齐。参考布局矩形为：

| 分辨率/投影 | 按钮矩形（left, right, top, bottom） | 结论 |
|---|---:|---|
| 1920×1080 GUI 参考空间 | `(1680, 1860, 90, 134)` | 完整可见，右侧留 60，顶部资源栏下方 |
| 本机 2560×1440，1.30 HUD 缩放 | `(2248, 2482, 117, 174)` | 完整可见；右侧留 78 px，扣除约 65 px 原生栏后仍有约 13 px 间隔 |

按钮容器现在同时要求：

- `Not(IsPauseMenuShown)`；
- `IsDefaultGUIMode`；
- `Not(IsRightWindowOpen)`；
- `Not(IsGameViewOpen('outliner'))`；
- `Not(IsGameViewOpen('barbershop'))`。

`outliner` 必须单独排除，因为它本身不是一个可用 `IsRightWindowOpen` 判定的普通右侧窗口。没有直接把按钮注入 `hud.gui`：那会整体覆盖原版大文件，制造版本升级和其他 UI mod 的高冲突面；相邻锚定加原生显示门是当前最小可靠方案。

| 标题栏关闭按钮 | 1 | 1220×820 居中面板标题栏 | 清除打开变量并支持原生 `close_window`（Escape）；重复清除是幂等操作 |
| 页签按钮 | 3 | 面板内部横向栏 | “所辖官员”“本人所属考核单元”“制度驾驶舱”；各自带 availability、`onclick` 和 `down` 状态，不会出现可点空页 |

按展开后的显式节点计，产品 GUI 有 `166` 个直接按钮节点（2 个互斥入口、1 个背景、3 个页签、160 个行链接）；标题栏通过 `header_pattern` 的 inherited `button_close` override 再提供 1 个可交互定义，因此严格按不同定义计为 `167`。两个 bridge 都没有按钮。

四项基础决议、361 张政策卡、京察活动入口、互动按钮和事件选项都由 CK3 原生决议/活动/互动/事件窗口渲染；本 mod 没有给它们额外叠放坐标，因此不属于这次 additive GUI 位置故障。

## 4. 面板尺寸、层级与点击审计

- 面板 `1220×820` 在 1920×1080 参考空间中的边界为 `x=350..1570`、`y=130..950`；按本机 2560×1440、1.30 HUD 缩放投影后仍完整落在安全区内。
- 顶层窗口保持 `alwaystransparent = yes`，关闭状态下只有真实可见按钮接收输入。
- 模态层打开时改为 `alwaystransparent = no`、`filter_mouse = all`，这是有意的全屏模态语义；居中面板本身也截获输入，面板内点击不会误触背景关闭按钮。
- managed/received 两个常驻按钮变体的显示条件互斥，不会堆出两个可点击热区。
- 三个页签只改变 `zg361_scoreboard_tab`，面板仍由同一模态层持有；不存在切页后按钮落到屏幕外的坐标变化。
- 160 个行链接由生成器统一产出，尺寸、点击链与 frozen-snapshot 数据上下文完全同构；静态测试逐槽确认 80+80 个入口。

## 5. 回归与下一轮实机验收

新增静态回归锁定：

- 新锚点、按钮安全矩形和 1080p/1440p 投影；
- 五项原版 HUD 显示门；
- 生成投影不可手工漂移；
- Escape 关闭、三个页签和 80+80 行入口原有合同继续成立。

全自动实机 runner 也已改为在同一次 CK3 启动里：

1. 明确打开原版“决议”右侧抽屉；
2. OCR 断言“考核榜”按钮此时不存在，并保存 `07_scoreboard_hidden_by_right_panel.png`；
3. 先把鼠标移出决议行 tooltip 再尝试 Escape，并连续两帧确认原生标题消失；若 CK3 只收掉 tooltip 而抽屉仍在，则点击原生标题栏 X，再连续两帧确认关闭。关闭方式写入报告，未确认关闭时绝不把“按钮继续隐藏”误报成位置故障；
4. OCR 只在归一化矩形 `x=0.86..0.985、y=0.05..0.16` 内等待按钮重新出现并点击，同时把像素中心、归一化中心和允许矩形写入报告；旧 `{-205, 165}` 漂浮位置不再可能误过；
5. 继续验证榜单标题、所辖页、制度驾驶舱切页和返回；
6. 不借用 Escape，直接点击榜单自身标题栏 X；连续两帧确认完整标题消失且安全区入口重现，再重新打开并确认所辖页恢复；
7. 点击远离居中面板的模态背景；用同一“标题消失 + 安全区入口重现”双条件确认关闭，再重新打开并确认所辖页恢复；
8. 从当前可见行中按榜单姓名列几何、姓名分隔符和人物名选出一条真实角色行，点击后同时确认榜单标题消失、同一人物名出现在 CK3 原生人物窗；清理人物窗后再确认安全区入口并重开所辖页，避免把后续京察验收留在错误 GUI 状态。报告固定写明生成行入口总数 `160`、本轮实点 `1`、未逐条实点 `159`；
9. 切换到真实受考玩家后，在含 `3.25` 的“本人所属考核单元”页直接实点当前页签，再以标题、本人页名和 `3.25` 三重 OCR 确认幂等重开。该角色没有继承宋帝的机制账本，不能假定“制度驾驶舱”可见；驾驶舱页签已在宋帝阶段独立实点。这样三个不同页签定义都经过 `deliberate_click + OCR`，而不是把第二入口默认打开本人页冒充页签点击。
